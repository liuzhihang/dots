# Proposal

## Why

现有角色家族入口藏在编辑器侧栏，搜索与家族切换也无法组成清楚的浏览路径；从首页查看五组或在手机上定位某一组不够直接。将家族导航独立整理后，用户能在五个明确家族之间探索角色，同时不丢失已编辑的角色与创作状态。

## What Changes

- 在首页及工作台提供一致的五家族导航：Dots、Grok Bot、Meta Muse、人物、动物，并与首页五张家族卡片互相对应。
- 提供以五组基准角色的名称、说明、身份特征、材质和配饰词汇定位的搜索；限制结果来源于现有五组与已登记基准，不扩展角色目录。
- 支持家族选择和搜索结果聚焦到正确家族；在切换、搜索、返回首页及移动端展开/收起导航时保留已有每组角色配置、当前创作模式、参考图文字和未完成编辑状态。
- 为当前家族、搜索结果、无结果和可用素材状态提供可见且可访问的反馈；不创建新角色、不改角色 schema。
- 保持导航交互与首页整体视觉刷新、全屏随机流程独立；按各自 change 接入。

## Capabilities

### New Capabilities

- `family-navigation`: 五个独立家族的浏览、检索、定位、状态保持、无结果处理及响应式交互。

### Modified Capabilities

无。主 `openspec/specs/` 当前没有已发布能力；本 change 为导航行为新增增量规范。

## Impact

影响现有原生 JavaScript 单页应用中的家族/搜索状态、导航组件和 `dist/` 页面样式；沿用现有角色项目数据与家族标识，不引入路由库、搜索服务、账号系统或新依赖。
