# Proposal

## Why

当前四槽随机搭配嵌在旧工作台底部，抽取过程中会影响当前角色，不够沉浸，也无法明确区分“预览配方”和“应用创作”。将随机体验独立为全屏步骤，让用户逐槽锁定、重新抽取、再决定应用或返回，避免取消时角色状态被延迟改写。

## What Changes

- 新增符合 R01 视觉系统的桌面与移动全屏随机面板，包含类型、质感、配饰、动作四个槽位。
- 支持锁定/解锁每槽、对未锁定槽再次随机、查看当前候选、明确“应用这款”或返回编辑器。
- 抽取过程只产生临时候选；只有用户明确应用时才提交一次角色设定并进入现有撤销/重做历史。关闭、返回、Escape 或中途取消不得造成迟到提交。
- 尊重 reduced-motion，提供可访问的焦点、状态播报和键盘操作；随机选择只使用五家族各自受支持的基准值，不生成图像或扩展角色目录。
- 清楚说明随机结果是角色配方和 Prompt 设定；实际 PNG 仅由受支持的 Artwork/Composer 路径提供。

## Capabilities

### New Capabilities

- `fullscreen-randomizer`: 全屏随机流程、四槽锁定、候选重抽、显式应用/取消、状态一致性及移动端/无障碍行为。

### Modified Capabilities

无。主 `openspec/specs/` 当前没有已发布能力；本 change 为全屏随机体验新增独立增量规范。

## Impact

影响现有随机配方模块、随机入口、角色项目提交/历史控制及页面样式；复用现有五家族配置、配饰与动作数据，不增加生成服务、路由框架或依赖。首页与工作台的位置和视觉归 `refresh-studio-visual-design`，家族选择/搜索归 `refactor-family-navigation`。
