# Design

## Context

参见 [proposal.md](proposal.md) 和 [fullscreen-randomizer spec](specs/fullscreen-randomizer/spec.md)。当前应用通过 `randomRecipe(input, seed, locks)` 确定性地选择配置，并使用内联的 `RecipeMachine` 为现有四个槽位生成动画。该机器目前会在最终组装阶段完成前调用项目的 `commit` 回调，因此即使用户尝试停止流程，延迟触发的 timeout 仍可能修改项目。主应用已通过 `commit`、撤销/重做历史、项目快照和全局 Escape 处理来管理常规编辑。

## Goals / Non-Goals

**目标：**

- 为现有四个配方维度提供独立的沉浸式界面。
- 明确区分临时随机候选与活动项目。
- 仅在用户明确操作后提交一次，避免取消操作或过期计时器修改项目状态。
- 保留现有五家族约束、参考图锁定、撤销/重做、当前创建模式及图像输出的真实状态。
- 确保鼠标、键盘、触控和减少动态效果偏好下均可使用此流程。

**非目标：**

- 不生成作品、不调用图像服务，也不承诺不受支持的 Composer 参数会更新 PNG。
- 不添加获准数据范围外的家族、基准、配饰、动作或预设。
- 不重写底层随机配方兼容规则或家族导航行为。

## Decisions

### Keep the randomizer as a separate presentation module

使用自包含的全屏对话框/覆盖层及其专属展示样式，并通过精简的回调边界与项目所有者交互：读取一份当前配置快照、计算候选配方、请求一次应用操作。该界面不得直接写入应用状态。保留现有四个维度：类型、外观/材质、配饰和动作。角色启用参考图后应保留当前家族，锁定类型控件并显示说明。随机化器使用已选家族的唯一基准和受支持值，不创建新预设。

**备选方案：** 将沉浸式界面和选择逻辑直接放进主 `studio.js` 控制器。未采用，因为这会把对话框生命周期与渲染器状态耦合，并重复已经分离的配方选择逻辑。

### 将每轮抽取暂存至用户应用

打开界面时捕获不可变的 `before` 快照并创建临时候选项。锁定和重新抽取操作只更新临时候选项及显示的四个值。每轮异步动画都关联当前操作 token；开始新一轮或取消时，使上一个 token 失效并停止其计时器。只有“应用”按钮会将最终通过验证的候选项发送给项目所有者，且只发送一次。该项目变更对应一个撤销步骤。取消/关闭/Escape 会丢弃 token 和快照，不调用 `commit`。

**备选方案：** 每次重新抽取都提交，并在取消时通过撤销回滚。未采用，因为这会在探索性交互期间更改自动保存、Prompt、渲染器和历史记录，而且无法安全撤销乱序回调。

### Render recipe truth next to the candidate

明确区分候选角色展示与已生成图像或当前导出的图像。在槽位附近显示简洁说明：随机选择只更新配置和 Prompt。若当前模式为 Artwork，其已登记图像保持不变。若 Composer 不支持某个字段，应说明该字段仅影响 Prompt，并保留该字段，但不得声称 Canvas 已改变。使用视觉改造共用的模式/状态标签，不绘制一个看似支持未实现能力的第二预览。

**备选方案：** 在对话框中重绘软件/3D 后备效果，使每个候选项看起来都能即时响应。未采用，因为当前生产模式可能是固定作品或能力有限的 2D Canvas；后备画面会错误暗示这些参数已经实际合成到图像中。

### Use modal focus and immediate reduced-motion behavior

若能适配首页/工作区共享外框，则使用原生对话框语义；否则实现等效的焦点限制、背景 inert 状态和焦点恢复。Escape 会取消临时候选项。对话框处于活动状态时，阻止应用级随机快捷键或工作区操作触发。启用减少动态效果后，立即显示新的候选项，同时保持相同的应用/取消流程。使用明确的实时状态消息播报当前槽位结果，而不是播报每一帧滚动动画。

**备选方案：** 将该体验做成独立路由。未采用，因为短暂的模态流程不值得引入额外导航和持久化复杂度，而且可能丢失用户正在编辑的确切项目。

## Risks / Trade-offs

- [先前抽取的计时器仍可能触发] → 清除所有计时器，并用可失效的操作 token 控制每次异步更新；只有“应用”回调可以修改项目状态。
- [当前视觉资源包可能不支持某个槽位值] → 保持配置和 Prompt 准确，标注不支持的视觉字段，并依据现有 Composer 契约禁用当前 PNG 输出或回退到受支持的状态。
- [随机流程可能与家族导航冲突] → 从任一入口通过相同回调 API 和当前稳定家族打开；关闭时返回原先调用的确切界面。
- [移动端全屏控件可能被浏览器界面遮挡] → 使用动态视口尺寸和安全区间距，并在 320/390/768 px 下测试，确保“应用”和“返回”操作可见。
- [用户可能将滚动数值误认为图像生成] → 在控件附近说明此流程仅随机化配方；保留与模式相符的输出标签。

## Migration Plan

1. 在保留现有配方函数和获准锁定规则的同时，添加独立的全屏界面与样式。
2. 在界面中暂存所有候选变更；重新抽取或取消时使先前的异步轮次失效，并将“应用”操作接入应用现有的单次提交/撤销流程。
3. 在真实页面的桌面及要求的移动端宽度下，验证锁定值、变化值、全部锁定行为、Escape/返回、减少动态效果、过期抽取取消、历史记录、当前 Prompt 和真实输出状态。
4. 将入口接入 R01 首页/工作区和五家族导航，且不改变已选家族状态；浏览器验证后作为现有 Site 候选版本的一部分发布。

## Open Questions

无。“应用”必须由用户明确操作；取消操作绝不修改项目。
