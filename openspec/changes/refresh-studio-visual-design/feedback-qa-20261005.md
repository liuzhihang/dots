# 手机反馈修复与页面核对 · 2026-10-05

## 实际变化

- 主入口、2D 结构入口及当前可达模块统一为 `?v=59`，避免新入口继续引用旧的无版本目录模块。用户手机截图与旧图片目录吻合；未获取该手机缓存/响应头，缓存原因是推断，不记为已证实。
- 用户否决的卷发阅读人物及错误的浅绿眼镜笔电 Grok 从发布目录撤下。旧 artwork ID 使用无图片路径的 retired 记录，保留 JSON 配置、导出、重新导入；页面明确显示撤下原因并禁用原图下载/放大。原 PNG 只保存在非发布参考目录。
- Grok 唯一基准按新提供的三张身份照片修正为紫色圆形、两枚同向斜白胶囊眼，无默认眼镜/笔电。旧浅紫软拱候选撤下；旧 v10 arch 配置仍可导入和重导，不改为 sphere。
- Meta Muse 继续使用自己的乳白包覆式候选 PNG，与人物独立；首页导航、家族卡和工作台实际载入成功。

## 线上与验收边界

发布前原生 Site 回读为 v29、源提交 `586fd488cc22551714f8c7d2ee55537a41c302c9`、部署成功。为复现手机问题访问原站时，正常 owner 登录流程返回 `400 Invalid content type`，无法进入线上 DOM；没有绕过登录或修改访问策略。本机页面 QA 与原生发布回读分开记录。新的发布结果见 release 记录。

用户的真实手机在更新后尚未验收。五组仍各只有一只候选；生成 PNG、程序检查、截图、构建、任务勾选和部署成功均不表示角色美术验收通过。尤其 Grok 是依据用户身份照片提炼的 imagegen 候选，不是官方原版文件。

## 推荐的后续方向

建议统一为一个组合工作台，内置形象使用同一份组合配置：选择预设后继续搭配，首页用预设和变化丰富内容。材质维持统一精细玩具质感，各家族保留不同轮廓/材质身份。优先固定视角的完整姿态模板与通过接触检查的图层，不把文字参数伪装成已变化的图片。

本轮只修复明确反馈；上述统一工作台尚未实施或视为用户确认。当前 Dots 仍仅支持原有有限组合，其余四组缺组合包，状态保持如实说明。Meta Muse 也只一只基准，扩展需要用户先确认本组网页形象。

## 程序与规范检查

最终实现通过 `npm run build`、`verify-creation`、`verify-creation-ui`、`verify-module-cache`（14 个版本化模块、五组独立资源）、`verify-character-system`（57 个冻结预设、24 个迁移、200 次单基准随机）及两个 change 的严格校验。其余相关目录、导航和随机回归结果随最终发布记录补充。

最终相关回归全部通过：`verify-studio` 62 项、`verify-recreations` 468 项、`verify-atelier` 7 项、`verify-family-navigation` 和 `verify-fullscreen-random`。导航回归原先把“圆球”当作 Dots 独占关键词；Grok 改为圆形后该假设不成立，改用既有独有词“团子”，并新增“圆球”返回 Dots 与 Grok 的共享检索断言，未修改搜索实现或删除筛选/多词检查。
