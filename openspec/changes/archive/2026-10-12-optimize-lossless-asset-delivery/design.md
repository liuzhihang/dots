# Design

## Context

动机见 `proposal.md`，行为合同见 `specs/`。当前工作室登记 PNG 作品、预览资源和模板图层资源，并为其保存稳定身份及文件元数据。项目已经具备独立的源文件清单、WebP 交付映射、支持交付映射的预览加载器，以及静态发布暂存边界。本变更必须让这些部分保持一致，同时不改动已批准 PNG 的字节或输出行为。

## Goals / Non-Goals

**Goals:**

- 保留每条交付映射所对应的已批准 PNG，作为规范且带版本记录的源文件。
- 在详情预览和模板图层传输中复用已登记、像素完全相同的无损 WebP，并提供明确证明和安全失败行为。
- 让源文件保留范围与静态站点上传范围可分别审查、可重复构建。
- 保留原始字节 PNG 下载，以及透明 PNG Draft 导出。

**Non-Goals:**

- 重新编码、删除、替换或修改任何已批准 PNG 源文件或其批准记录。
- 将 WebP 用作 Artwork 下载、Draft 导出，或新的公开 Artwork/Template 身份。
- 改变视觉内容、图层几何、堆叠顺序、锚点、合法组合或角色系列的编辑控件。
- 向浏览器新增图像处理依赖，或在运行时生成交付资源。

## Decisions

1. **将规范源文件和传输派生资源登记为独立记录。** 每条映射都保留一份规范 PNG 源记录，包含仓库路径、SHA-256、尺寸和字节数。派生资源则有自己的路径、SHA-256、`image/webp` MIME、尺寸、字节数、alpha 信息，以及无损/精确标记。这样可保留现有 Artwork 或 Template 图层身份，同时允许传输字节采用不同编码。拒绝把源 PNG 改写为 WebP，因为下载/导出和既有批准均绑定原始 PNG 字节。

2. **发布前以解码后的 RGBA 像素证明等同性。** 确定性的资源生成/校验步骤会解码已登记的 PNG 和无损 WebP，验证尺寸及 RGBA 字节完全相同，并将 `pixelSha256` 记录为解码后 RGBA 字节的 SHA-256。alpha 是否存在及是否透明、内嵌颜色配置文件是否保留，都要分别检查。在浏览器像素对比检查中，使用 `createImageBitmap(..., {premultiplyAlpha: 'none'})` 解码；默认预乘可能导致 PNG 和 WebP 的低 alpha RGB 通道量化结果不同，即使编码源与派生资源无损。运行时加载器在渲染/比较前也必须使用相同的非预乘 alpha 解码路径。浏览器会校验可信映射、下载到的 WebP 哈希、MIME、尺寸和 alpha 元数据；无需为重复构建时的像素比较而下载仅保留在源目录中的 PNG。源绑定、文件哈希或证明缺失/不匹配时，禁止使用该资源。编码差异本身不会扩大美术审核范围。

3. **仅对可安全排除源文件的资源交付 WebP。** 源资源清单仍包含规范 PNG。`sourceOnlyFiles` 必须精确列出已登记且具有通过验证的 WebP 映射的预览/模板 PNG 源路径；对应 WebP 仍须包含在交付集合中。需要支持原始字节下载或保持既有导出的 Artwork 原图 PNG 仍须包含在交付集合中。分别校验已登记的 `dist/` 清单、仅保留于源目录的子集和实际上传暂存目录，避免实现仅凭 Git 树推断部署内容。

4. **从精确计算的交付集合构建上传暂存目录。** 暂存后的 `dist/` 子树必须恰好包含 `files - sourceOnlyFiles`；每个复制文件都重新校验字节数和 SHA-256。若目标目录已存在，则暂存失败，不得清空该目录。所需托管配置和本地暂存证明与已登记的静态内容清单分开管理。拒绝上传整个仓库或完整 `dist/`，因为这会一并上传仅用于源文件保留的图层和无关文件。

5. **所有导出路径继续绑定规范 PNG 数据。** 原始 Artwork 下载和未修改的 Export 路径都读取已登记 PNG 原图。修改后的 Draft 使用经验证的 WebP 传输资源解码出的像素，按同一份规范图层配方渲染，并仍然输出绑定到冻结的 Artwork/Template/选项版本的透明 PNG。界面背景和 WebP 字节均不得进入上述任一种输出。

## Risks / Trade-offs

- [浏览器运行时解码或 MIME 交付与构建假设不符] → 使用前检查响应 MIME、WebP 文件签名、尺寸、alpha 和文件哈希；将校验失败视为资源不可用并明确报告，不回退到过期或未登记的字节。
- [生成的 WebP 节省空间有限，或比 PNG 更大] → 记录源文件与派生资源的字节数；仅在该 WebP 是有意登记的交付映射时保留，不得为追求更小体积而放宽无损校验。
- [清单误排除了导出仍需要的 PNG] → 将所有下载/原图 Export 引用与上传闭包核对，并在发布前读取暂存路径及哈希进行验证。
- [源映射变化悄然扩大了批准范围] → 映射绑定到精确的源路径、哈希、尺寸和字节数；工程校验与源图美术批准分开处理。

## Migration Plan

1. 生成或关联交付派生资源前，冻结并计算已批准 PNG 源文件集合的哈希。
2. 生成或校验无损 WebP 及源文件映射；若解码 RGBA 对比、alpha、颜色配置文件、尺寸或字节数/哈希检查失败，则拒绝该源文件映射。
3. 更新交付资源登记和精确发布清单：只有具有已验证 WebP 映射的预览/模板 PNG 源文件才进入 `sourceOnlyFiles`；所有规范 PNG 都保留在仓库中，下载/导出所需的 PNG 原图也保留在静态交付集合中。
4. 运行资源登记、预览加载器、导出、构建清单和隔离暂存检查。任何获准上传之前，检查暂存目录 `dist/` 的文件清单及哈希。
5. 回滚时，移除受影响的 WebP 交付映射和对应 `sourceOnlyFiles` 条目，再将未改变的 PNG 源文件纳入交付集合。回滚绝不删除或改写其规范 PNG。

## 托管 MIME 兼容性补充

Site 49 线上返回 WebP 的 SHA-256、尺寸和字节量均与交付映射相同，但 HTTP Content-Type 为 `application/octet-stream`。仅对已登记 WebP 允许这一通用传输类型；实际内容仍强制通过 SHA-256、RIFF/VP8L、尺寸校验后，才将 Blob 标记为 `image/webp` 解码。`text/html` 等错误类型、错误内容、未登记图片均不可借此绕过校验。修复以页面缓存版本 102 发布，原图与交付文件不重新编码。
