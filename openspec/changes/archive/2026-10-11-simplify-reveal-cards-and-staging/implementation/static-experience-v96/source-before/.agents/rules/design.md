# 设计实现与验收规则

遵循最新用户确认的产品范围及 [DESIGN.md](../../DESIGN.md)。主页面和抽卡关系见[视觉与交互系统](../../design/studio-visual-interaction-system.md)。历史证据按归档 README 查阅；旧任务勾选不构成当前验收。

1. 保留品牌、已选首页构图与批准角色身份。页面使用真实 DOM、CSS 和已登记资源；展板只作整体布局参考，不能嵌入截图充当网站，也不能裁出原型角色像素作为成品。
2. 首页专题与 typed tags 可扩展。成品、独立线索图、场景插画、来源、资源状态和批准范围分别登记。用户外部创作后上传成品是后续规划，当前揭晓交互不实现上传、后台审核或站内对话创作。
3. 随机来自已登记完整作品。角色风格事实保留，但不作为独立展示卡；Dots、Grok Bot、Muse、人物、动物身份标签在首张外形五官卡停稳时出现。每轮按外形五官、配色材质、衣物、配饰、道具排序，前两类必显，后三类只展示真实且已核实的值。卡数随作品实际内容决定，同轮冻结；当前 15 件作品为 2 张卡 7 件、3 张卡 7 件、4 张卡 1 件。无值维度不产生空卡，未来有值类别不截断；任一必要事实未知时，作品不进入默认随机池。
4. 首张外形五官卡不能提前显示最终角色或其专属颜色、衣物、配件、作品名和简介；首卡停稳时才显示轻量身份标签。滚动卡、停卡和结果摘要仅显示线索图片及类别名。卡片不得加特征名称、说明段落或宣传文案。
5. 线索不负责拼装或穿戴。通用配件可被多个适用作品显式引用，关联要符合各自成品事实；不得据此为其他作品生成效果。停卡、最终图、Prompt、下载须绑定同一 DrawResult。
6. 首页、画廊和灵感游戏复用抽取流程；首页/画廊单击后立即开始动效。相同结果资源未准备好时卡片持续滚动且结果隐藏。全部有效卡停稳后等待约 900ms 再揭晓；减少动态下静态展示同一批卡并等待用户操作。
7. 结果在同一紧凑深色舞台展开：桌面卡片一排呈现，角色在揭晓时成为视觉主体；收拢线索卡后显示完整角色与作品名。主按钮“带走伙伴”打开内联操作面板，含复制 Prompt、下载图片、ChatGPT 和真实 Feature 锁定；“再遇一位”为次级操作，详情入口轻量，完整描述只在详情显示。手机突出当前卡并露出邻卡；重抽回到下一轮舞台起点。角色图不滤色。
8. 同一维度的普通筛选采用 OR，不同维度采用 AND；结果后设置的必备 Feature 全部 AND。资源失败不得静默换作品或降低条件，页面文案不显示内部校验状态。
9. 角色原图下载登记字节、保留真实 alpha；页面底色不进入原图。静态图、独立姿态、真实动画、sprite sheet 和目标包不得混称。Dots 新制材质保持短绒；Grok Bot 和 Meta Muse 维持各自身份。
10. 运行适用的目录、构建、浏览器和下载检查。视觉检查桌面及 320/390/768 CSS px，并标明模拟视口。脚本/截图/任务勾选不能替代用户艺术批准、实体设备验证或发布确认。
11. 只改必要源码和文档。保留来源、批准、历史证据、Site 身份和访问设置；不清空 dist/，不覆盖并行工作，不自动提交或发布。
