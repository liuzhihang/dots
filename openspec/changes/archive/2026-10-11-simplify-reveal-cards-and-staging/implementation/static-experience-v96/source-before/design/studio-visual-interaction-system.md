# Dot Icon Studio 视觉与交互系统

## 参考材料与优先级

首页沿用用户选定的 Dot Icon Studio 展板构图：品牌、中央标题、左右群像、明亮氛围、专题卡、图库和大图详情。抽卡重点参考“随机生成一个可爱角色”弹窗，以及总览图中的逐卡过程与最终结果画面。蓝色绒球和形状/材质滑杆工作台只可作为独立素材质感参考，不作为页面交互方向。

优先级为：用户最新文字要求与角色身份 → 已批准原图及来源记录 → 用户选择的页面和抽卡原型 → 辅助视觉参考。原型用于关系和节奏探索，不自动批准页面、美术或素材。批准状态必须绑定具体文件版本与呈现范围。

## 页面关系

- **首页**保留品牌、中央主标题、左右群像与轻盈明亮氛围。现有专题作为可扩展图库入口，不构成永久固定的身份数量。
- **画廊**以完整角色作品为主，提供关键词、标签和事实筛选。无内容类别不作空入口；打开详情后恢复查询、滚动和焦点。
- **灵感游戏**复用首页与画廊的抽取模型和结果；首页使用默认有效池，画廊随机继承当前查询。
- **随机揭晓**在深色舞台中呈现线索卡停下的过程。卡片不是组件，也不演示临场装配；最终图始终来自目录中的一张完整作品。
- **作品详情**展示完整作品、精选事实、真实规格和操作。复制 Prompt 与下载图片优先，变体、完整 Prompt、目标说明及 ChatGPT 为次级内容。
- **参考图辅助**目前提供风格、描述、保留项和条件式 Prompt；用户进入 ChatGPT 后自行上传参考图并发送。用户外部创作完成后上传成品、存储与审核是后续独立规划，当前界面不承诺这些服务。

## 身份与素材

Dots 使用已批准的具体作品；新制 Dots 保留柔软短绒。Grok Bot 保留软几何主体与成对胶囊眼，不画成屏幕脸；Meta Muse 保留奶油包覆外形与内嵌脸面。人物和动物保持原创身份与可辨识物种特征。既有批准图不因概念图或新素材而静默改写。

底层完整记录角色风格、外形、五官、配色材质、衣物、头部配饰、身体饰品、随身道具八类事实。角色风格仍用于身份与事实检索，但不生成独立揭晓卡。Dots、Grok Bot、Muse、人物、动物身份标签在首张外形五官卡停稳时出现。动作/表情是独立成品变体或实际动画，背景属于资源规格。

独立的 reveal visual 是抽卡和说明线索，不是可装备部件：

- 外形五官是首张真实线索卡；身份标签仅作轻量文字标记，不需要单独 style 视觉素材，也不能展示最终原图、专属颜色或配件组合。
- 其余卡片线索按外形五官、配色材质、衣物、配饰、道具等实际类别登记准确资源，保留来源、Asset ID、版本/hash、用途和工程/批准状态。
- 可复用的通用配件图需显式关联到真实含有相应配饰的作品。共享不要求复制文件，也不会使该配件能贴到其他角色上。每轮停卡仍须与最终作品中的事实一致。
- 有值维度缺少合格线索时记录素材缺口；不可删掉有值卡、拿最终图填充或以粗糙占位声称完成。已核实无值的可选维度不显示卡、不要求空值图片。候选素材保持待审状态。

## 动态卡片与揭晓

前台卡片顺序保持稳定：外形五官 → 配色材质 → 衣物 → 配饰 → 道具。前两类必显；衣物、配饰、道具仅在对应内容已核实为有值时加入本轮。因此卡片数量不固定，也不为了统一数量展示空值。当前 15 件作品按有效类别派生为 2 张卡 7 件、3 张卡 7 件、4 张卡 1 件。未来若某件作品的五个展示类别都确有内容，可以展示五张卡；这不要求穷举或预先制作任何新组合。任何真实有值类别都不能为适配固定版式而被截断。

一次抽取开始前根据最终 Artwork 的已核实事实生成有效卡清单。滚动、等待、停止、跳过、窗口变化、结果、详情返回都沿用该清单；下一轮才可使用另一张作品的卡数。任何卡的必要事实为 unknown 时，候选不能因隐藏该项而进入有效随机池。头部饰品和身体饰品属于同一张配饰卡，多件内容按一个类别展示。

第一张外形五官卡展示真实但不完整的线索。它停稳时显示 Dots、Grok Bot、Muse、人物或动物身份标签；在此之前以及其后其他卡尚未揭晓时，都不能泄露完整作品、专属配色、衣物、配件、作品名或描述。所有抽卡中卡片、停下的卡片和结果摘要只包含线索图与简短类别名；“柔软绒毛”“灵动有神”等特征描述不出现在卡面。真实事实仍保存在 Artwork 和搜索索引中。

抽卡舞台采用紧凑深色构图，压缩无内容的留白，让线索卡和角色成为视觉焦点。桌面以居中一排展示本轮 2–5 张 5:6 卡，少卡保持适中卡宽，不拉成空旷长条。手机突出当前卡并露出邻卡，不把所有卡压成一排。候选线索绑定各自来源作品与素材；最终停值、完整图、名称、Prompt 和下载绑定同一个 DrawResult。

首页/画廊有效点击后弹窗立即打开并启动卡片动效；灵感游戏使用共享流程。加载同一结果所需的图片与有效线索时，卡片可以继续滚动，但不能提前停止或露出最终角色。资源齐备后再逐卡减速停止。普通模式与跳过动画都在所有有效卡停稳后保留约 900ms、结果隐藏的间隔。减少动态模式不滚动、不翻牌，静态展示同一批卡，等待用户点击“揭晓伙伴”。失败不静默换作品、不放宽条件。

完整角色在同一个舞台揭晓：已停卡收拢至摘要，卡片在上方，角色大图在主体区域明显放大；显示作品名，不在揭晓结果中放完整描述或工程说明。主按钮“带走伙伴”打开内联操作面板，提供复制 Prompt、下载图片、ChatGPT 和 Feature 锁定；“再遇一位”为次级操作，详情入口轻量，完整描述只在详情中显示。结果图保持原色。完整角色与作品名在最终揭晓前保持隐藏；不得通过背景或尚未停卡的无障碍文本提前泄漏完整结果。单卡停稳后可访问该卡的真实事实和 n/N 进度。

## 交互与视觉检查

页面沿用现有品牌与 CSS token。深色揭晓舞台、浅色卡面、中性背景和紫色强调应服务于作品与线索的层级，避免过多霓虹、复杂说明和假进度。

检查首页、画廊、随机、结果、详情和返回路径在桌面以及 320、390、768 CSS px 模拟视口下的可读性、滚动、焦点和溢出。分别记录当前真实的 2、3、4 卡抽取中、全停、揭晓状态；五卡只在真实作品有五类内容时检查，不为覆盖数字而构造发布组合。检查真实 Artwork 与其线索素材的来源和语义。构建/脚本/截图只证明相应工程范围，不等于美术批准、实体设备验收或发布。

## 抽卡与分享的不同用途

抽卡舞台采用卡片在上、完整角色在下的同屏交互，视觉质量优先，不以粗糙线索或大量文字补画面。分享使用独立版式：角色大图、名字、一句分享文案、少量真实特征和品牌署名，不放抽卡操作按钮。本轮横/竖分享稿仍是 `design/acceptance/current-20261008-v93/share/` 中的设计稿，不扩大为抽卡界面或社交发布实现。v93 抽卡候选经用户指出与原型差距较大，不视为接受；当前修复候选单独记录于 v95 证据目录，页面和素材保持 pending。
