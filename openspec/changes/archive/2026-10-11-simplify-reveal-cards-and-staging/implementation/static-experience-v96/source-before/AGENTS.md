# 协作约定

开始任务前阅读 [产品与设计约定](DESIGN.md)、[设计审查规则](.agents/rules/design.md)、[README](README.md) 及任务相关的 OpenSpec change/spec。以用户最新确认的范围为准；当前主规范是唯一执行基准，不维护未发布旧方案的兼容层。使用仓库现有 OpenSpec 配置和 CLI 1.14.1，不初始化或自动升级。

## 产品边界

Dot Icon Studio 提供高质量完整角色图库、typed tags 搜索、随机发现、对应 Prompt 与参考图文字辅助。主导航为首页、画廊和灵感游戏。保留 Dots、Grok Bot、Meta Muse、人物和动物首批身份；专题、作品数和标签均可扩展。

- 随机玩法从已登记的完整角色作品中发现一款，卡片只展示线索，不现场拼装角色。用户可以在 ChatGPT 或其他创作工具中继续创作；用户完成作品后上传/投稿、后台存储与审核属于后续产品范围，需另行规划。本轮揭晓卡改动不实现这些流程。参考图辅助目前只生成文字模板，用户在 ChatGPT 自行附图和发送。
- Artwork、实际 Feature、Asset、Prompt、DrawResult 稳定绑定。底层保留八类事实：角色风格、外形、五官、配色材质、衣物、头部配饰、身体饰品、随身道具。动作/表情属于已制作的独立变体或实际动画，背景属于资源规格。
- 卡片数量按作品真实有值的类别决定，同一轮在动画开始前固定。当前 15 件作品派生为 2 张卡 7 件、3 张卡 7 件、4 张卡 1 件；不强行固定四张、不用空值补齐，也不截断未来实际存在的线索类别。底层八类事实保留角色风格；角色风格不再单独占卡，Dots、Grok Bot、Muse、人物、动物身份标签在第一张“外形五官”卡停稳时轻量出现。卡片按外形五官、配色材质、衣物、配饰、道具排序，前两类必显，后三类仅在成品含有真实内容时显示；多项配饰合并一张卡。none/notApplicable 保留在作品事实中但不生成空卡，unknown 仍使作品不具备随机资格。
- 第一张卡使用共享、中性的身份线索，不提前展示最终作品、专属配色、服饰、配饰、名称或简介。卡片及摘要只显示线索图片和简短类别名，不显示特征短名、描述段落或宣传文案。所有最终停卡都准确对应同一成品；卡片只用于揭晓，不代表配件可穿戴或作品已被现场合成。
- 独立配件线索可以被多个适用作品显式引用复用；每条关联须与该作品的真实特征相符。维护者可单独制作、登记线索素材。素材来源、工程状态和艺术批准分开记录；概念图或候选资源不自动成为已批准成品。
- 首页、画廊和游戏入口复用同一抽取结果。首页/画廊点击后立即开始动画；同一 DrawResult 的图和线索资源准备期间可继续滚动，但未就绪前不得停卡或揭晓。全卡停稳后保留约 900ms 的隐藏结果边界；减少动态模式静态展示相同卡清单，并等待用户点击“揭晓伙伴”。紧凑深色舞台在桌面以一排卡片呈现，揭晓时突出完整角色。结果在同一舞台展开：线索卡收拢后展示完整角色与作品名；主按钮“带走伙伴”打开内联操作面板，提供复制 Prompt、下载图片、ChatGPT 和 Feature 锁定；“再遇一位”为次级操作，详情入口保持轻量。完整描述只在详情中显示。失败不静默换作品。
- 普通筛选采用同维 OR、跨维 AND；结果后明确锁定的必备 Feature 全部 AND。Artwork 标签描述真实成品，不授予渲染、穿戴或目标平台安装能力。
- 角色原图下载原始文件字节并保留真实 alpha，不通过 Canvas 重绘；页面底色不能烘焙进原图。静态图、动作变体、实际动画和目标包须准确区分。
- 新制 Dots 保留柔软短绒触感；Grok Bot 保留软几何与成对胶囊眼，不画成屏幕脸；Meta Muse 保留奶油包覆形体与内嵌脸面。已批准美术按原版本与批准范围保留。

## 文件与验证

dist/ 同时是可编辑源码和 Sites 发布树，不得整体清空。旧运行代码与测试保存在 historical-runtime/，不进入新构建或发布；来源、艺术批准及历史失败/取消证据须保留。只修改必要路径，不覆盖他人改动，不使用 reset/clean 或宽范围暂存。

按影响范围运行目录/抽取检查、构建和浏览器检查；这些检查只证明各自覆盖范围。视觉任务检查桌面与 320、390、768 CSS px 实页；下载检查真实文件字节、尺寸、hash、alpha 与内容。模拟视口不是实体手机，美术批准须由用户确认具体版本与呈现范围。

新增候选证据写入唯一的 design/acceptance/current-<日期>-v<cache>/ 目录，绑定源码和资源 hash。不得把失败、取消、pending、工程检查或历史任务勾选改写成用户美术批准或当前验收通过。

保持 .openai/hosting.json 的 Site 身份与访问设置。提交、Sites 保存、部署和对外发布均按具体用户授权执行。
