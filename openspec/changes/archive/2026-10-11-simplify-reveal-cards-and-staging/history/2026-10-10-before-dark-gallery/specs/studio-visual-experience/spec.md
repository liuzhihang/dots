# Spec Delta

## MODIFIED Requirements

### Requirement: 发布静态页面资源必须与作品清单版本一致
发布页面引用的清单、封面、场景、完整原图和预览 SHALL 来自同一有效发布版本；客户端不得混用过期子模块或未发布资源。失效资源 MUST 显示可恢复失败，不以其他版本静默替代；旧运行功能及非发布候选不得只通过 CSS 隐藏后继续发布。

#### Scenario: 加载新发布的目录
- **WHEN** 浏览器载入首页或画廊
- **THEN** 所用清单与资源版本一致，不启动旧抽卡、工作台或候选预览入口

#### Scenario: 命中过期资源
- **WHEN** 缓存或网络返回与登记版本不符的资源
- **THEN** 对应区域说明加载失败并允许重试；不把错误资源标作当前作品，也不要求整体重新生成目录

## ADDED Requirements

### Requirement: 首页必须呈现单一阶梯式共创露台
首页 SHALL 以 P02 的台阶纵深、前中后景与群组留白构图，并使用 P01 克制黄昏光色。唯一露台背景 SHALL 按桌面、平板和手机视口比例自适应铺满可视屏幕，不使用固定624px Hero。导航、标题、说明、Copy Prompt / Explore Gallery 和类别控件作为场景上的可读 overlay；类别 SHALL NOT 生成独立 Featured 作品区、大分类卡或第二主题。每个视口使用一张完整合成静态场景图，不叠加透明角色群组，保留空台阶与过道。

#### Scenario: 检查桌面构图
- **WHEN** 在 1440×900 实际浏览器检查首页
- **THEN** 露台背景铺满可视屏幕；Dots 领衔，近处互动、中景合作 / 阅读、远景伙伴清晰且留有空台阶与过道。每个可见角色只对应一个已登记 Artwork ID / 版本；原有15个身份保持不变，新白色原创机器人、白兔等仅以独立 pending 候选加入。角色和道具在同一图中有真实承托、遮挡与共享光照，类别与文案仅覆盖在场景上，不出现 Featured 作品区

#### Scenario: 手机场景只映射真实可见角色
- **WHEN** 在 390×844 实际浏览器检查手机首页
- **THEN** 同一黄昏露台按手机视口比例铺满屏幕；热区只对应该构图中实际可见的 Artwork。原有15身份不被替换；新增候选保留 pending 标签；类别控件覆盖场景，不在背景下方新增 Featured 作品区

#### Scenario: 平板比例使用对应场景构图
- **WHEN** 在 768px CSS 宽度检查首页
- **THEN** 露台仍铺满视口，并使用登记的平板构图及其独立热区；不得把桌面图裁切后继续启用已被裁掉的角色，也不得将手机热区套用到平板图

#### Scenario: 素材不足
- **WHEN** 任一视口缺少完整静态场景图、图中角色映射或页面批准
- **THEN** 记录缺口或 pending；不裁概念拼版、不叠透明角色群组、不重复绘制角色，也不把工程候选标为艺术批准

### Requirement: 场景角色必须以稳定热区响应指针键盘和触控
每个可交互场景角色 SHALL 绑定明确 Artwork ID / 版本，并具有固定贴合对应视口完整场景图中可见角色的热区。手机或平板未出现的角色 MUST NOT 有热区。Hover 或键盘聚焦 SHALL 显示简短名称 / 查看提示，并沿该角色在场景图中的真实外轮廓显示描边动画；轮廓只能描边，不复制或移动角色图像，也不是角色动作 / 表情动画。点击、Enter / Space 或手机一次轻点 SHALL 立即打开共用详情，不等待描边动画。MUST NOT hover 自动弹出完整详情、让热区漂移或以矩形框冒充真实轮廓。

#### Scenario: 鼠标移入并点击
- **WHEN** 指针从空台阶移入角色再点击
- **THEN** 显示该角色简短提示，并以描边动画沿其真实轮廓反馈；点击立即进入其详情。提示和描边不遮挡相邻角色或通道，指针移出后结束，不打开悬浮详情窗或移动角色

#### Scenario: 键盘打开与图像位置映射
- **WHEN** 用户 Tab 聚焦桌面或手机图中实际可见的角色并按 Enter / Space
- **THEN** 焦点可见、名称可读，并显示与 hover 相同的真实轮廓描边；详情立即打开该热点绑定的 ID / 版本。热点坐标和轮廓对应当前视口实际图像，不因 CSS 缩放错位

#### Scenario: 减少动态或无动作资源
- **WHEN** 用户启用减少动态或该角色只有静态素材
- **THEN** 完整场景保持静态，角色反馈改为静态真实轮廓和提示并可进入同一详情；不出现虚假的角色移动、表情变化或必须 hover 才能操作的入口

### Requirement: 画廊必须使用统一浅色开放网格
画廊 SHALL 以 P01 为主参考，使用统一浅色背景、弱卡片边界、完整角色和光学平衡尺寸，名称与系列简短。默认展示静态封面；搜索、系列、无结果及清除条件真实有效。MUST NOT 为每件角色增加底座、小场景或整页同时自动循环动画。

#### Scenario: 浏览不同形体
- **WHEN** 画廊同时展示 Dots、Grok Bot、Muse、人物和动物
- **THEN** 各角色完整显示且视觉尺寸平衡，保持各自材质，背景统一；无展柜、底座或每卡场景

#### Scenario: 无结果与加载失败
- **WHEN** 查询没有匹配项，或某个封面加载失败
- **THEN** 无结果显示修改 / 清除条件操作；单张加载失败显示名称和重试，其他结果仍可浏览，不自动放宽查询或换成其他作品

### Requirement: 界面和Prompt必须支持英文与简体中文
首页、导航、画廊、详情、指南、错误与状态提示 SHALL 提供英文和简体中文；首次访问默认英文。界面与 Prompt 模板 SHALL 使用当前语言，作品 ID、资源引用、搜索条件及修改意图不随语言切换而改变。语言偏好可轻量本地保存，存储不可用时仍可完成当前会话。

#### Scenario: 切换语言不丢失浏览上下文
- **WHEN** 用户在带筛选的画廊或已打开详情中切换语言
- **THEN** 文案、可访问名称和模板更新，当前作品、系列、文本查询、详情来源和修改意图保持；用户自由文本不被擅自翻译

#### Scenario: 持久化不可用
- **WHEN** 浏览器拒绝读写本地偏好
- **THEN** 当前会话仍能切换语言与复制所选语言 Prompt，不阻断浏览或提示用户开启图片存储

### Requirement: 首页主操作必须对应已登记作品与画廊
首页 SHALL 保留简短英文标题、短说明、Copy Prompt、Explore Gallery 和轻量角色点击提示，并支持简体中文切换。Copy Prompt SHALL 对应一个明确登记的 Dots 主角 Artwork 的创作 Prompt；悬停其他角色不暗中更换该按钮内容。角色点击进入真实作品详情；首页 MUST NOT 宣传现场生图、组件装配、抽卡或未验证 Pet 安装。

#### Scenario: 复制首页 Prompt
- **WHEN** 用户点击首页 Copy Prompt
- **THEN** 复制清单中主角的所选语言 Prompt 并显示真实结果反馈；提示可识别其对应角色，失败时可选取完整文本

#### Scenario: 浏览画廊
- **WHEN** 用户点击 Explore Gallery
- **THEN** 进入真实作品画廊，不先播放动画、抽卡或选择场景

### Requirement: 单场景和静态页面必须按目标视口重排
首页、画廊、详情及指南 SHALL 在 1440×900、390×844 和 320/768 CSS px 边界分别检查。露台背景在桌面、平板、手机均铺满可视屏幕，并使用与该比例相符的场景构图和热点；窄屏不得仅整体缩小桌面拼版。画廊、详情和指南按内容自然滚动，MUST NOT 横向溢出、强制地图拖拽或依赖 hover 才能发现主要操作。

#### Scenario: 手机首页取景
- **WHEN** 用户在 390×844 或 320px 视口访问首页
- **THEN** 单行导航和同一露台背景适配手机视口，类别作为场景 overlay 而非独立内容区；不显示 Featured 作品区。角色密度、轮廓反馈和热区按手机构图核对，不整体缩小桌面拼版

#### Scenario: 桌面与平板
- **WHEN** 用户在 1440×900 或 768px 视口浏览首页、画廊与详情
- **THEN** 场景、网格、筛选、角色轮廓和关键操作完整可见，布局变化不改变作品身份或详情绑定

## REMOVED Requirements

### Requirement: 首页必须保留图 1 的品牌、构图和轻盈氛围
**Reason**: 旧双 Hero、中央标题和五张专题卡已被用户指定的单一露台取代。
**Migration**: 采用 P02 首页构图与 P01 黄昏光色，不保留第二主题 / 场景或旧稿入口；旧图片与证据保留在历史范围。

### Requirement: 首页、画廊和游戏必须分别呈现各自的真实任务
**Reason**: 灵感游戏与随机结果已退出范围。
**Migration**: 使用首页、画廊、静态指南和共用详情，不建立旧游戏适配路径。

### Requirement: 首页只能承诺真实存在的作品发现能力
**Reason**: 此要求包含已取消的随机、游戏或独立参考图会话场景，整体由新静态体验合同替代。
**Migration**: 采用“首页主操作必须对应已登记作品与画廊”及其场景；保留真实操作、无障碍和恢复能力，旧运行合同不继续生效，历史证据不改写。

### Requirement: 新产品页面必须在桌面和指定模拟视口可读可操作
**Reason**: 此要求包含已取消的随机、游戏或独立参考图会话场景，整体由新静态体验合同替代。
**Migration**: 采用“单场景和静态页面必须按目标视口重排”及其场景；保留真实操作、无障碍和恢复能力，旧运行合同不继续生效，历史证据不改写。
