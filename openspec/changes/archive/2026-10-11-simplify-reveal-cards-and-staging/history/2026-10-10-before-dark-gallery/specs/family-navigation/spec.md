# Spec Delta

## MODIFIED Requirements

### Requirement: 关闭作品详情必须恢复图库浏览位置和筛选
从首页场景或画廊打开详情时，系统 SHALL 保留来源、查询、系列、滚动位置和触发角色焦点。关闭、Escape 和浏览器返回 MUST 恢复打开时的来源状态；变体切换不得改写来源查询。直接打开详情 URL 时 SHALL 提供明确的返回画廊入口，不伪造不存在的来源或强制跳出本站。

#### Scenario: 打开并关闭作品详情
- **WHEN** 用户搜索、选择系列并滚动到作品后打开详情，再关闭或按 Escape
- **THEN** 恢复原查询、系列、滚动和卡片焦点；搜索结果不会重置，详情内变体不会改变画廊条件

#### Scenario: 浏览器返回离开详情
- **WHEN** 用户点击首页远景伙伴，再使用浏览器 Back
- **THEN** 关闭详情并恢复首页相同滚动位置及原稳定热区焦点，不进入画廊或旧抽卡结果

#### Scenario: 浏览器前进恢复详情
- **WHEN** 用户从详情 Back 返回来源后再 Forward
- **THEN** 恢复 URL 对应的作品 ID 和版本，保持一个活动详情，不重复叠加弹窗

#### Scenario: 触发角色已经不可用
- **WHEN** 详情关闭时原触发节点因目录不可用或布局变化而不存在
- **THEN** 焦点落到来源区域的稳定标题或结果容器，仍恢复有效来源条件且不丢到不可见元素

## ADDED Requirements

### Requirement: 主导航必须提供首页画廊和创作指南
主导航 SHALL 只提供首页、画廊、轻量创作指南及语言切换，背景与首页场景融合。Explore Gallery SHALL 直接进入画廊；导航不要求账号，不出现随机、工作台、上传或个人空间入口。无效新路由 SHALL 显示可恢复的未找到状态，不启用旧路由适配。

#### Scenario: 浏览三个主要页面
- **WHEN** 用户通过导航或 Explore Gallery 进入目标页面
- **THEN** 正确高亮当前页面，三个页面均可回到首页，页面不启动抽卡或打开编辑器

#### Scenario: 无效路由
- **WHEN** 地址不属于当前页面或详情路由
- **THEN** 显示未找到并提供首页 / 画廊入口，不执行旧游戏逻辑或进行旧 Schema 迁移

### Requirement: 作品详情必须具有可直接打开的稳定地址
详情地址 SHALL 指定可信静态目录中的 Artwork ID 和版本；站内打开更新地址并记录来源，复制链接、刷新和直接打开 SHALL 恢复同一作品。默认公开画廊、搜索和 tags 只包含已发布作品。明确登记为 `PREVIEW_*` 且资源、Prompt、版本校验通过的 pending 候选可使用同一 `#/artwork/<id>?v=<version>` 详情地址，并显示 `Preview · 待确认`；该入口不授予发布资格。未知 ID、错误版本、资源缺失或未满足 preview 条件的 pending 资源 MUST 显示明确不可用状态，不静默改为另一作品或最新版本；任意 URL 不得注入资源路径。

#### Scenario: 复制并直接打开详情地址
- **WHEN** 用户在新标签页打开某作品的详情地址或刷新当前详情
- **THEN** 展示相同 ID / 版本和操作；无站内来源时提供返回画廊入口，不依赖内存中的 overlay 注册表

#### Scenario: 地址版本不可用
- **WHEN** 用户打开不存在、错误版本、资源缺失或不满足 pending preview 条件的 Artwork
- **THEN** 显示未找到 / 不可用及返回画廊操作，不显示错误作品图片，也不提供该版本的复制或下载成功状态

#### Scenario: 直接打开已登记的 pending preview
- **WHEN** 用户通过可信详情地址打开资源、Prompt、身份和 pending 状态都已登记的预览候选
- **THEN** 使用同一 Artwork 详情展示真实候选并标记 `Preview · 待确认`；它不进入默认画廊、搜索、tags 或发布资格，其他非法或未完整登记的候选仍不可用

### Requirement: 首页和画廊必须共用单一活动详情
首页、画廊和详情直达入口 SHALL 共用同一详情体验、Artwork ID 和版本。站内打开采用单一活动详情，桌面浮窗、窄屏可全屏；背景 MUST 暂停交互并管理滚动、焦点进入与圈定、Escape 关闭和焦点恢复。“创作我的版本” SHALL 在详情内展开，不另开工作台或叠加第二个对话框。

#### Scenario: 同一作品从两处进入
- **WHEN** 用户分别从首页角色和画廊卡片打开同一 Artwork 版本
- **THEN** 图片、Prompt、真实下载及变体能力一致，使用相同详情结构，仅返回来源不同

#### Scenario: 键盘打开和关闭
- **WHEN** 用户以键盘打开详情、遍历操作并按 Escape
- **THEN** 初始焦点稳定位于详情顶部，Tab 保持在活动详情内，背景不可操作；关闭后滚动解锁并恢复来源焦点

#### Scenario: 展开修改 Prompt
- **WHEN** 用户在详情内展开“创作我的版本”
- **THEN** 使用原详情的焦点和滚动上下文，不建立嵌套对话框，折叠后仍停留当前作品

### Requirement: 静态角色页面必须适配窄屏和平板
首页、画廊、详情及指南 SHALL 在 1440×900、390×844 与 320/768 CSS px 边界保持可读、可操作。触控和键盘 SHALL 可访问场景角色、搜索、系列、清除和主要操作；窄屏详情可全屏，MUST NOT 以横向溢出或固定遮挡阻断内容。

#### Scenario: 手机一次轻点
- **WHEN** 用户在 320px 或 390px 首页轻点角色
- **THEN** 第一次轻点即进入详情，不需要先触发 hover；关闭、复制和下载可达，返回保持来源

#### Scenario: 平板查询和详情
- **WHEN** 用户在 768px 画廊设置查询并打开详情
- **THEN** 控件、角色完整轮廓和详情操作不被裁断，横竖尺寸变化后仍能关闭并恢复查询

## REMOVED Requirements

### Requirement: 主导航必须提供首页、画廊和灵感游戏
**Reason**: 新主路径不再包含灵感游戏及首页专题宣传卡。
**Migration**: 由“主导航必须提供首页画廊和创作指南”替代；旧入口退出运行，不提供旧 URL 兼容。

### Requirement: 全站弹窗必须由单一活动 overlay 协调
**Reason**: 此要求包含已取消的随机、游戏或独立参考图会话场景，整体由新静态体验合同替代。
**Migration**: 采用“首页和画廊必须共用单一活动详情”及其场景；保留真实操作、无障碍和恢复能力，旧运行合同不继续生效，历史证据不改写。

### Requirement: 新页面与筛选必须适配窄屏和平板
**Reason**: 此要求包含已取消的随机、游戏或独立参考图会话场景，整体由新静态体验合同替代。
**Migration**: 采用“静态角色页面必须适配窄屏和平板”及其场景；保留真实操作、无障碍和恢复能力，旧运行合同不继续生效，历史证据不改写。
