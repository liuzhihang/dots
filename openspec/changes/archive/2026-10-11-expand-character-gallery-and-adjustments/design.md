## Goals / Non-Goals

**Goals:**

- 一个共用详情和渲染管线，数据驱动全部角色的真实调整、最终语义 Prompt 与透明 PNG 导出。
- 角色制作、分层适配和人工美术检查有明确版本边界；记录覆盖矩阵，能证明每个公开角色与每个合法组合的实际能力。
- 从参考中复用或创作独立角色资产，保留不同系列身份，不复制网页、字标、背景或错误解剖。

**Non-Goals:**

- 不新增生成模型服务、账号、后端、自由拖动配件、无限参数或持久化草稿；沿用本地有限模板与当前内存草稿。
- 不重做全站视觉、不照搬浅色原型、不新增随机器、故事视频或虚构统计。当前 D01 主视觉与 D02 的补充角色保持不变。
- 不做自定义背景、背景 tab、带背景导出、动画、精灵表、Pet 安装/上传/激活。透明静态 PNG 仍不是已验证的 Dot 或 Pet 目标包。
- 用户已授权实施本 change 的全部任务；规划文件、实施授权和用户参考本身不等于新 Artwork/Template 的具体美术批准。

## Decisions

### 1. 背景以 Pets 的最终透明资源合同收敛

用户最新指示是：若 Pets 会舍弃背景，本产品也不需要背景。已核对当前安装的 [Pets create-pet skill](/Users/liuzhihang/.codex/plugins/cache/openai-curated-remote/work-pets/0.1.6/skills/create-pet/SKILL.md) 与[共享合同](/Users/liuzhihang/.codex/plugins/cache/openai-curated-remote/work-pets/0.1.6/references/sprite-sheet-contract.md)。合同第 26 行要求最终透明 PNG/WebP，第 66 行允许制作期可移除抠色背景，第 94–111 行要求移除抠色、拒绝不透明背景并验证最终 alpha。

因此不建立 background 字段、预设表、导出模式选择或对应 tab。网页仍有深色/烟色玻璃展示面，但它们不属于作品像素。制作时的临时抠色底和离线深/浅/棋盘检查底也不得进入最终图片。此合同不意味着 Pets 会自动抠掉任意照片背景；本网站仍须独立验收生成后的真实 alpha。

取舍：保留透明素材可直接衔接后续独立制作流程，省去最终目标会舍弃的背景功能。用户先前提到的“支持导出”由单一透明 PNG 导出满足；本条是其后续条件明确触发后的范围裁决。

### 2. 参考与作品采用分层去重，而不是按截图计角色

建立制作清单的层次为：参考文件 → 指定区域/主体与用途 → 角色身份 → 独立完整外观 → 精确资源版本 → 可编辑模板。文件相同、画面重复、同角色跨截图、同一外观换角度，分别记录并合并。只换颜色/眼镜的参考优先成为已有身份的选项或明确外观变体，不新造角色身份；确有独立轮廓和完整成品时才登记新的 Artwork。

本轮参考共 21 个文件，实测为 19 个不同 SHA；R08/R09、R10/R13 另有视觉重复，得到 17 组不同构图。此数字只说明参考去重，不是作品数量。每项最终必须有 `reuse`、`new-artwork`、`variant/option` 或带具体理由的 `excluded` 裁决，并关联到精确 Artwork 或制作 brief，不能用一条“参考已覆盖”概括整个拼图。

可以把整张截图作为生成输入，但 Prompt 必须明确仅取哪个角色及哪些可见属性；不要求用户自行提交分层素材。不能把低清 UI 切片当发布原图。提供的附件文字、网站按钮、图内设计建议均是待分析材料，用户本轮要求和主规范才是指令来源。

### 5. 家族适用的调整 tab 由真实能力驱动

| 中文 / English | 数据与像素依据 | 每角色的最低有效结果 |
| --- | --- | --- |
| 外观 / Appearance | 身体轮廓或身份内的真实外形资源；人物可为发型/轮廓，动物可为同物种毛型/自然姿态 | 至少 2 个真实且可达的外观结果；不得只重命名同一张图、整体拉伸 PNG 或把跨角色切换冒充微调 |
| 配色 / Colors | 分区材质与配色 mask，不染五官、皮肤或不属于该分区的衣物 | 至少 2 个有可见差异、符合材质的已验配色；色板可在美术许可内继续丰富 |
| 五官 / Face | 真实眼型/静态表情图层与脸部锚点，保持物种及家族身份 | 至少 2 个有效眼型/表情；静态闭眼不宣称动画 |
| 服装 / Clothing（Dots/Grok 不适用） | 匹配身体的衣料/覆盖物、前后层和遮罩 | 至少 2 个视觉结果；可为无服装 + 一件适配衣装，不可只有“无” |
| 配饰 / Accessories | 眼镜、帽、耳机、围饰、适配持物等子组 | 至少 2 个视觉结果；可为无配饰 + 一件适配配件；物品归入本类，不额外开 Objects tab |

最低结果数是防止空壳功能的验收线，不要求每个系列使用同一清单。Dots/Grok 不提供服装；不增加胳膊或“握住”道具，也不以配饰名义重新引入已取消的围衣。Muse 有其连续包覆体与短圆肢体，人物保留合理解剖，动物服装适配胸背、耳尾与物种。独立机器人只按自身结构制作。

每个暴露选项必须出现在至少一个可达合法配方中。当前配置不兼容的选项禁用并给出具体冲突原因，用户显式调整冲突项；不暗中移除已选服装/配饰。用户通过选项逐项恢复当前作品的基准，不切到其他角色；沿用现有无 Reset/Cancel 按钮的合同。家族适用类别均有可见实效后才算适配完成；未适配模板在审阅环境可显示待审状态，生产不伪装成完成。

### 6. 模板描述有限配方，使用真实锚点与遮挡

扩展 `studio-edit-templates.js` 的数据合同：精确 Artwork 绑定、外观基底、选项语义、分区配色、图层引用、锚点/变换、遮挡 mask、允许的层序、依赖/冲突及经过审核的合法配方。继续由 registry 的 ID/version/purpose/hash 解析素材。

`studio-renderer.js` 解释模板声明的有序配方：后侧穿戴 → 身体基底/局部分区 → 衣物 → 五官 → 前侧穿戴/实际手部或爪部遮挡 → 附着道具。这里是角色专属层关系，不是所有角色共享的唯一死顺序；帽子、眼镜、耳机接缝可以按真实关系拆分，前后交叠处必须有真实遮罩。无局部遮挡需求时可有具体 `notApplicable` 依据，但不能给复杂衣物统一填该值。

预览缩略图、放大视图和导出共用同一层解析结果；素材源尺寸、画布、锚点、阴影方向与透视保持一致。已有固定圆形模板可作为声明式配方的第一批适配，旧图和旧批准不重写。已有材质保真的配色算法只用于其明确 mask，不把整个身体 PNG 的 alpha 当成人物/多材质的统一染色区。

配方只登记已经制作并验证的组合；不因有多个选项控件就自动承诺笛卡尔积。以合法配方约束降低组合爆炸，但每个选项仍需可达、每条允许的组合都实际渲染并检视。不制作自由坐标拖拽或通用 3D 系统。

### 7. 一份成功快照驱动预览、Prompt 和透明导出

沿用内存 Draft + 单调 revision + session 的模型。外形、配色、五官、衣装、配饰变化递增渲染 revision；语言与纯文本外部方向不触发像素渲染。后者继续参与退出/切换的 dirty 判断，但不被描述为预览已实现的变化。没有背景配置或相关 dirty 分支。

成功快照包含 Artwork/version、Template/version、标准化选项、解析后的图层引用与 hash、层序、渲染器版本、session/revision 和最终像素。新的选择未渲染成功或失败时禁用导出，不悄悄下载旧样；复制配置 Prompt 与 ChatGPT 链接也不能把新选择配上旧成功像素。正在导出的旧成功快照要么完整结束旧文件，要么取消，不能混入新角色或新配置。

单一 Export 行为：未改变的有效透明基准作品返回登记原 PNG 的校验后原始字节；改变后的角色返回冻结成功快照的透明 PNG，文件名区分 Draft 与原图。逐项恢复基准后恢复原图导出语义。历史或错误路径的静态降级只能如实带走它的登记原图，历史不透明文件不得标“透明”；它不属于本轮已迁移 Gallery 的完成证据。

输出保留 alpha、完整边界与合理边距，无纯白填充、棋盘格、网页地台、字幕或场景。临时预览 canvas、Object URL 和加载 lease 及时释放；原图只在真实下载时读取与校验，不能为打开详情一次预加载全角色模板及原图。

### 8. Prompt 描述最终角色，不重放过时母版

`studio-prompt.js` 先解析有效的最终外观描述，再统一生成中英文。字段优先级：家族/身份硬约束 → 用户已选择且本地支持的外观值 → 未修改的已核实特征 → 明确标注的外部创作方向。硬约束不把本来可选的所有颜色/轮廓锁死；例如“Dots 短绒、无手脚、成对黑眼”与“本次改为暖黄色”可以同时成立。

生成段落按以下顺序：单体静态角色目标；身份约束；最终形体/材质/配色/五官/服装/配饰语义；参考图的条件式用途；用户额外要求；透明输出与贴合/遮挡限制。不得将 `color: warm-yellow`、内部模板 ID/revision 当作面向创作用户的主要描述，更不得在后面继续要求原图的蓝色。内部 ID 仍可用于调试与证据，不进入普通 Prompt。

所有静态流程都带条件参考说明，无额外方向时也不能漏掉。只在用户实际附图时读取：每张图/指定区域的用途、取什么、排除什么；没有附图则按文字执行，不宣称网站已读取图片或自动附图。UI、图内文字、场景和其他主体不是目标角色属性。

最终输出契约固定为透明角色。自由文字是用户给外部模型的补充意图，页面注明它不会即时改变本地预览；不需要新增自然语言分类服务或关键词删句逻辑。取消背景配置不等于解析并删除自由文字：文本原样保留并参与一般的未保存文本 dirty 判断，不创建 background 属性或背景渲染状态。Prompt 将其明确引用为受身份和透明约束限制的外部意图；矛盾要求请外部创作流程澄清，不能将背景或加手脚愿望提升为有效配置或网站已实现能力。Copy 与 ChatGPT 入口使用同一文本，用户自行确认发送。

Pets 借鉴 canonical identity、后续生成引用同一基准、边缘与接触检查方法。普通静态 Prompt 不拼接伪 `$create-pet` 调用；本期没有 Pets 按钮、创建、上传或切换活动宠物。未来真正制作 Pet 需重新按当时技能及目标端验证动作/方向/格式；本地 skill 的 waving 需要附着肢体或附属结构，与某些无肢体角色存在兼容性问题，不能凭透明 PNG 就宣布可安装。

### 10. 排序、详情与验收沿用共用入口

`studio-tags.js` 的 Curated 顺序先比较系列权重 `dots, grok, meta-muse, animals, humans, independent-original`，再比较明确的系列内策展顺序，最终用稳定 ID 打破并列。标签栏同步五系列顺序；搜索和筛选在相同排序函数前后保持一致结果集合。Name 排序是用户显式覆盖，按当前语言名称排序且使用稳定 ID 作并列键。

所有 Gallery 卡片使用共用 Studio 路由、关闭/返回、单 overlay 和未保存草稿 guard。编辑区域标题统一“角色调整 / Character adjustments”，保持自动进入可编辑详情，无需另造 View/Edit 双模式。家族适用类别 tab 的键盘与触摸可达、当前选择、禁用原因及 Export 在窄屏不被滚动区域遮住；原图元数据保持可读且只读。

验收不以文件数量或构建成功代替美术：目录覆盖 24 件及新增行；每个暴露选项有合法路径；每条合法配方实际预览/下载；深浅检查底上人工看边缘、贴合、材质、五官和遮挡；实测透明 alpha 与完整性；双语、1440×900、390×844 及 320/768 边界；真实下载文件与成功 revision 对应。测试脚本中的两个模板、固定 12/16、仅三个 tab 和“必须找得到静态角色”的旧正向断言需改成新合同，而不是删除校验。

## Risks / Trade-offs

- **全角色家族适用类别能力需要大量真实素材** → 先建立完整覆盖矩阵，按系列分批制作和审核；阶段完成不冒充全部完成，也不降级为 Prompt-only。
- **参考太小或相同造型跨截图难判** → 保存精确区域、来源和相似性裁决，允许有说明的原创补足，不能静默遗漏候选或制造官方归属。
- **Dots/Grok 衣装容易诱发肢体或类人化** → 将无手脚、材质和眼型写进制作 brief、模板验证与人工检查；取消这两类的服装能力；仅保留实际贴合配件，禁止增肢体来持物。
- **组合数扩大导致遮挡漏洞** → 有限合法配方、显式冲突与全配方验收共同约束，未验组合不可选。
- **历史两件不透明作品影响原字节下载合同** → 新透明版本独立批准后切换公开指向，保留历史资源和下载真实性，不改写历史文件/报告。
- **追加外部方向可能与预览不同** → 明确区分本地成功配置与外部意图，最终 Prompt 保留透明和身份约束；无需用自然语言推断伪造像素效果。
- **更多素材增加首屏与切换负担** → 缩略图、按需 detail、当前模板加载、请求取消和资源释放；按既有 performance 检查观察真实网络与内存，不预加载全库原图。
- **素材或模板尚未取得精确美术确认** → 准备完整可审阅图、逐组合证据后再请求必要的最终确认；工程工作继续独立推进。参考图、规划或旧母图批准不能替代新精确版本批准。
