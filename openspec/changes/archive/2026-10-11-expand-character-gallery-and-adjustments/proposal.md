# Proposal

2026-10-11 用户审阅针织围衣后明确选择：Dots / Grok Bot 取消服装 tab，只保留外观、配色、五官、配饰四类；Muse、动物、人物和独立机器人保留服装，共五类。Dots / Grok 的服装能力不适用，不以 None 控件充数，也不将衣物改名塞进配饰。每个适用类别仍须至少两个真实、合法可达且改变像素的结果。原有含围衣候选及检查记录保留为历史制作证据，不作为当前推荐或美术通过依据。

## Why

现有画廊有 24 件公开作品，但只有 2 件具备真实分层调整模板；其余作品只能查看和带走原图，参考图中的多种独特形象也尚未完整覆盖。需要把参考去重、角色身份、美术兼容、全角色调整与导出建立为同一套可验证的产品能力，同时修正原图背景和 Prompt 与最终配置不一致的问题。

## What Changes

- 对本轮 21 张参考图登记来源和用途，按文件重复、视觉重复、角色身份、独立外观分层去重；复用已有作品，补齐有明确差异的 Dots、Grok Bot、Muse、动物和人物外观。截图中的文字、UI、背景及错误肢体不进入角色资产。
- 保留所有当前公开角色，并使当前 24 件作品及本轮接入的新外观全部通过共用详情获得真实、经过逐件适配的角色调整能力；不以收缩画廊或 Prompt-only 达成覆盖率。待审、历史和异常资源保留明确降级行为，但不算全角色完成。
- 将详情中的“微调作品”统一为“角色调整 / Character adjustments”。提供外观、配色、五官、配饰；Muse、动物、人物和独立机器人另提供服装调整；各角色提供符合身份且有实际效果的选项，物品归入配饰，禁止空 tab、假选项与未适配跨角色套层。
- 以具体 Artwork/version 绑定模板、轮廓、图层、锚点、遮挡、材质和合法组合。Dots 与 Grok Bot 均无手脚；有四肢的屏幕脸机器人保持独立原创身份，不能混入 Grok Bot。
- 画廊使用真实 alpha 透明角色素材；为当前两件不透明资源另制透明版本，保护历史原图及批准记录。默认精选顺序为 Dots → Grok Bot → Muse → 动物 → 人物，独立原创角色随后；显式名称排序继续按名称工作。
- 保留单一 Export 入口，仅导出透明 PNG，预览和导出使用同一成功快照，不改变图库原图。依据用户最新条件及已核对的 Pets 0.1.6 透明资源合同，本期不提供背景设置、背景 tab 或带背景导出；界面底色只用于展示。
- 将 Prompt 生成改为依据最终语义配置、角色身份和明确参考用途输出一致的双语提示词；借鉴 Pets 的身份基准、透明边缘和参考约束方法，静态 Dot 保持本期核心。调用技能的文字不冒充技能已经执行，普通 PNG 不冒充 Dot/Pet 安装包。
- 补齐逐角色覆盖、全部合法组合、透明导出、异步快照、双语与移动端的验收；工程结果、美术检查、用户批准、目标包验证和部署分别记载。

## Capabilities

### New Capabilities

无；扩展现有合同，不建立平行的角色、编辑或导出规范。

### Modified Capabilities

- `artwork-catalog`: 参考去重、完整外观覆盖、精确版本资格、透明替换资源及统一结果快照。
- `catalog-tags`: 默认系列优先级和稳定排序，保留事实检索与显式名称排序。
- `character-families`: 参考身份归类、Dots/Grok 无肢体及独立机器人边界，适配不继承批准。
- `family-navigation`: 全角色共用详情、家族适用类别调整及草稿的退出/切换规则。
- `bounded-character-editing`: 全画廊精确模板覆盖、非空实效选项、图层兼容和透明导出。
- `character-contact-and-motion`: 穿戴接触、遮挡和形体规范，以及全角色透明资源边界。
- `character-visual-acceptance`: 逐件模板和全部合法组合验收、版本化资源证据与透明导出核对。
- `studio-creation-experience`: “角色调整”信息层级、共用详情与单一透明 PNG 导出。
- `studio-visual-experience`: 固定画廊优先级、透明素材显示、家族适用类别调整和双语响应式呈现；保留现有 D01 主视觉。
- `reference-creation`: 最终配置驱动的 Prompt、参考用途声明、身份约束和 Pets 方法的可选外部衔接。
- `target-resources`: 区分透明原图、透明 Draft 与真实目标包，遵循透明输出并保持目标验证边界。

## Impact

- 主要实现入口是 `dist/studio-content.js`、`studio-artwork-catalog.js`、`studio-tags.js`、`studio-edit-templates.js`、`studio-draft.js`、`studio-renderer.js`、`studio-preview-loader.js`、`studio-editor.js`、`studio-detail.js`、`studio-prompt.js` 及共用样式；继续使用当前静态 ESM/Canvas 架构。
- 需要制作新的完整作品与逐角色分层素材，维护版本、hash、来源、能力、合法组合及精确批准范围；复用共用渲染器不等于复用其他角色的素材或批准。最终新增数量由设计中的参考裁决清单和实际去重结果决定，不能以任意扩增或静默遗漏替代。
- 相应更新目录、模板、渲染、下载、编辑布局、透明度和浏览器验证，以及角色新增说明和精确静态发布闭包；旧 2 模板 / 12+16 组合断言改为依据登记的覆盖矩阵验证，历史记录保持原文。
- 本 change 的规划不生成或批准素材，不修改主规范或产品代码，不升级依赖。后续实施不包含动画精灵表、Pet 创建/上传/激活、账号/后端、全站改版或部署；sync、archive、提交和发布需要各自明确授权。
