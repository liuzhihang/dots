# Spec Delta

## MODIFIED Requirements

### Requirement: 五组工作台的 Canvas 输出必须遵守已登记的完整形象和配方
五组工作台 SHALL 以受信任登记的完整姿态形象作为 Canvas 源，在实际 Canvas 中合成当前受支持的形象与背景。每一组的可选形状、耳机、其他配饰、姿态和颜色 MUST 限定为其实际存在的完整形象模板或显式受信任变体；工作台 MUST NOT 以单只静态位图、任意拉伸或通用参数 UI 冒充任意捏形功能。Dots 的裸形/耳机两种互斥配方 SHALL 保持原有范围并通过真实 Canvas 呈现；其他组仅可开放已登记模板确实支持的形象和背景。任何组选项超出真实 Canvas 支持范围时，Prompt 与项目 JSON 仍可用，但该选项 MUST NOT 被描述为当前 PNG 已呈现。美术验收状态 SHALL 按具体素材、页面版本和用户明确确认单独记录；尚未确认的候选保持待确认，已明确确认的当前版本不得在验收记录中继续列为未确认。冻结发布版本中的候选标签只描述发布时的状态，后续确认以关联该版本的记录为准，不要求为追记确认重新发布。

#### Scenario: 在 Dots 中切换已登记的裸形和耳机完整配方
- **WHEN** 用户在 Dots 工作台切换耳机开关
- **THEN** 页面通过互斥选择显示裸主体或耳机与主体正确接触的实际正面 Canvas，不能把耳机悬浮/穿入的另一张图叠在基准上充当组合

#### Scenario: 修改真实 Canvas 未登记支持的参数
- **WHEN** 用户在任一家族编辑未登记支持的形状、表情、姿态或配饰
- **THEN** Prompt 保留该设定，页面说明该控制只影响 Prompt，不改变 Canvas 当前输出

#### Scenario: 更换背景并导出当前 Canvas
- **WHEN** 用户从当前家族已登记的背景选项中选择背景
- **THEN** 页面在真实 Canvas 中将该背景与当前完整姿态形象合成；下载 PNG 与画布回读一致，更换背景或下载行为本身不能将背景与角色资产标为美术已验收；明确用户确认只能按独立记录覆盖的素材与页面版本生效

### Requirement: 五组基准必须有真实的表情姿态变体
工作台 SHALL 为五组 canonical 基准各提供一套经登记的完整表情/姿态 PNG 变体，并通过既有角色字段原子选择。变体 MUST 以真实图片的眼形、表情、姿势和动作登记，Canvas、Prompt、项目 JSON 和 PNG 导出保持一致；不可将只更新 Prompt、CSS 位移或未加载素材称为已改变角色动作。尚未明确确认的变体 SHALL 保持候选待用户美术确认；已确认状态必须绑定实际呈现的素材、页面版本及确认范围，不能扩展到未制作或未呈现的状态。冻结发布版本中的旧候选标签不代替后续确认记录，既有 15 个图库身份不增加。

#### Scenario: 切换已登记的表情姿态
- **WHEN** 用户选择某基准的可用表情/姿态
- **THEN** 页面绘制该完整透明 PNG 与背景，更新同一角色配置与 Prompt，仅最新成功 Canvas 可以导出

#### Scenario: 重新导入含表情姿态的项目
- **WHEN** 用户保存再导入项目
- **THEN** schema 10 与文档 v1 保持，完整变体按可信字段恢复，未登记参数继续保留原值并明确不支持，不接收任意图片 URL
