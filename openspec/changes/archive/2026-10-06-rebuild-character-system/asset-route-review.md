# 资产路线与双模式实施合同

## 决策

2026-10-05，用户确认整图＋Prompt 与组合编辑可以并存，并要求优先保证整体效果；ChatGPT Dots 组合表现可作为质量方向。当前五组实际页面候选已被用户否决，不能靠刷新、构建或局部微调宣称已达到目标。采用两条能力边界清楚的路径，共用 Dots、Grok Bot、Meta Muse、人物、动物五组身份及同一角色设定。

两条路径分别是**Artwork（完整静态图＋Prompt）**与**Composer（本地分层图实际合成）**；**结构诊断**单独保留既有三维诊断。它们不是同一种预览的不同皮肤：静态作品不能随着配置伪变成当前角色；组合图只由受信任分层资产包真实合成；旧三维模型只能帮助检查结构、接触和渲染问题。

## 共享设定和项目文档

角色设定继续使用既有 VERSION 10。项目模式由外层文档包装，不升级角色 schema：

```json
{
  "format": "dot-studio-project",
  "version": 1,
  "character": { "version": 10 },
  "creation": {
    "mode": "artwork",
    "artworkId": "dots-historical-example"
  }
}
```

上面仅展示字段结构，不能作为有效角色配置样本。`creation.mode` 限于 `artwork` / `composer`，`artworkId` 限于本地登记且与当前角色组相符的 ID 或 `null`。JSON 不放图像字节、本地任意路径或任意 URL。老的纯角色 JSON 继续按原迁移规则导入；项目包装保留模式选择。配置编辑、参考文字、配饰意图、撤销/重做、自动保存和导入导出都作用于同一当前角色设定。

完整 Prompt 的展示、复制、TXT 下载和打开 ChatGPT 基于同一冻结配置快照。打开 ChatGPT 只复制当前 Prompt 并打开 ChatGPT；用户自行粘贴、附图和发送。本地不自动生成、上传或附加用户图片，也不代发消息。

## Artwork：下载登记的完整作品，设定只影响 Prompt

固定作品由应用本地清单按稳定 ID 注册，字段包括角色组、文件、名称、来源及身份状态。用户修改颜色、表情、姿态或配饰时，角色设定和 Prompt 跟随变化；原图保持字节不变，并在页面说明它是固定作品示例、不会随设定变化。下载必须直接取得清单内原始文件，不经画布重裁切或重绘。

当前可用历史 PNG：

| 角色组 | 文件 | 页面状态 |
| --- | --- | --- |
| Dots | `dot-plush-headphones-v2.png` | 历史整图示例；来源记录不证明为官方原版 |
| Grok Bot | `grok-matte-work-v2.png` | 历史整图示例；来源记录不证明为官方原版 |
| 人物兼容组 | `muse-fabric-reading-v2.png` | 历史整图示例；不能代表新原创人物基准 |
| 动物 | `pet-shiba-scarf-v2.png` | 历史整图示例；不能代表新原创动物基准 |
| Meta Muse | — | 当前没有整图 |

历史图只可由 Artwork 路径明确标为历史示例并原样下载，不得冒称官网原版、当前用户设定的生成结果、新基准角色或美术验收通过。整图不存在时显示缺失状态，保留 Prompt 与 JSON 能力；禁止以别组图片填空。任何历史 PNG 都不允许夹带用户从动漫截图裁切的像素、贴图或抠图。

## Composer：仅导出真实支持的分层合成结果

`layered-2d` 资产包由应用本地发布并登记在受信任清单；不从导入的 JSON 中读取资源 URL 或路径。每个包至少绑定稳定包 ID、角色组、版本和来源，明确一个或多个可实际完成的视图、支持的角色参数/取值、前后遮挡顺序和有效范围。配饰包还须声明与基准相容的接触/遮挡关系。当前只批准固定 front 作为第一版能力方向；任意转三维、侧视角或未制作动作不能凭一张图推断支持。

系统根据当前共享设定选择清单中确切支持的图层，并把它们真实绘制到 Canvas。只有绘制成功且配置没有超出该包声明能力时，Canvas 才能当作当前结果显示和导出。不得拉伸静态完整作品伪装为体型变更，不得把历史整图、三维诊断画面或占位符当成合成结果。缺包或当前配置未被包支持时，保留编辑、Prompt 与 JSON；明确提示原因，并隐藏/禁用当前角色 PNG 导出。

目前 `COMPOSITION_PACKS` 清单为空。没有高质量新基准或经页面验证的分层角色包，故五组当前都不能从 Composer 导出新角色 PNG。未来可按一组一只基准、网页可见的真实组合、透明边缘/遮挡/导出实测、明确用户确认来逐组添加资产；任一组通过不自动解锁其他组。

## 结构诊断：保留旧三维合同，不作成品入口

旧实时 Three.js/WebGL、CPU renderer 以及多视角、动作、比例和构图诊断继续保留在名称明确的“结构诊断”入口，服务于旧模型的几何、配饰接触与动作排查。既有三维渲染/接触/CPU 要求仍对这条路径有效。诊断页与 Artwork/Composer 明确区分；即使能生成真实诊断 PNG，它也不代表已完成高质量角色资产或通过网页美术验收。若后续提供真正的三维角色成品，该生产路径仍须达到本 change 原有 WebGL 与 CPU、多视角、比例端点、动作、配饰接触和实际导出合同，不能以“诊断入口”为由跳过验收。

将来真实新资产通过不同能力合同验收：Artwork 检查来源标签、角色身份、材质与配饰接触、下载文件和共享 Prompt；固定视角分层 Composer 检查真实 Canvas、声明范围内的参数、层次遮挡、边缘和实际文件。单张 2D 图只验收其声明视角；旧三维侧面、动作、CPU 要求继续在结构诊断中保留，真实三维成品则同样必须满足原三维合同。两条路径都不能代替真实角色的艺术质量和用户逐组确认。

## 本轮工作范围

本轮继续实现创建模式、共用设定、文档兼容、Prompt 和按模式选择输出的逻辑，按本合同保护真实能力边界。不会因为模式逻辑、旧图下载或结构诊断通过而勾选任何组的艺术任务；五组仍须分别通过真实页面检查并获得用户对该组的明确确认。分类导航和全屏随机仍由 `refactor-family-navigation` 与 `add-fullscreen-randomizer` 两个独立 change 管理，不在这里改造或发布。

## 证据边界

原 `acceptance/evidence/` 保存的是用户否决前各次本地源码的诊断截图、旧图、旧导出、Prompt 与检查数据，相关 manifest/hash 不应被后续实现重写。新模式逻辑另行记录可复现代码版本和新验证结果；概念图、历史图、自动化测试通过、build 成功和 OpenSpec 勾选都不表示当前页面美术验收通过。用户原始动漫图只用于分析提炼，不能成为人物/动物的最终图片、抠图、纹理或完整复刻。
