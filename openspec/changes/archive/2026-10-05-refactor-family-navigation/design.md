# Design

## Context

背景见 [proposal.md](proposal.md)，可观察行为见 [family-navigation spec](specs/family-navigation/spec.md)。应用是原生 JavaScript 单页编辑器，只有一个活动项目和五个稳定家族 ID。用户最新确认的路径为封面、内置形象画廊与创作工作台；首页家族卡进入对应图库，“用这个形象定制”才选中形象并进入工作台。图库由 `refresh-studio-visual-design` 登记每组一只 canonical 基准及两项候选，共 15 项。旧的首页卡片直入工作台与只搜索基准的合同由本次更新替代；角色 VERSION 10 与项目 JSON v1 保持不变。

## Goals / Non-Goals

**目标：**

- 用相同的五个家族 ID 连接首页、图库和工作台，清楚区分浏览筛选与活动项目。
- 首页搜索五家族展示元数据，图库搜索已登记的 15 项形象；保留每组唯一 canonical 基准与候选标签。
- 只有明确选择形象定制或切换工作台家族才改变角色；浏览操作保留未提交草稿。
- 在当前页面会话中恢复各家族的编辑、参考文本、创建模式和输出设置。
- 保持桌面、平板与移动端可用，不引入独立路由框架。

**非目标：**

- 不增加家族、canonical 基准、图库身份、云端收藏或新的持久化格式。
- 不负责整体视觉系统、随机状态机或逐组美术验收。
- 不将搜索或筛选转化为图像生成，也不将任务完成视为角色获得用户认可。

## Decisions

### Separate gallery browsing from the active family

所有卡片、筛选和工作台入口使用稳定家族 ID。首页家族卡调用 `openGallery(family)`，进入 `#looks/<family>`，不调用角色提交或工作台家族切换。首页及图库的筛选选中态表示当前浏览范围；工作台和首页卡片的当前角色标识仍读取活动项目家族，两者可以不同。“全部家族”不是第六个角色 ID。

图库卡片的“用这个形象定制”调用现有 `startLook(artworkId)`，载入该形象的可信角色设定并导航到 `#workspace`。用户选择完整形象是一次明确的角色变更，可撤销；沿用当前工作台选择操作对自定义名称、背景、补充文字及参考说明的保留规则。普通路由、浏览和筛选不替换当前项目。

**备选方案：** 浏览某家族时同步重置工作台到该组基准。未采用，因为用户选择的是内置形象浏览入口，而且这会丢失当前创作上下文。

### Keep an in-memory project draft per family for the active page session

工作台切换家族前保留当前项目快照；首次进入另一个家族载入其 canonical 默认项目，同一会话返回时恢复该组草稿。快照包含角色、创建模式、参考文字与保留项、补充文字及输出设置。显式选择图库形象定制会建立用户选择的新活动项目，不要求恢复被用户主动替换的形象；其余家族草稿保持独立。搜索、图库筛选、返回首页及进入工作台均不提交项目。

多家族草稿映射只存在于当前页面会话；现有单个活动项目的导出/导入及会话保存继续负责既定的保存行为。不得将草稿集合强制写入角色 schema 或项目文档，也不得宣称完整重新载入可恢复所有家族。

**备选方案：** 将所有家族集合写入项目 JSON。未采用，因为产品仍是单活动角色文档，用户未要求多角色持久化格式。

### Search only registered family and gallery metadata

首页搜索五家族的名称、说明及精选特征词。图库搜索当前登记的 15 项完整形象的名称、描述、家族和资产 ID，并与所选家族筛选求交集。两处统一 NFKC、大小写及空白，多词须在同一条元数据中匹配。无结果状态提供清除操作；清除图库查询保留该图库家族筛选，不修改角色或草稿。

搜索仅展示已登记内容，不把历史/退役作品和 legacy 预设加入图库，不增加 canonical 基准，也不启动生成。图库筛选使用现有 hash 路径并替换当前浏览历史项，保持 URL 与可见家族一致。

**备选方案：** 搜索全部旧预设和编辑字段。未采用，因为历史兼容数据不属于本轮 15 项图库候选目录。

### Keep browsing and selection operable at touch widths

桌面在页面外框显示家族栏和搜索框；窄屏搜索占满可用宽度，五家族筛选采用内部横向触控滚动或换行。当前图库筛选自动进入可视区，键盘筛选后保留焦点；主要页面无水平溢出。首页卡片、图库定制动作和工作台家族选择均有清楚名称与当前状态。搜索提示和结果数量在手机保持可见。

**备选方案：** 将五家族藏在无标签图标菜单中。未采用，因为它会隐藏身份和当前浏览范围。

## Risks / Trade-offs

- [图库筛选与工作台当前家族不同] → 将筛选状态与活动项目标识分别呈现；只有定制形象或工作台家族选择改变项目。
- [完整重新载入丢失其它家族的内存草稿] → 保留现有单项目保存合同，明确多家族映射仅属当前页面会话。
- [15 项图库被误认为扩展许可或美术通过] → 每组仍一只 canonical 基准加两项候选，展示与搜索不改变验收状态。
- [内部触控导航误造成页面溢出] → 在 320/390/768 px 实际浏览，核对选中筛选、焦点和页面宽度。

## Migration Plan

1. 将独立导航 proposal/design/specs/tasks 与用户最新的封面→对应图库→明确选择形象→工作台路径协调一致，保留当前实现。
2. 使用实际生产事件处理与路由/草稿函数补回归：五组家族卡进入正确图库，浏览/搜索/清除不提交项目，定制动作选择准确形象，工作台返回各组恢复独立草稿。
3. 在真实浏览器复查首页、图库筛选/搜索、定制进入工作台、返回及单项目导入/导出，并覆盖桌面、768/390/320 px 和键盘焦点。
4. 运行相关回归与严格 OpenSpec 校验；本轮仅本地编辑、验证及符合条件的规范同步/归档，不推送或发布。历史 Site 交付记录继续单独保留。

## Open Questions

无。浏览筛选不改变活动项目；只有明确选择定制或工作台家族切换才改变角色。逐组用户美术确认仍属角色 change 的独立门槛。
