# Proposal

## Why

用户已将“内置形象”和“创作工作台”确认为两条独立路径：首页家族卡用于浏览该组图库，只有选择某张形象的“用这个形象定制”才将其设定带入工作台。旧导航合同仍将家族卡和搜索结果直接视为当前角色选择，与已交付路径不一致。将五家族浏览、图库筛选与工作台角色选择明确分开，使用户能探索现有角色而不丢失当前草稿。

## What Changes

- 在首页、内置形象页与工作台使用一致的五个稳定家族 ID：Dots、Grok Bot、Meta Muse、人物、动物；“全部家族”仅为浏览筛选状态。
- 首页家族卡进入对应家族的内置形象画廊，不切换当前项目；图库筛选与当前工作台家族可不同。工作台家族入口才恢复或建立该组页面会话草稿。
- 首页搜索已登记的五家族展示元数据；图库搜索当前登记的 15 项内置形象。每组仍有一只 canonical 基准和两项本轮展示候选，导航不新增身份、基准或扩展许可。
- 搜索、筛选、清除及首页/图库/工作台路由切换只改变浏览状态；每张形象的“用这个形象定制”才明确载入该形象并进入工作台。
- 在工作台家族切换时保留各组角色配置、创作模式、参考图文字与保留项、补充文字及输出设置；保持 VERSION 10 和项目 JSON v1。
- 保持导航交互与整体视觉刷新、全屏随机状态机独立；不引入账号、路由库、搜索服务或站内生成服务。

## Capabilities

### New Capabilities

- `family-navigation`: 五个独立家族与已登记图库的浏览、检索、筛选、明确选择、草稿保持及响应式交互。

### Modified Capabilities

无。本 change 为新增家族导航能力提供增量规范；图库的 15 项有界内容、候选身份和美术验收边界沿用 `refresh-studio-visual-design` 与 `rebuild-character-system`。

## Impact

影响现有原生 JavaScript 单页应用的家族/搜索状态、导航组件、hash 路径及页面样式。当前实现已采用首页家族卡进入图库的路径；本次协调合同并补导航回归，保留现有实现与角色格式，不退回旧的直入工作台行为。
