# Design

## Context

当前工作树保留44件原Artwork、44个精确获批Template、90个来源Look、540条合法recipe。首轮把每个来源的appearance直接显示为卡片，漏掉了跨来源的基础外观去重。用户本轮授权修正，并要求下拉按钮左侧留白更紧凑。先前验收报告仅证明当时实现的技术行为，不证明90种不同基础外观；原报告原文保留。

## Goals / Non-Goals

- 图库同一基础外观只出现一次；颜色、五官、配饰不增加卡片。
- 保留真实来源与配方，当前成功预览、Prompt和PNG始终绑定同一实际配置。
- 保持原生下拉语义、44px命中区、双语、键盘和窄屏可用。
- 不重绘素材、不克隆批准Template、不伪造组合，不删除原Artwork/Look/recipe，不新增依赖；不进行仓库Git提交/推送、规范同步或归档；用户后续明确授权通过后发布现有 dots Sites。

## Decisions

### 1. 来源Look与公开Figure分层

保留GalleryLook作为单Artwork/Template/appearance的来源记录，新增GalleryFigure公开导航。按明确基础轮廓分组，禁止用body文件hash或通用classic/soft选项名自动判定身份：不同颜色的素材hash可能不同，同名选项也可能属于不同角色。

确认3组：`dots-orb`聚合蓝/莓粉/浅紫圆球（3→1）；`dots-cloud`聚合三者云团、奶油黄低矮云团和蓝帽云团（5→1）；`dots-rounded-triangle`聚合奶油贝雷帽与黄色眼镜圆角三角（2→1）。90个来源Look归入83个Figure。宽圆云团、花云、窄高三角等登记了不同轮廓的外观不在本次归并；Grok光滑软几何与Dots短绒材质不混合，人物/动物不同身份不因通用标签相同而合并。

Figure包含稳定id/version、memberLookIds、canonical defaultLookId、双语基础名称、系列及canonical完整封面。merged版本为v1，登记成员版本和来源签名；singletons沿用Look版本。默认圆球采用candidate-dots，云朵采用其cloud，三角采用butter-beret。卡片名称不以颜色或配饰命名合并形象。

### 2. 真实配方状态与语义选项

每个Figure state保留原Artwork、Template、Look、recipe和original selections引用；全部540条原配方恰好归属于一个Figure。公开UI使用各字段的语义ID与真实标签；original/alternate等模板局部ID不能作为全局颜色。无配饰统一为none；颜色及实际配件按登记语义映射，不凭同名id扩大能力。

选项解析保持未点击字段的当前语义值，只接受一个真实已登记recipe；同语义配置多个来源时优先当前来源，再按稳定目录次序选择。不存在合法结果时禁用并用短说明解释，不静默卸除配饰。语义重复值不增加来源/样式tab，也不强迫公开区分像素文件来源。旧精确入口仍可访问原来源配方。

### 3. 稳定Figure会话与单来源渲染

FigureEditor外壳维护figureId、session、baselineStateId、currentStateId及externalIntent。底层createDraft/createEditor/renderDraft继续按精确单Artwork/Template/Look工作，不创建合成批准模板。跨成员切换先验证目标state，再取消旧child、绑定真实目标并渲染；Figure会话、语言、补充要求及dirty基线不因child重建清空。只有最新state成功才更新Prompt并允许PNG导出，旧请求不能覆盖新状态。

Figure标题/相关入口保持基础形象，当前原始资料与结果操作使用实际source。所有Figure入口无论是否修改都导出当前成功renderer PNG，以保证画布与下载一致；旧Artwork/Look入口保持原字节/修改PNG语义。关闭、返回、Escape和回图库不确认；切到别的Figure仍保留既有dirty处理。

### 4. 路由、下拉与验证

主图库和相关形象使用 `#/figure/<id>?v=<version>`；旧Artwork/Look路由继续严格解析，未知版本不回退。恢复搜索、系列、排序、滚动和Figure触发焦点。

首轮只调整左对齐仍留下过大中间空白：当前中文语言控件108px、排序132px。去除固定宽度及移动固定列宽，用原生 field-sizing:content 按当前选项收紧；不支持该属性时保留原生内在宽度回退。12px左padding、34px右槽包含12px箭头和约10px间隔，保持44px高度、配色、focus-visible和键盘行为。用当前内置Browser截图及中英/桌面/390/320px实测闭环。

工程验收证明83 Figure、90来源、540配方绑定完整、无跨模板合成、跨来源云朵颜色/配饰操作后Prompt/PNG精确、旧链接与原批准文件不变。保留原540renderer像素基线，新增公共Figure UI、默认及跨来源导出、会话/竞态/关闭和下拉复验。测试因主图库去重而迁移公开计数，不减少原44来源断言。

## Risks / Trade-offs

- 同语义来源的纹理和细微比例可能不同：保留真实来源、确定性解析，不宣称图像字节相同；基础分组由已观察轮廓和登记语义明确指定。
- 合法配方稀疏：不把所有颜色×配饰当作可用组合，无法保持其它选择时明确禁用。
- 跨来源异步串图：Figure revision/session与child取消共同约束，测试快速切换及成功结果绑定。
- 其他相似轮廓：仅归并本次证据明确的3组，不按通用标签全站误并。

## Migration Plan

在当前未提交工作树增加Figure层、更新受影响入口和精确manifest。原素材/审批和旧链接保留，无持久存储迁移。完成本地验收后按精确manifest生成发布目录、通过Sites专用源仓库同步和发布到现有项目，保留受众设置并完成线上复验。用户工作仓库保持未提交；不sync/archive。

## 下拉控件视觉细化（用户后续反馈）

保持 native select DOM 与既有 onchange/详情迁移行为，统一为轻紫灰描边、12px圆角、深色渐层表面，桌面13px/窄屏12px字重500，44px高度和10px文字到箭头间距。支持 appearance:base-select 的浏览器渐进启用原生 picker：菜单右缘与按钮对齐、7px分离、14px圆角、6px内距、44px菜单项，淡紫色当前项和原生 checkmark。键盘焦点与 hover 分开处理；不支持该能力时使用相同收起按钮及系统菜单，不新增替代组件或依赖。展开菜单的 Escape 应只收起菜单，再次 Escape 才关闭Studio。

以当前线上页面截图作问题依据，复验支持端的展开/选择/键盘及窄屏位置，同时明确旧浏览器回退为工程模拟，不宣称已测实体Safari/Firefox或手机。

弹窗标题栏原先只有2px上下留白，44px语言控件显得拥挤。桌面上下留白调整为8px，窄屏为6px并兼容安全区；语言控件双语统一13px、44px点击高度，标题与返回文字桌面13px、窄屏12px，保持同一垂直中心。320px英文标题允许自然折行，不缩成10px小字、不挤占语言文字和关闭按钮。

线上双语切换补验发现增大字号后“返回”受原18px内边距挤压换行；桌面返回按钮改为12px水平内边距，窄屏6px并保持单行，确保返回、语言和关闭按钮均为44px高度。新增实际文本行高断言，保留问题截图与修复后证据。

## 弹窗导航收紧（用户再次纠正）

用户明确要求缩小导航和语言下拉。本轮以当前线上60px标题栏、44px语言按钮、54px且等分拉满的分类导航为基线。精细指针下标题栏收紧为44px，返回/关闭/语言按钮为36px；语言使用12px文字、8px圆角和按内容宽度，原生菜单最小宽度128px、36px选项。调整分类改为内容宽度，不将少量分类均分铺满面板，36px高、单行；多个分类超出窄屏时局部横向滚动。粗指针触屏按钮、菜单项和分类保留44px目标。图库语言/排序样式及弹窗正文排版维持当前状态，不改变角色数据、选项、预览或导出逻辑。

## 相关角色直接切换（发布前用户反馈）

线上改过颜色的Figure点击相关角色仍经过window.confirm；原生对话框会阻塞页面，内置Browser中该次点击也无法返回。按用户明确的点击切换意图，跨角色、变体及详情前进/后退同样直接导航，替换当前临时会话并载入目标默认配置，不增加第二弹窗。dirty保留为内部配置差异，不再用于浏览阻断。此决定取代上文保留跨形象dirty guard的初期设计。回归必须覆盖从已修改配置及补充要求切换、再次编辑/语言切换、关闭恢复图库，以及不同角色间异步预览不会串图。线上版本一致性与交互验证分开记录。

## 发布目录中的配饰缩略图（用户截图反馈）

v107 的 Figure 缩略图加载器显式关闭了 deliveryRegistry，直接读取模板源 PNG；真实发布闭包按主规范排除这些 source-only PNG，因此完整本地 dist 可显示图片而线上出现红叉。恢复已有登记无损 WebP 传输，并显式要求完整 delivery coverage；仍使用原源资源身份、hash 与图层放置，不新增图片或改变配方。验收须实际服务按 static-publish-manifest 生成的目录，证明六个非空圆球配饰均显示真实缩略图且没有请求模板源 PNG。

缩略图失败与兼容性禁用独立记录：“None”的灰色叉表示无配饰；红叉表示读取失败；蓝色圆球闭眼时黑色墨镜与赛博眼镜没有保持其它字段的登记配方，因此继续禁用，睁眼时恢复可选。不得用网络原因掩盖发布路径错误，也不得为了消除禁用状态擅自增加组合或静默改变五官。发布修复版后复验截图所示配置、合法点击与当前透明 PNG，网络延迟和实体设备结果单独说明。

## 选项素材辨识度与加载反馈（用户追加）

v108截图表明，56px透明缩略图区使黑色眼镜几乎融入深底，扁平配件也过小。将真实素材缩略图区放大到76px，沿用登记的有效边界裁切与实际图层，以柔和中性亮底承托深浅素材并保留名称；不增加新素材或改变导出像素。此背景仅为CSS界面呈现，不使用棋盘格，不将图片失败占位当作已完成设计。

waiting-for-manifest和loading状态显示轻量旋转指示，Figure按钮通过aria-busy暴露加载状态；ready、empty、error结束加载指示。减少动效时使用静态加载标记。缩略图加载不扩大当前配方能力，也不把图片的加载状态与预览更新或组合禁用混为一谈。复验须包含实际配饰、五官和人物服装、桌面/390/320双语，以及人为延迟交付资源的加载与减少动效状态。

### 用户对灰色底块的纠正

v109灰底虽改善黑色素材辨识度，但用户认为过重、与现有网站风格不协调，未部署。后续采用当前品牌的低饱和紫蓝色与浅紫柔光，优先融入卡片整体而非叠加厚重的内层灰方块；选中与hover仍需清楚，黑色镜框及白色厨师帽都可辨。先在真实页面比较配色，再冻结发布目录复验。加载环和透明PNG合同继续保留。

v110实际页面比较后选用整张卡片上部的淡紫柔光：沿用focus/accent-light色值，向下渐隐到深色卡片；缩略图区域透明，去除内层底框，素材阴影减半。空配饰和加载中采用同一完整卡片背景。原始素材、配方与PNG保持不变。
