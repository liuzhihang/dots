# 资产路线复审

## Context

2026-10-05 用户明确否决程序化候选，并询问是否没有渲染。页面 canvas 已处于 `ready`，WebGL 实际渲染和真实 PNG 下载均存在；粗糙外观是当前模型、材质和资产组织的结果，不是等待加载即可恢复。修正穿面、索引和接触只是必要的工程修复，不能证明达到 R01。

用户随后提出完整图片＋Prompt 与组合可以并存，并强调整体效果；ChatGPT Dots 的组合效果也可作为质量方向。该反馈不等于用户批准当前五组候选，也不等于要求放弃组合。当前程序化实现不足不能推导为所有程序化或组合方案都无法做好。

## 推荐方案：整图与组合共用角色设定

采用两条创作路径，保持 Dots、Grok Bot、Meta Muse、人物、动物五个分组与单只基准门槛。站点视觉仍沿用已确认会话与 R01，无登录或用户空间。以下为推荐的修订方案，尚未落实为业务代码；现行真实三维视角/动作合同须在路线明确后逐条修订，不能暗中删除。

| 路径 | 页面与输出 | 资产制作 | 真实验收 |
| --- | --- | --- | --- |
| 完整形象＋Prompt | 显示明确标注的完整作品，下载该作品，复制设定 Prompt 或打开 ChatGPT；自己的图片另附 | 按基准设定制作精细完整图，保持身份、材质、光照、表情、配饰接触；图片版本绑定设定与来源 | 检查真实页面尺寸、作品实际文件、透明度、下载和 Prompt 回读。作品不代表组合渲染或三维模型已通过 |
| 组合编辑 | 在页面实际更换已支持的颜色、表情、配饰，导出当前合成结果和对应 Prompt | 先做好精细基准，再制作同光照、同透视的部件；采用真实模型或明确标注的分层资产，不继续用粗糙占位作为成品 | 每个开放组合在真实页面检查遮挡、接触、边缘、尺寸与导出。生成素材本身不算页面验收 |

完整作品的参数变化首先更新 Prompt。若画面没有实际生成或合成新结果，页面必须明确标注原作品是设定示例，不能把旧图称为当前参数的输出。本站不宣称已自动生成新图或已把图片发送给 ChatGPT。

两条路径共享：稳定角色 ID、身份参考、主体/眼睛/毛发/服装/配饰色、材质语言、表情、姿态、背景、来源与禁止项。整图 Prompt 与组合 Prompt 从同一份设定生成，区别只在真实输出能力和画面类型；完整图不能出现组合基准没有的身份特征，也不能以高质量样张遮掩低质量组合结果。

## 制作顺序与质量门槛

1. 先精做一只 Dots：裸形与黑色耳机组合。页面正常显示尺寸必须读出柔软体积与细密短绒，不得有刷毛条纹、黑点、塑料球质感或漂浮耳罩。
2. 以同一设定制作完整作品与可组合部件；每件配饰包含前/后遮挡关系，接触位置按该主体确定。三维资产需要实际网格、材质和连接；分层图片资产需要干净 alpha、固定透视和遮挡层，不能简单贴 PNG 到主体上。
3. 在真实页面切换无配饰/耳机、颜色和已支持表情，检查桌面、320/390/768 px 与实际导出。完整图和组合分别记录结果。完成这些证据并获得本组明确确认后，才扩展 Dots。
4. Grok Bot 按软胶、胶囊眼与克制状态表达制作；Meta Muse 按 A02 包覆外壳与暖色内嵌脸面制作。人物与动物先建立原创精细基准，禁止动漫截图、抠图、贴图或完整复刻，再从相同基准拆解可组合部件。每组分别验收，不能由 Dots 通过推断其他组通过。

不以部件数量为目标，也不先生产大量表情、衣物、物种或姿态。当前没有已验证的精细三维资产包；用户允许使用软件原版身份，不等于本地已经拥有原产品的模型、毛发系统和动画资产。

## 必须显式界定的能力

- 分层资产可以做精细可编辑的 2D/2.5D 合成；仅开放已制作和验收的视图及动作。不能宣称一张图支持自由三维旋转，也不能把对整图的拉伸称为真实体型编辑。
- 真正三维方案须有完整模型、材质、贴图、必要的骨骼/变形/动作和配饰连接，再检验 WebGL 与 CPU 路径是否实际支持。当前 CPU 数值检查不证明新三维资产已能正确渲染。
- 当前 change 对多视角、比例、动作和两条渲染路径有要求。选定新资产方案后须在 proposal/specs/design/tasks 明确替换或保留哪些要求，不能将缺失能力记为完成。
- 本次只修订推荐方案与失败记录，不新增图片上传/生成服务，不保存 Sites 新版本、不发布，不改分类导航或全屏随机。
