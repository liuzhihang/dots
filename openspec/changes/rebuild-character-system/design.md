# Design

## Context

动机与范围见 [proposal.md](proposal.md)，源码身份、工具及运行边界见 [source-audit.md](source-audit.md)。本设计跨角色数据、几何、材质、配饰、动作和两条渲染路径，并涉及旧配置迁移，因此需要独立 design。

实施前 v27 的 `dist/studio-model.js` 使用 schema 9，支持 6/7/8 的迁移，只有 `dots/grok/muse/pets`。`muse` 使用人物解剖、头发、衣物；`pets` 提供多个物种。目录有 57 个历史预设，不能将用户要求「放弃旧美术」解释为删除已保存数据。`dist/studio.js` 和 `studio-random.js` 都直接枚举 FAMILIES，角色注册会同时影响选择和随机。

实时渲染是 Three.js 0.180.0；身体、表面纤维、配饰、动作分别位于 `src/live/`。已有头顶、脸面、颈前、口部、肩、手锚点及配饰表面 raycast；这些只能提供几何位置，不能证明视觉接触自然。固定美术成片和实时角色目前存在精度差距。WebGL 与 software renderer 都有地面/脚底阴影逻辑，必须同时处理。

## Goals / Non-Goals

**Goals:**

- 把身份、表面与接触规则分开，避免一套基础模型换色覆盖所有组。
- 用五只实时可编辑基准逐组检验当前架构是否能达到已确认的精细方向。
- 在保留旧配置的同时，将新候选与 legacy 美术、生成概念图明确区分。
- 把真实页面证据、程序验证和用户逐组确认分别记录。

**Non-Goals:**

- 不建设登录、账号、我的空间、用户云端图库。用户直接在工作台创作和导出；参考图片在 ChatGPT 另附，本站不假装已携带图片或完成生成。

- 本 change 不生成新效果图替代实时模型；当前已获 apply 授权，实施和页面检查在本机进行，发布仍需单独指令。
- 本 change 不改分类导航布局，不新增动漫组，不实现全屏随机体验，不新增图片上传/识别服务。
- 不先升级依赖、替换渲染框架或批量生成全部角色；不以固定 PNG 覆盖实时预览。

## Decisions

### 产品入口与功能参考

核心路径为「创建形象 → 带走结果」：实时可编辑预览导出 PNG/JSON、完整 Prompt 复制/TXT、复制并打开 ChatGPT、自己的图片与参考 Prompt 配合使用。当前 ChatGPT 入口会复制文本并打开 ChatGPT，随后由用户粘贴、另附图片并提交；本站不自动生成图片或代用户发送。R01 顶部的登录/我的空间不纳入产品。

2026-10-05 只读检查用户给出的 [bloub](https://bloub.vercel.app/) 与 [Grokbot Icon](https://grokbot-icon-studio.serio-ai.chatgpt.site/)：前者可见形状/表情/颜色编辑、动画入口与 PNG/其他格式输出；后者可见短/完整 Prompt、复制、ChatGPT 入口和另附原图步骤。这些仅支持功能路径的参考，网站设计仍采用既定会话方案与 R01，不采用参考站视觉。只读看见入口不等于已验证参考站的导出或生成结果。

### 0. 以本轮确认图确定整体方向，按来源处理角色身份

用户本轮确认 [R01](references/r01-confirmed-direction.jpg) 的整体效果为最终方向：明亮柔和的蓝/紫/绿/米白配色、轻盈背景、具有体积的精细角色、清楚的毛发与织物层次、鲜活表情和自然配饰。图中的宽幅角色展示、浅色家族卡片、轻量编辑区作为后续页面气质参考；具体导航和全屏随机仍分别在独立 change 中处理。登录、我的空间等图示内容不会自动变成新功能需求。

来源分两类处理。用户从动漫截取的人物、动物图仅作观察参考，不能把截图像素、裁切/抠图或贴图作为最终角色资产，不能通过临摹建模还原同一完整角色。提炼发束组织、表情、比例、毛色结构和材质精度后，重新组合脸型、发型、服装、物种细节与配色；仅换色或换配件不算完成重设计。

Dots、Grok Bot、Meta Muse 以及 Codex 等软件内置角色，按用户明确的使用范围可以保留原版身份与识别特征，仍标明具体来源，不冒称为本站原创。软件内置身份与动漫截图来源不得混为一类。本轮不新增 Codex 分组，也不预先挑选未提供的内置角色。R01 确定总体精细度，各组基础身份仍按各自原版参考校准：Dots 和 Grok 不互换五官/材质，Meta Muse 保持已指定 A02 的包覆式身份，人物与动物使用新设计。

原版产品身份与原创人物/动物分别管理，同时保留动漫截图禁止直接使用的明确边界。R01 仍是设计方向图，不能替代可编辑网页和逐组用户验收。

### 1. 一组一只基准，先检查裸形再检查配饰

以下具体颜色、发型和物种是**方案默认候选**，用于使后续实施可执行；会话确认的是五组身份与整体精细风格，不代表用户已批准这五只具体成品。网页检查与用户确认进度另见实施证据记录；本表不表示已通过。

| 分组 / 基准候选 | 必须识别的结构 | 材质处理 | 首轮接触组合 | 禁止项 |
| --- | --- | --- | --- | --- |
| Dots / 蓝色圆润主体 | 保留官方基础轮廓和简洁成对眼睛；以会话 Dots App 截图及官方页面校准 | 高密度细短绒，方向与主体曲面一致，柔和自身明暗，黑色眼睛清晰 | 无配饰 → 黑色耳机；头梁连续，耳罩两侧贴合 | 把生成图的鼻口、四肢直接当官方结构；粗刺、稀疏毛束、塑料球；断开的耳机 |
| Grok Bot / 淡紫软拱形 | 保留官方 Grok Bot 基础语言，柔和圆角几何、成对胶囊眼，无人物头发；保留独立轮廓 | 哑光软胶，低对比柔光，避免金属高光或长绒 | 无配饰 → 透明眼镜 → 工作电脑；检查点列与液滴 | 被人物/动物替代；机器天线、复杂面板、拟真人脸；状态特效遮眼 |
| Meta Muse / 米白包覆式 | 连续圆润头罩与躯干、内嵌暖色椭圆脸面、简洁眼睛与小表情、短臂双脚 | 细腻哑光布面/短纤维外壳；脸面与头罩内缘有清楚层次 | 无配饰 → 耳机 → 低饱和围巾；不挤压脸面开口 | 旧卷发 Muse/Veda；人物发型、长手脚；头罩与脸面没有厚度关系 |
| 人物 / 原创栗色短发角色 | 大头小身体，眉眼表情，分层发束、细发丝，明确领口袖口 | 皮肤柔和、眼睛有克制高光、头发有方向，织物有细纹与厚度 | 无配饰 → 耳机 → 读书；手掌承托、视线朝书 | 头盔式头发、随机粗刺、全身同材质；完整复刻参考人物的脸发服饰道具 |
| 动物 / 原创柴犬 | 立耳、口鼻、前后爪、卷尾与柴犬比例；身体毛色分区 | 短绒随结构方向，口鼻和脚掌有材质区别，色块边界稳定 | 无配饰 → 蓝色围巾 → 电脑；前爪承托、后爪支撑 | 复用旧粗糙模型当重制；所有动物球体换色；人手、多余肢体；完整复制参考奇幻角色 |

参考及批准语义见 [references/README.md](references/README.md)。尺寸与纤维参数先沿用现有可调范围，以正常页面观感调校，不把任意毛发数量或数值参数当美术合格阈值。扩展物种、发型或 Dots 轮廓必须在本组基准验收后进行。

备选是先批量替换目录缩略图，代价是无法判断实时模型与接触是否成立，且容易再次漏组，因此不采用。

### 2. 五组注册与旧数据兼容分离

沿用现有状态模型与编辑器，不重写框架。实施时使用稳定内部身份，例如 `dots/grok/meta-muse/humans/animals`，显示名固定为五个目标名称。新增独立 Meta Muse 解剖路径与组内材质/组件约束；人物和动物的新基准进入各自新候选目录。界面只做五组可选的必要接入，导航搬迁与新布局留给 `refactor-family-navigation`。

如配置结构需要新版本，采用 schema 10 的显式迁移：保留 dots/grok；旧 muse 映射到 humans 的 legacy 路径，保留旧人物参数；旧 pets 映射到 animals 的 legacy 路径，保留物种。旧预设和旧几何可作为兼容快照存在，但不放入新基准候选或默认新设计入口，不计为已重制。已保存旧配置仍可查看、修改、导出和恢复。

迁移保留原配置、来源与用户配饰意图；动作临时需要的道具仍由 existing resolver 解析，不能反向覆盖用户保存的选择。无法支持的字段给出明确说明并保留原值供恢复，禁止静默落到 Dots 或新 Meta Muse。导入、保存、撤销和再导入共用迁移规则。原有 original/recreation 来源区分继续保留，新参考提炼角色记录实际来源而不自动称为官方或原创版权已核验。

现有随机器仅做身份与组件兼容调整。单只候选指固定基准预设，不禁止用户编辑同一基准的颜色、配饰、姿态，也不禁止既有随机器在已开放参数范围组合这些属性。新组只以本组单只基准及其已验证参数为来源，未验收的新物种、发型、轮廓或其他固定预设不进入随机池；不得将随机结果自动保存成额外重制候选。legacy 配置可继续恢复，不借随机器批量产出重制预设。全屏抽取与组装节奏由 `add-fullscreen-randomizer` 单独规划。

备选是将旧 `muse` 原地改义为 Meta Muse，改动较少但会把用户人物 JSON 变成另一个角色，故不采用。最终内部 ID 属于实施细节，可调整拼写但不能改变迁移语义。

### 3. 先在现有实时渲染器改善结构和表面

`avatar-body.js` 分别构建各组主体和解剖；人物头发继续使用底层、主发束、细发丝的层次结构，重调轮廓与方向；动物先建立柴犬耳口爪尾及色区，后续再扩展其他物种。Meta Muse 新建头罩外层、内缘与脸面，不调用旧人物头发结构。

`surface-fur.js` 与基础材质按分区应用：Dots 主体短绒，Grok 无纤维软胶，Meta Muse 外壳细布面，人物皮肤/头发/衣服分离，动物皮毛/口鼻/掌垫分离。全组任意材质混用不能破坏基准身份；只开放本组已验证材质。纤维密度与阴影先在桌面和手机尺寸看结果，再控制性能。

固定 art/inspiration 更新必须绑定相同基准配置和来源说明；可以用作灵感，不得替代实时模型或作为验收截图。若当前几何无法达到方向，暂停该组扩展，在该组范围内细化几何或可编辑资产方案，并重新提供真实页面候选；不能用「实时模型天然较粗糙」降低标准。大规模更换渲染架构需另行决策。

备选是直接铺生成 PNG，能快速呈现精细图像，却无法验证编辑、视角和配饰接触，因此不采用。

### 4. 接触由身体表面与动作目标共同决定

保留现有锚点和 raycast，扩充为基准形态可用的表面/朝向信息；锚点只定位区域，最终连接必须检查实际网格。头部配饰放在随头部运动的层级，手持道具与持物姿势共享目标点；更换比例和轮廓后重新求接触，不能沿用球体固定偏移。

| 组件 | 实施重点 | 页面否决条件 |
| --- | --- | --- |
| 耳机 | 沿头顶采样连续头梁，左右耳罩由侧面接触点及法线定向；按绒毛/发层留合理厚度 | 头梁断线、耳罩悬浮或穿头、明显不对称、遮掉物种耳朵/脸面 |
| 帽子/头饰 | 接触实际头顶，随所属头部变换，不掩盖身份关键区域 | 漂浮、滑脱、发束穿出不合理位置 |
| 眼镜 | 逐眼朝向/深度，弧面镜桥与镜腿；单片仅对指定眼；透明与深色镜片遮挡语义不同 | 一副平板眼镜悬在弧面前，重复眼睛、断桥/断腿 |
| 围巾 | 包围颈/躯干真实表面，前垂带有厚度与自身遮挡 | 穿体、悬浮、垂带在身体后方或遮住关键口鼻 |
| 电脑/书本等 | 物体目标与手/前爪/翼尖位置统一，视线和姿态协同，临时道具不改保存意图 | 手不接触、道具悬空/穿脸、四足失去后爪支撑、鸟长出人手 |

初次接触矩阵覆盖五只基准开放的头型/比例端点、正面/四分之三/侧面，以及代表动作起始/中段/结束。尚未开放的新轮廓不能被自动判为已支持；未来开放时扩展同一矩阵。程序中的 constraint notes 或 raycast 命中结果只能支持诊断，不能替代逐帧查看。

备选是增加更多固定偏移补丁，能修单个截图但会在形变与侧面失效，因此不用作通用方案。

### 5. 移除地面投影，保留角色体积与部件层次

在 `live-preview.js` 去掉 floor shadow、fade 与脚底 soft contact core 的独立影层；同步处理 `software-renderer.js` 的地面投影与脚底接触暗化。普通背景允许原背景舞台存在，但没有脚底独立投影；透明背景无地面且 alpha 透明。

保留网格表面的明暗、自身遮挡与耳罩、围巾、手和道具相接时的局部层次。不是全局关闭灯光或把模型压成平面。正面与侧面检查两条渲染路径，导出检查实际 alpha 和画面边界。

### 6. Grok 状态与配饰共用实际构图边界

沿用六状态 `idle/thinking/processing/waiting/blocked/done` 和当前暂停时间语义。思考默认点列、处理中默认液滴，保留现有表现形式手动切换，并保证状态仍可辨识；两者都要校准主体、眼睛和特效的比例，不新建真实流体模拟。状态复制形体与粒子以角色位置为中心，构图边界纳入配饰、道具和动效；头部与道具继续保持接触。减少动态时用可辨识静态姿态，不循环移动或形变。

WebGL 与 CPU 共用配置、几何、动作与背景语义；允许光照像素不同，但身份、肢体、接触和透明度一致。PNG 取实际预览暂停帧，不取 art 图片。

### 7. 网页验收采用独立记录，按组解锁扩展

规范见 [character-visual-acceptance](specs/character-visual-acceptance/spec.md)。未来记录使用每组独立文件，包含源码版本/页面 URL、渲染器、可复现 JSON、参考编号、裸形和组合截图、角度/动作结果、320/390/768/桌面视口、实际 PNG/alpha、下载文件和 Prompt 剪贴板回读。文件不能只写 toast 成功或测试通过。

状态顺序：`未实现 → 页面检查中 → 待用户确认 → 该组已验收 → 允许该组扩展`；检查失败退回修正。每组单独确认，某组通过不解锁其余组。OpenSpec tasks 的进度与该状态并行记录。浏览器视口检查不能替代真实手机验收，若未使用实体设备要明确标注。

## Risks / Trade-offs

- [精细纤维增加性能开销] → 先在五只候选和规定视口验证，控制分区密度；性能不佳先优化，不能靠粗糙占位作为成品。
- [原生成图出现额外五官、脚底影或遗漏 Grok] → 文字合同及用户身份参考优先；概念图冲突局部不继承。
- [旧 Muse/Pets 迁移丢失用户角色] → 保留原配置和 legacy 路径，验证旧版 JSON、撤销与往返导入；禁止静默重解释。
- [兼容目录被误认成新美术成果] → 旧数据可恢复，新候选独立标记，默认入口与验收记录区分。
- [单视角贴合但动作穿模] → 表面法线和层级修正后仍执行三视角、比例端点和关键帧检查。
- [CPU 光照不同] → 保持同一结构与状态合同，分别留证，不以 WebGL 成功替 CPU 通过。
- [原站下载/剪贴板历史检查缺证] → 实施验收必须回读实际目标；仍不可回读时记录未执行并保持未通过。

## Migration Plan

1. 用户已明确授权 apply；以 v27/HEAD `eea2a0dd71ba2e3162d11e32fbb1d2be3518e8c3` 为可恢复基线，并保存旧配置样本与来源清单。程序化候选已实现，但当前五组实际页面候选均被用户否决外观，尚未通过网页美术验收。
2. 建立独立身份和 legacy 迁移，再按 Dots、Grok Bot、Meta Muse、人物、动物推进各一只基准及接触修正。
3. 在本机按源码流程安装/构建并运行实际页面；如需要跨设备预览，再使用该原 Site 的可访问候选预览，不先部署生产。
4. 每组完成真实证据并得到该组用户确认后，才提出/实现该组扩展清单；不批量推断通过。
5. 分类导航、全屏随机分别在后续创建 `refactor-family-navigation`、`add-fullscreen-randomizer`，引用本合同，独立评审与实施。
6. 发布需要另行明确指令；届时继续原项目与原网址，先保存候选版本再部署并回读线上。回滚保留 v27 及旧 JSON 备份，通过已保存 Site 版本恢复，不能仅恢复本机文件就宣称线上恢复。

当前已进入 apply；实施版本、页面证据和未完成项另行记录，不发布。
