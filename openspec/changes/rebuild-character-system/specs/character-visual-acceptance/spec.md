# Spec Delta

## Purpose

为五组角色建立真实网页美术验收流程与可追溯证据门槛，使每组先完成一只基准角色的可编辑页面验收并经用户逐组确认，再允许扩展该组角色。

## ADDED Requirements

### Requirement: 五组角色必须各自从一只基准角色开始
Dots、Grok Bot、Meta Muse、人物和动物 MUST 各自建立一只与用户确认的身份、材质和禁止项相符的可编辑基准角色。每只基准角色的检查 MUST 同时包含无配饰状态和按该组设计试配的配饰或道具状态。对每一组，在该组基准未取得真实页面验收和用户对该组的明确确认前，该组在本 change 中的新增或重制候选 MUST 保持单只基准，不得新增该组后续候选；其他已获确认的组可独立解锁扩展。此处候选指新基准或后续新角色的固定预设，不指同一基准的颜色、配饰、姿态编辑。既有 legacy 预设和旧配置 MUST 保留兼容，不计为新候选或新美术验收通过，也不因此要求删除。

#### Scenario: 首次验收单组基准角色
- **WHEN** 某一组首次提交角色进行验收
- **THEN** 页面可编辑地显示该组在本 change 中唯一的基准候选，并分别提供无配饰状态和该组设计所列配饰或道具的试配状态

#### Scenario: 组内角色扩展尚未获确认
- **WHEN** 某组基准角色的验收证据缺失、验收未通过或用户尚未明确确认
- **THEN** 该组扩展状态记录为未通过或待确认，不得新增该组后续重制候选

### Requirement: 美术验收必须检查真实网页中的可编辑渲染
验收 MUST 在可访问的实际站点页面中进行，并查看实际可编辑角色渲染器；独立生成的效果图、固定美术样张、静态缩略图、构建成功或 OpenSpec 任务勾选均不得单独作为网页美术通过证据。每次验收 MUST 记录所查看页面的来源与版本，并保存能辨识角色轮廓、材质、配饰接触和阴影的页面截图。

#### Scenario: 检查真实可编辑预览
- **WHEN** 验收人员打开包含该基准角色的实际站点页面并修改角色或配饰
- **THEN** 角色预览随设置实时变化，截图来自该页面实际渲染的角色，且验收记录包含页面来源、版本、配置和使用的渲染路径

#### Scenario: 仅有生成效果图或构建结果
- **WHEN** 某组只有独立生成图、静态样张、构建通过记录或任务勾选而没有实际页面截图
- **THEN** 该组验收状态保持未执行或未通过，不得记为网页美术验收通过

### Requirement: 页面布局必须覆盖桌面、手机与平板视口
每组基准角色 MUST 在桌面和宽度 320 px、390 px、768 px 的实际页面视口中检查。验收人员 MUST 记录各视口的截图，并检查角色主体、耳朵、尾巴、配饰和道具是否被裁切，以及页面控件和预览是否仍可见、可操作。

#### Scenario: 检查规定的响应式视口
- **WHEN** 验收人员分别以桌面、320 px、390 px 和 768 px 页面视口查看基准角色
- **THEN** 每种视口都有对应页面截图，角色及其必需特征没有非预期裁切，预览和必要操作控件仍可访问

### Requirement: 每组角色必须检查镜头、动作和暂停状态
每组基准角色 MUST 在正面与侧面视角检查；规格包含四分之三视角时也 MUST 检查该视角。带动作的角色 MUST 检查动作起始、中段、结束关键帧及暂停后的实际画面，并确认接触关系在运动过程中保持稳定。

#### Scenario: 检查不同视角下的角色辨识与接触
- **WHEN** 验收人员将基准角色切换到正面和侧面视角，并检查规格要求的其他视角
- **THEN** 角色身份特征、配饰接触、肢体数量及轮廓均可辨识且没有非预期穿透或悬浮

#### Scenario: 检查动作关键帧与暂停
- **WHEN** 验收人员播放基准角色的代表动作并在起始、中段和结束阶段暂停查看
- **THEN** 每个关键帧都保留物种正确的肢体和道具接触，暂停画面与当时的预览状态一致，动作结束后角色恢复稳定姿态

### Requirement: PNG、下载和剪贴板必须通过真实结果回读验收
每组验收 MUST 使用实际页面操作角色 PNG 导出、文件下载和 Prompt 复制。验收人员 MUST 检查实际导出文件的画面和 alpha 透明度、确认文件已真实写入下载目标，并从剪贴板回读复制内容与页面显示的 Prompt 是否相符。成功 toast 或按钮反馈 MUST NOT 单独作为通过依据。

#### Scenario: 检查真实 PNG 和文件下载
- **WHEN** 验收人员从实际页面导出透明背景 PNG 并触发下载
- **THEN** 实际文件已出现在下载目标，打开检查可确认角色画面、透明 alpha、裁切边距与页面预览一致，且没有地板或独立脚底阴影团

#### Scenario: 检查 Prompt 剪贴板内容
- **WHEN** 验收人员从页面复制 Prompt 并回读系统剪贴板
- **THEN** 剪贴板实际内容与页面当前显示的 Prompt 相符；单独出现成功提示但剪贴板未回读或内容不符时不得通过

### Requirement: 验收证据、任务进度和用户确认必须分别记录
每组验收记录 MUST 包含基准配置或可重现配置、页面来源与版本、渲染路径、规定视口截图、视角与动作检查结果、PNG 文件和 alpha 结果、下载回读结果、剪贴板回读结果及明确的用户确认状态。OpenSpec 的任务状态 MUST 与网页验收状态分开记录；未执行项 MUST 明确记为未执行，不得推断为通过。

#### Scenario: 逐组记录通过并等待用户确认
- **WHEN** 一组的全部页面与导出检查均已有证据且检查通过
- **THEN** 该组仅进入待用户确认状态；记录用户对该组的明确确认后，才可将其标为已验收并开始该组扩展

#### Scenario: 验收记录中仍有缺项
- **WHEN** 任一要求的截图、动作结果、真实下载文件、alpha 检查或剪贴板回读缺失
- **THEN** 对应项记为未执行或未通过，该组不得标记为已验收；OpenSpec tasks 的勾选状态不得改变这一结论
