# Spec Delta

## Purpose

规范五组基准角色在配饰、持物、动作和渲染中的可见接触关系，避免配饰悬浮、穿透或脱离角色，并确保真实预览与导出保留相同的角色结构和状态。

## ADDED Requirements

### Requirement: 头戴配饰必须沿实际头部轮廓连续贴合
头戴耳机 MUST 形成跨越头顶的连续头带，并让左右耳罩落在头部两侧；帽子、花饰等头饰 MUST 落在头顶或设计指定的头部表面。配饰 MUST 随头部形状、比例和动作同步移动，不得悬浮、穿过头部或遮住设计要求保持可见的耳朵与五官。

#### Scenario: 耳机适配不同头型
- **WHEN** 用户给不同轮廓的基准角色戴上耳机，并在正面、四分之三和侧面检查
- **THEN** 头带从两侧耳罩之间保持连续可见，耳罩贴住头部侧面，不悬空、不穿透，且不因头型不同出现明显的尺寸或角度错位

#### Scenario: 头饰跟随角色运动
- **WHEN** 角色转头、改变姿势或播放带有头部运动的动作
- **THEN** 头饰持续贴合原来的头部接触区域，不滑脱、不漂移，也不穿过头发或头部

### Requirement: 眼镜和颈饰必须服从面部与颈部接触面
眼镜 MUST 对齐被覆盖眼睛的朝向与深度；双片眼镜逐眼对齐，单片眼镜贴合指定单眼。镜桥、镜腿或单片眼镜连接件 MUST 与面部及头侧形成可见、自然的连接。透明镜片 MUST 保持眼睛可读，深色镜片 MUST 遮住眼睛且不得重复显示镜片外的眼睛。围巾或其他颈饰 MUST 环绕颈部或躯干的真实表面，其垂带 MUST 落在角色身体前方并随角色移动。

#### Scenario: 眼镜顺着弧面佩戴
- **WHEN** 用户为角色试戴透明眼镜、墨镜或单片眼镜，并切换正面与侧面视角
- **THEN** 双片镜片逐眼跟随面部弧度，单片镜片贴合指定单眼，连接件自然接触；透明镜片保留眼睛可见，深色镜片遮住眼睛且不产生重复五官

#### Scenario: 围巾贴合颈部并落在胸前
- **WHEN** 用户给人物或动物基准角色添加围巾，并改变姿势或播放动作
- **THEN** 围巾环贴颈部与躯干接触面，垂带贴近身体前方且保持可见，不切入身体、不悬浮，也不挡住角色识别特征

### Requirement: 手持道具必须由符合物种结构的肢体承托
角色的手、前爪或翼尖 MUST 与动作要求的道具形成可见接触。人物使用手；四足动物使用前爪承托道具并由后爪支撑；鸟类使用翼尖和双脚，不得出现人手或额外前爪。道具 MUST 保持稳定、可辨识并避免穿入脸部或主体。

#### Scenario: 四足动物使用前爪持物
- **WHEN** 四足动物执行工作、阅读、饮用、拍摄、送花或其他需要持物的动作
- **THEN** 前爪在道具的预定接触位置承托或握持，后爪仍支撑身体，且角色没有新增的人手、悬浮道具或明显穿模

#### Scenario: 人物或鸟类执行持物动作
- **WHEN** 人物或鸟类执行需要手持道具的动作
- **THEN** 人物的双手或鸟类翼尖按动作要求接触道具，视线与道具方向协调，身体和道具保持稳定且没有额外肢体

### Requirement: 接触关系必须覆盖基准候选开放的头型、视角和动作
本 change 基准候选向用户开放的所有头型 MUST 在正面、四分之三和侧面视角保持配饰贴合，包括非球形轮廓和带有发型、耳朵或其他头部突起的形态；在角色缩放、转头、摆姿势和播放动作期间，接触点 MUST 继续落在角色表面。更换头型或比例后，旧接触位置 MUST 更新到新表面，不得沿用导致悬浮或穿透的固定位置。

#### Scenario: 检查基准候选开放的所有头型
- **WHEN** 验收人员逐一检查本 change 基准候选开放的头型，包括非球形轮廓、发型和耳部突起，并查看已佩戴配饰
- **THEN** 每种头型均能在正面、四分之三和侧面视角保持接触关系连续、可见且没有明显穿透

#### Scenario: 修改头型和比例后重新检查配饰
- **WHEN** 用户改变角色的头型、头部比例或身体宽度后查看已佩戴配饰
- **THEN** 配饰重新贴合当前角色表面，并在正面、四分之三和侧面视角都保持连续、可见且没有明显穿透

#### Scenario: 动作中持续检查接触
- **WHEN** 角色执行转头、挥手、工作、阅读或睡眠等动作
- **THEN** 贴身配饰随所属身体部位移动，持物道具保持与对应手、爪或翼尖的动作接触；临时动作结束后角色恢复原有配饰关系

### Requirement: 地面表现不得使用脱离角色的脚底椭圆阴影团
角色 MUST 通过自身明暗与遮挡表达体积，并保留配饰与角色表面相接处的局部接触层次。系统 MUST NOT 绘制或合成独立的地面、脚底投影层，包括椭圆与非椭圆阴影团、柔化投影和脚底接触核。透明背景 MUST 保持透明，并移除地面。

#### Scenario: 角色站立或坐落在地面
- **WHEN** 用户在浅色棚拍或纯色背景中查看站立、坐姿或四足角色
- **THEN** 地面没有独立投影层或脚底阴影团，角色自身明暗与配饰接触层次仍然可见

#### Scenario: 导出透明背景
- **WHEN** 用户选择透明背景并导出角色图
- **THEN** 导出背景保持 alpha 透明，不包含地板、棋盘格、白底或与角色脱离的阴影团

### Requirement: Grok Bot 的六种状态动效必须锚定角色且服从减少动态偏好
Grok Bot MUST 保持待机、思考、处理中、等待、受阻和完成六种状态的可辨识表现。思考 MUST 默认使用点列，处理中 MUST 默认使用液滴；用户可切换现有已支持形式，但仍须保留当前状态辨识。这些效果、头部配饰和持物道具 MUST 以当前角色的位置与动作边界为锚点。启用减少动态偏好时，系统 MUST 停止循环位移、缩放和粒子运动，同时保留可辨识的静态状态画面。

#### Scenario: 点列或液滴状态跟随角色
- **WHEN** Grok Bot 进入思考或处理中状态，或切换已支持的表现形式
- **THEN** 默认思考呈现点列、默认处理中呈现液滴；切换形式后仍可辨识当前状态，动效围绕当前角色构图而不脱离舞台边界，已有配饰和持物道具继续贴合角色，动效不得遮住胶囊眼或核心轮廓

#### Scenario: 等待、受阻或完成状态可区分
- **WHEN** Grok Bot 分别进入等待、受阻或完成状态
- **THEN** 每种状态均呈现对应的克制动作或静态姿态，角色配饰和道具仍与身体保持接触

#### Scenario: 用户启用减少动态
- **WHEN** 系统或用户启用了减少动态偏好
- **THEN** Grok Bot 不播放循环粒子、液滴轨迹或连续形变，并以静态画面保留当前状态的可辨识度

### Requirement: 结构诊断中的 WebGL、CPU 渲染和取帧必须保持同一角色状态
既有 WebGL 与 CPU 渲染要求适用于显式“结构诊断”入口中的旧三维路径；两者 MUST 使用相同配置、几何、配饰接触、动作状态、镜头和背景语义。诊断取帧 MUST 捕获用户选择的实际预览状态；允许像素级光照差异，但不得出现角色结构、道具接触、动效状态或透明度语义差异。若未来真实三维角色作为成品交付，该生产渲染路径也 MUST 满足原三维 WebGL/CPU、多视角、动作、接触和取帧合同。整图原样下载及受信任二维组合 Canvas 的输出由 `character-creation-modes` 规范定义，不要求伪装成三维取帧，也不能豁免任何未来真实三维成品要求。

#### Scenario: 在结构诊断中切换 WebGL 与 CPU 渲染
- **WHEN** 相同基准角色和动作分别由结构诊断入口中的 WebGL 与 CPU 渲染
- **THEN** 两种渲染都显示相同的头型、配饰接触、肢体结构、持物关系、镜头取景和背景语义

#### Scenario: 在结构诊断中导出当前暂停帧
- **WHEN** 用户在结构诊断中暂停实际预览并取帧
- **THEN** PNG 呈现同一配置、镜头、动作状态和接触关系；透明背景的 alpha 与所选背景一致，且不把静态美术参考图冒充为实时预览导出
