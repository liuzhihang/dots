## Goals / Non-Goals

**Goals:**

- 将完整事实账本与本轮有效卡清单分开，保持同一结果在选择、预载、跳过、恢复和下载中的身份一致。
- 保留风格事实并在首张真实线索卡停稳时显示轻量身份标签，避免单独大卡与外形卡重复，同时保留各角色身份。
- 用现有原生 DOM、资源登记和共享视图完成同屏揭晓，保留可测试状态和无障碍语义。

**Non-Goals:**

- 不建立可穿戴组件、适配层、图层装配器或自动生成成品；多件配饰也只是展示素材。
- 不增加数据服务、账户、上传/审核、站内对话或素材商城。此前讨论的对话创作后上传、自动管理资源等需求保留为后续独立规划。
- 不改写成品 PNG、历史批准、旧冻结证据；不承诺原型已经证明动画好玩或实体设备通过。

## Decisions

### 1. 八类事实保留，展示清单不含独立风格卡

保留角色风格、外形、五官、配色材质、衣物、头部配饰、身体饰品、随身道具八类事实。角色风格仍供标签、查询和身份说明使用，不派生为独立抽卡卡片。展示清单从其余已核实类别生成并随 DrawResult 深冻结：

- 必显：`appearance`、`palette-material`，都须 known 且具备有效事实。
- 可选：`clothing`、`accessory`、`prop` 仅在分组为 known 且有真实值时入列。
- 任一相关子事实 unknown/缺失仍排除随机资格。例如已知帽子但身体饰品未知，不能认为配饰已齐备。
- `none` / `not-applicable` 只影响展示，不从 Artwork、完整 `revealFeatures` 或锁定来源删除。
- 配饰聚合头部与身体事实；帽子、眼镜、项链共用一个类别，不按物件拆卡。

这比把 `revealFeatures` 直接过滤更安全：后者会丢失详情、无值筛选与锁定依据。展示清单随结果保存，恢复结果时不从实时目录再次计算。它不是对旧项目 JSON/持久化 schema 的兼容承诺；当前没有此类外部接口。

### 2. 在本轮卡片第一次出现前确定卡数

打开弹窗立即显示品牌、标题与中性开场反馈，不等待网络。取得查询和有效选择后，立刻以已冻结的 `displaySlotKeys` 建立本轮卡背/进度并开始动效；随后加载资源。选择尚未完成时的中性反馈不伪装为若干卡槽；本地同步选择通常在首帧内完成。

`renderReadyCards()` 改为接受实际定义，不再写死六卡；`buildSlots()`、`buildRestoredSlots()`、进度、顺序停止和跳过都遍历同一清单。已显示卡数不能随候选、预载完成、缩放或 restore 改变。滚动候选按类别读取自己的来源，只在有真实值且有合格视觉时参与；不能把别人的无值卡插入该轮有值类别。

保留当前后台预载与取消机制；至少同一结果原图及全部有效卡素材就绪后才能停止任何卡。缺资源不删卡或换作品。被省略类别不再要求空值素材和加载请求。

备选“先展示六张骨架再隐藏空卡”会制造卡数跳动；“资源全部就绪才打开弹窗”会退回慢响应，均不采用。

### 3. 身份标签与真实线索资源分开登记

style 继续是 Artwork 的真实事实，但不再请求或绘制独立 reveal visual。首张外形五官卡停稳时，通过轻量文字标记显示 Dots、Grok Bot、Muse、人物或动物身份；该标记不代替任何作品 Feature，也不暴露完整角色。

- 身份名称来自已登记的 artwork family/identity 映射，不从图片视觉或自由文本临时推断；前台短标签可用 Muse，底层稳定身份仍为 Meta Muse。
- 外形五官、配色材质、衣物、配饰和道具线索在表达的类型、外观及组合内容匹配时共享。保留适用 Artwork 关联，不能只凭“耳机”字符串跨所有作品自动复用。
- 默认每个卡槽使用一个已制作的展示 Asset；多件配饰由一张预制的完整配饰展示图表达，避免新增运行时拼图。图库原图始终是完整成品；展示图不是穿戴部件。
- 已生成的中性 style 候选保留其来源和 pending 记录，但不再作为随机卡或必需生产素材。其他候选示意按可见有效卡逐项核对，质量不足才补作对应线索，不批量重画完整角色。
- 缺图或语义不符仍排除该作品的正式随机资格，不能因省略无值卡而放松事实检查。成品在画廊的原批准单独保留；线索 candidate-preview 仅供明确的候选复核，不能因已关联成品变成 published。

当前解析器允许 candidate-preview，因此实施需增加显式资格策略：默认只接受 published 且批准覆盖具体版本/用途的有效线索；仅由本地审阅入口或测试装配显式注入候选策略，普通页面、公开 URL 参数和默认构造均不能开启。构建检查须验证默认生产路径未启用该例外。两至五卡 fixture 覆盖“任一有效视觉缺失/未批准则正式池排除、明确预览可接受完整待审素材”；不能通过少显示一张有值卡获得资格。这是收紧既有资源边界，不引入账户或公众审核系统。

备选新建“通用组件系统”超出本次用途；现有 display-only 登记已经能承载共享线索。来源图片可以作为制作参考，但不自动成为本站公开素材或自有成品。

### 4. 卡面只留下图和类别，事实进入恰当的信息层

抽卡、停卡与结果摘要统一删除可见 `.fr-reel-value`、说明段落及装饰性编号，保留素材与类别名；类别顺序由进度表达，不再给卡片堆字。元数据中的 `shortName`、description 和完整事实可以保留供维护、详情及无障碍使用，不做无关字段删除。

滚动中的候选轨道继续从无障碍树隐藏；首张停稳时读屏可获得类别、该卡事实、身份标签及 n/N 进度。完整角色图、作品名与结果操作在 reveal 前同时从视觉和无障碍树隐藏，不通过 alt、aria-label、title 或 hover 提前泄漏。结果卡不包含完整描述或工程说明；完整描述在详情入口中可访问。

结果显示完整角色与作品名，不显示工程描述或完整简介。主按钮“带走伙伴”展开同一舞台内的操作面板，包含复制 Prompt、下载图片、ChatGPT 与真实 Feature 锁定；次级按钮为“再遇一位”，详情作为轻量入口，完整描述只在详情中显示。

### 5. 在同一舞台内揭晓，保持现有时间边界

顺序：本轮卡片滚动 → 逐项停止 → 首卡停稳后显示身份标签 → 全停约 900ms → 卡片收拢 → 大幅呈现完整原图与作品名 → 用户选择“带走伙伴”后打开内联操作面板。不显示正在装配的身体、不让配件飞入、不使用“随机生成全新角色”文案。

- 普通模式保留现有减速机制，停卡总数改由清单驱动；具体速率先保留，只有动态评审证明过快/过慢才在本 change 内调节，不在提案中凭静图声称已好玩。
- `skip()` 在资源准备阶段记住意图，资源就绪后静态停好本轮全部卡；仍经过 900ms，仍使用同一 DrawResult。
- 减少动态不滚动、翻牌、平滑滚动或移动收拢；资源就绪后静态停卡，等待“揭晓伙伴”点击。
- 重试同一作品保留其清单；主动重抽才新建。恢复结果复用冻结清单；关闭取消请求、timer 和 RAF，旧回调不得写入新轮。

备选独立大图结果幕视觉更宽，但会削弱用户这次指向的同屏连续关系，暂不采用。

### 6. 卡宽按容器收敛，数量不决定卡片巨幅放大

复用随机视图 token。揭晓舞台使用紧凑深色构图，减少与内容无关的留白。桌面卡片保持 5:6，按本轮真实数量居中一排呈现；角色在揭晓后明显放大成为视觉主体。进度连接线由实际首尾位置决定，不预留固定卡数。

320/390 CSS px 使用当前卡约 180px 级别的横向聚焦轨道，露出邻卡；768 CSS px 若容纳不了本轮卡宽则使用同一横向轨道，不压小文字。结果卡变紧凑摘要，手机沿用约 110～120px 级别横轨但仅保留素材和类别名。短高视口允许纵向滚动，不裁完整角色，不强制一屏塞完；关闭和主要操作可触达。

结果布局为：上方线索摘要 → 大幅完整角色 → 作品名 → “带走伙伴”主按钮及内联操作面板；“再遇一位”和轻量详情入口保持次级层级。完整描述只在详情中显示。上方卡片的类别、顺序与实际数保持一致。视口尺寸变化不重新选择 Artwork 或改变 card keys。移动重抽复位 overlay/view 的实际滚动容器及卡轨 scrollLeft，保留关闭/返回后的画廊查询、焦点和滚动。

### 7. 规范冲突显式替换，验收保留未确认状态

本 change 的三个 delta 替换旧 style 卡、固定卡数、空值占位、结果说明层级与原摘要短名称等要求，保留其他主规范。实施时窄改 `AGENTS.md`、`DESIGN.md`、`.agents/rules/design.md`、`README.md`、`design/studio-visual-interaction-system.md` 对应说明。历史合同按本次新增清理授权合并/移除；有依据作用的历史验收证据保持原样。

用户本次 apply 已明确授权合并/移除与当前规划不符的历史 specs/changes，因此本轮直接同步主规范。除应用 delta 外，核对 `fullscreen-randomizer` Purpose 的“六张事实卡”和 `character-families` 示例中的“六卡”是否需作随附措辞更新，清理路径和引用检查见 implementation/spec-cleanup.md，不为旧版建立兼容层。

## Risks / Trade-offs

- [卡数本身透露有无附加元素] → 接受这是线索的一部分；禁止首卡展示完整成品，不承诺完全隐藏所有特征。
- [移除 style 卡后身份标签出现时机] → 只在第一张真实外形五官卡停稳时显示轻量身份名，不提前显示完整作品或名称/描述。
- [通用素材的颜色或样式不匹配] → 保留显式适用关系和逐作品语义核对；需要不同外观时登记独立版本，不靠标签强行套用。
- [当前线索仍有未批准候选] → 记录每个有效卡资源状态；工程可先完成候选预览，正式随机资格与用户艺术批准不混同。不回退到剧透原图保证数量。
- [现有作品卡数不一致] → 维持真实的 2/3/4 卡分布；未来只有真实作品五类均有值时才出现五卡，不为布局测试新增公开组合或素材承诺。
- [同屏纵向结果较高] → 卡片收拢、合理缩放原图、允许容器滚动；验证短高视口、关闭、重抽及主要操作。
- [测试硬编码六和原图预览] → 将相关断言改为独立预期清单及不剧透检查，保留同结果、错误路径和锁定语义的覆盖。

## Migration Plan

1. 后续 apply 先保留当前源码和已批准原图的哈希基线，逐项盘点有效卡线索；开发 DrawResult 展示清单及新视觉解析，再接入同屏 UI 与对应测试。
2. 独立线索候选按实际缺口制作和登记，资源存在、工程核验、页面候选及用户确认分别记录；不以原型像素填生产资源。
3. 运行本 change 的目录/状态/布局/过程/下载检查；新候选证据放实施当日唯一 `design/acceptance/current-<本机日期>-v<cache>/`，本轮使用新的 cache95 目录，不覆盖 cache92 或 v93 历史证据。
4. 在具体候选版本上完成用户视觉确认后，记录其实际范围。未通过的艺术、实体设备或发布项保持未完成，不能通过任务勾选冒充通过。
5. 本轮完成实施和开发期合同清理。发布仍单独授权，保留 Site 身份/权限；如候选不合格，暂不替换现行发布版本。需要回退实施时只恢复本 change 的明确路径和版本，保留新增候选记录，不 reset/clean 或回滚他人文件。

## Apply 中的最新视觉补充（2026-10-08）

用户确认抽卡与分享可以采用不同排版。分享沿用既有横/竖稿与分享文案，不扩展本轮范围。抽卡最新参考以用户再次给出的紫色耳机角色揭晓图及三阶段截图为准：紧凑深色舞台、卡片在上、角色更大、完成后突出“查看详情”/带走操作。角色风格仅保留为底层事实；身份标签随首张外形五官卡停稳出现。实际卡片数量由内容决定，当前 15 件作品为 2 张卡 7 件、3 张卡 7 件、4 张卡 1 件，不固定四张、不补空卡、不截断有值类别。

用户已指出 v93 的实际画面与原型差距较大，因此 v93 的实现和截图只记录上一候选，不得勾为视觉通过。修复工作使用独立 cache95 证据目录；此前发现 Vite 8 会将 `?v=94` 视为强不可变依赖，导致 IAB 普通重载未回源，所以本地服务增加 `Cache-Control: no-store` 并重启 5180，最终候选改用 v95 以避开已缓存模块。工程检查、页面候选、素材 pending 状态和用户艺术确认分别记录。既有分享稿和原图历史字节不改写。
