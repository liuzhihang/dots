# Dot Icon Studio · 静态重构设计与范围锁定

此文件是下一次 OpenSpec Explore 的输入，不是已创建的 change，也不是已完成的实现。配合 CODEX-EXPLORE.md 阅读。

## 1. 这次究竟采用哪两张

**P01-selected-third.png** 对应用户上一轮选中的“第三个”：左上横向黄昏首页、右上手机首页、下方浅色画廊和贝雷帽角色详情。它负责整套 UI 基准、画廊、详情、手机信息层级，以及首页的克制黄昏气质。

**P02-selected-last.png** 对应用户上一轮选中的“最后一个”：上半张宽幅阶梯露台，左边标题、右边向远处升高的宽阶梯，下面是画廊、详情和手机示意。它只负责首页几何构图、横向比例、近中远景和留白；不采用图中的所有导航或功能。

不是两套方案AB测试，不是两张图各做一个场景。首页的布局以P02为先，UI语言/画廊/详情以P01为先。

### 优先级

本次文字范围与纠偏 > 已批准角色身份及原始素材 > 上述页面级参考分工 > 其他历史资料。

所有其他旧拼版、HTML Demo、随机游戏稿、自由组合稿仅可作历史材料，不能成为本轮并列设计依据。

## 2. 本轮产品

发现角色 → 查看共用详情 → 复制Prompt/下载作品 → 在ChatGPT附图创作。

首页、画廊是两个主要页面；详情是共用视图；指南是轻量辅助页面。网页不聊天、不生成图片、不接用户文件、不上传。选择创作要求只生成文本。

### 已排除

数据库、对象存储接入、内容写API、登录、收藏体系、用户空间、投稿审核、上传控件、站内参考图预览、MCP、自动生成发布、随机卡片/老虎机/灵感游戏、自由组装、旧版兼容层。

本次无公共上传，也无“仅本地预览所以不算上传”的隐藏例外。用户在ChatGPT附图是外部流程。维护者通过仓库添加静态文件是本期维护方式。

不提前实现未来数据库Provider。保留可扩展数据字段不等于实现多套存储或兼容旧schema。

## 3. 首页构图

桌面基准1440×900；导航约64 CSS px；主视觉内容约520–580 CSS px。不要用100vh让封面占满屏幕。实际页面必须横向展开，不能套用拼版中某块面板被压缩后的比例。

一个阶梯式共创露台，统一光照与地面。约12–15个角色作为美术构图容量，而不是必须发布的条数。Dots占主体；Grok Bot、Muse、人物、动物都要出现，独立机器人可作为补充。没有相应正式素材时在任务中标缺口，不以原型批准代替每张新图批准。

近景少量角色，主群组位于中景，远景台阶存在更小但可辨认的伙伴。两三处小组、少量独处，保留过道和空阶梯。若采用近:中:远约1:0.75:0.55的尺度起点，仍需按物种与造型调整。

关系示例：共创组围绕一张草图/一台电脑；阅读组共享书本；柴犬与Dots看向同一玩具；一个Grok安静观察。无肢体角色以视线和倾斜表达，不为了办公凭空长手。

去掉泳池、强反光地板、巨大前景杯子、各处标语、满屏飞艇和过多霓虹。保留少量植物/暖灯与低对比城市轮廓。不要将角色罩上一层统一紫色滤镜。

首页不再次追加五张巨大专题卡或多排重复角色。底部只用轻量的Explore Gallery入口与最小页脚。

### 文案与导航的本期基准

- 品牌：Dot Icon Studio，优先使用仓库中既有brand-mark原图；不另造相似Logo。
- 导航：Home / Gallery / Guide；轻量EN/简体中文切换。
- 英文主标题：Small Dots. Big Ideas.
- 一行说明：Pick a character. Create your version in ChatGPT.
- 主操作：Copy Prompt（默认Dots基础创作提示词）。
- 次操作：Explore Gallery。
- 角色提示：Click a character to explore.
- 复制后的反馈提供Open ChatGPT入口并提醒附参考图，不宣称自动附图或发送。

这些是为了纠正原型中不一致的占位文案而给出的文字基准。不要并列再放Make It Your Dot.、A Kinder AI World等多套Hero标题。UI文案代码化并接i18n，不能烘焙在场景图片里。

## 4. 角色身份纠偏

### Dots

简单几何/云朵/水滴/心形等轮廓，短而细的绒感。轮廓先于纹理，避免毛发外扩。以无手脚的基准款为默认；已有获准扩展角色可保留自身结构，但不能在场景生成时随意增加肢体、嘴巴。眼睛、眼镜、帽子和耳机要有自然遮挡和连续结构。

C03只参考短绒、轮廓与配件的感觉，不把它的所有局部形变当作任意加手脚的许可。

### Grok Bot

见C02：光滑软几何、成对胶囊眼；不带机械屏幕脸。白色软圆体黑眼、紫/绿/橙几何白眼可按具体母版使用。机器人保留时独立登记为原创角色，不借Grok分类。

### Muse

见C01：奶油包覆形体、内嵌的暖色脸面、小眼嘴、短圆手脚。不能替换为云状长毛团、发芽白球、熊脸玩偶。低分辨参考用来确认身份，不作为正式下载资产。

### 人物和动物

人物保留分层发束、柔和皮肤、清楚衣物，不把发丝做成毛团。暖橙柴犬保留立耳、口鼻白区、卷尾和四足结构；不要无说明换成长毛垂耳犬。小猫可陪读/休息，不为填画面反复复制同一动物。

## 5. 首页交互合同

视觉是一个场景，内容是可独立定位的角色。角色身份ID贯穿首页、画廊和详情。

静态图必须先可用。Hover/键盘聚焦才短回应，点一下开详情；不自动开Modal、不等待动作完毕、不移动热区使用户点空。触摸直接开详情。

采用环境层、家具遮挡层、独立角色或角色加道具局部动画单元的最小方案。合成底图包含同一角色时须有明确去重策略，不可叠动画后出现两个角色。

没有真实动作帧就只做清楚的UI反馈，不冒充表情动画。背景动作错峰，当前页面不可见、角色离屏、详情打开或用户暂停时停止不必要播放。尊重减少动态，所有关键操作仍可用。

手机为同一场景设计取景/角色位置，不复制桌面画面整体缩小；不能完全丢掉多系列表达。远景主要角色要有可点区域，并可从画廊找到；不要求用户靠拖动大地图使用首页。

## 6. 画廊

P01负责布局与信息层级。统一浅色画布、开放式网格，最多很轻的背景区分，不做每个角色一个小展柜。保留全身/完整轮廓、统一光学尺寸、对齐名称与系列。大图内的衣物/耳朵/尾巴不强裁。

1440px可按5列起步，768px约3列，390px约2列，最终按实际UI宽度验证。默认封面PNG/WebP；仅存在真实动态资源时允许播放。输入是GIF不代表必须原样向所有访客同时播放；解码/体积和播放管理列入Explore评估。

只保留一处搜索和一组系列标签。默认All/精选按静态内容配置，热门统计和收藏不在范围。系列标签可扩展，不硬编码“永远五大家族”。无匹配显示清空筛选。

## 7. 共用详情

用P01的左图右信息布局和移动端堆叠，不采用P02的虚构许可字段或繁多About表格。

桌面站内以浮窗进入，移动端可全屏；直接打开详情URL时可单独呈现。URL方案适配当前静态托管，不依赖新后端。关闭/返回恢复来源、过滤状态、滚动与焦点，按正常页面规则处理未知新路由，不兼容旧工作台链接。

顺序：大图、角色名、短描述、3–4个精选标签、Copy Prompt/Download PNG、Open in ChatGPT、Prompt短预览、实际动作/变体、折叠创作要求、相关作品。规格使用真实元数据。主要操作不埋在长Prompt后。

变体只展示该角色实际存在的资源；不能把不同角色当同一角色动作。常规PNG下载不画成Install Pet；动作预览不等于目标包。首期不因为预留字段而强制制作全量动作包。

“创作我的版本”只改变待复制Prompt，当前参考图不变。明确保留/无/替换，合法选项按风格与角色结构控制。常用维度为颜色/形状/眼睛/眼镜/配件；未知参数不假装拥有效果。当前图库索引和真实资源不能被用户修改意图覆盖。

## 8. 静态模型与素材发布

建议概念：Character（身份）、Artwork/Look（成品）、Asset（原图/缩略图/动画）、ScenePlacement（首页布置）、PromptTemplate（规则+本地化）。这是待Explore结合仓库精简的方向，不强制新增五个代码类或五张表。

内容存仓库内清单与文件。构建前检查资源引用、尺寸/格式与Prompt完整性。页面不写每个角色专用分支。维护者更新内容后仍需静态构建/部署；不宣称本期有远程内容实时发布。

语言/动态偏好可在客户端轻量保存，不缓存用户图片、不迁移旧用户数据。真实原图下载应保持文件内容和alpha，不把UI背景烘焙进去。

## 9. 原型中明确不实施的示例

- Sign in、个人头像/空间、底部Profile、收藏爱心及计数。
- 没有统计来源的Popular；虚构的“100+”“128+”。
- 旧的随机、抽卡、游戏、工作台、上传按钮。
- 场景切换或左下角色选择滑轨作为第二个工作台。
- 机器人代表Grok；白色长毛团代表Muse；带手脚造型无说明替换基准Dots。
- 页面截图裁片充当原始角色素材。
- 同一角色不存在的多状态缩略图、假下载格式、无依据许可。
- 把细小拼版字当准确文案，或复制图中错别字。

## 10. Explore交付与下一步

Explore只读，不创建正式change，不写代码。输出现状、原型差异、资产缺口、两种以内的真实方案及推荐、文件清理表、交互状态表、路由和内容模型、测试映射、阶段任务、活跃change处理建议。

之后经用户确认，才进入现有change的规划更新或新的refactor change。候选名可为 `refactor-dot-studio-static-experience`，只是建议，不在Explore中自动创建。

需要实际页面尺寸稿时列为前置，不要求凭概念拼版宣称像素级完整还原。验收需要独立的1440×900和390×844实页截图、交互过程、320/768边界与真实文件回读；UI、功能、美术身份、素材存在、目标包验证分别记录。
