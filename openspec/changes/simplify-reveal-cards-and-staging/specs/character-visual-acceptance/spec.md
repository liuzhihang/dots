# Spec Delta

## MODIFIED Requirements

### Requirement: 作品资源工程状态、美术批准、目标验证和发布状态必须分别记录
每个 Artwork/Asset MUST 分别记录文件存在与读取、版本/hash/尺寸/alpha、来源资格、使用用途、用户美术批准范围及发布状态。已有目标平台验证记录 SHALL 独立保留；本期静态资源不要求目标平台测试，状态记为不适用，不在 UI 展示。任一状态不得代替另一个状态。目录资格与资源有效性按具体版本检查；场景关联和页面用途不得超出批准，历史批准只覆盖其有证据的范围。

#### Scenario: 资源存在但没有人工批准
- **WHEN** 一张图通过格式和 alpha 检查，但没有绑定的用户美术批准
- **THEN** 工程状态可记为可读取，美术状态仍待确认，该图不得显示为已批准

#### Scenario: 已批准作品缺失资源
- **WHEN** 用户批准记录存在但引用的 Artwork 文件缺失或 hash 不符
- **THEN** 资源状态显示缺失/不匹配，作品不可下载，批准记录原值及范围仍保留

#### Scenario: 已批准角色图用于新首页场景
- **WHEN** 维护者将已批准 Artwork 身份呈现在新的完整静态首页整景图中
- **THEN** 原图批准范围仍限于其记录的 Artwork；整景图、热点对应关系、接触构图和页面呈现另行记录来源、用途及美术状态

### Requirement: 页面和资源验收必须绑定本次实际版本与观察范围
页面验收 MUST 记录实际源码和资源清单、浏览器及版本、实际观察路径与视口。首页、画廊、详情的功能和视觉结果分别记录；Artwork 下载和 Prompt MUST 基于实际下载字节、剪贴板或文件回读。真实浏览器截图 SHALL 覆盖 1440×900、390×844，以及 320px 和 768px CSS 宽度边界。桌面、平板和手机首页都须检查满屏场景适配、实际可见角色、热区和轮廓反馈。概念图、生成图、截图 diff 或构建结果 MUST NOT 自动代表页面视觉通过、用户美术批准或实体设备验证。

#### Scenario: 检查桌面及响应式页面
- **WHEN** 验收者在真实浏览器检查 1440×900、390×844、320px 和 768px CSS 视口中的首页、画廊和详情
- **THEN** 记录浏览器版本、实际页面截图、源码/资源版本及视口；模拟视口明确标为模拟

#### Scenario: 分开记录功能和视觉结果
- **WHEN** 搜索、系列筛选、详情打开/关闭、键盘返回或资源操作通过功能检查
- **THEN** 功能结果与页面层级、身份、密度和美术批准分别记录，功能或构建通过不自动代表视觉或用户艺术通过

#### Scenario: 验证下载 PNG 与 Prompt
- **WHEN** 验收者检查 Artwork 下载和当次 Prompt
- **THEN** 回读下载文件尺寸、内容、alpha、hash，并回读该次剪贴板或文本；未回读的输出保持未验证

### Requirement: 取消范围和历史缺证不得转换为验收通过
被明确取消或失败的历史工作 SHALL 保持原状态，缺失的证据不得补写为通过。当前产品的通过状态仅由当前范围对应的工程证据、素材登记、人工批准或平台验证分别产生。v93 的失败、v95 的 pending，以及历史 34/35 项状态 MUST 保持原记录，不得由本次重构改写。

#### Scenario: 已取消工作不作为当前通过项
- **WHEN** 当前范围不再包含一项历史工作，且其原记录标记为取消、失败或待确认
- **THEN** 保留对应历史状态；不得因当前重构或归档将其勾选为通过

#### Scenario: 新增变体没有确认记录
- **WHEN** 变体文件存在且工程校验通过但没有对应人工确认
- **THEN** 工程检查与用户美术状态分别显示，不能因测试通过标记艺术确认

#### Scenario: 记录新的视觉验收
- **WHEN** 为本次变更创建新的验收记录
- **THEN** 新记录写入唯一的新版本目录并绑定本次源码和资源 hash；v93、v95 及历史 34/35 项的状态和原始记录保持不变，不覆盖旧证据

## ADDED Requirements

### Requirement: 页面视觉验收必须遵循指定原型分工和角色身份
P01 与 P02 SHALL 作为多页拼版逐页映射，MUST NOT 把整张拼版当成单一页面。桌面首页构图以 P02 的宽幅阶梯露台、远近层次与群组留白为准，并采用 P01 克制黄昏光色；背景 SHALL 自适应铺满视口，类别仅作为背景 overlay，不保留 Featured 作品区。手机首页竖幅层级、画廊和详情控件以 P01 对应页面为准；768px 平板 SHALL 作为同一露台的第三种响应式取景核验。角色身份 MUST 对照 C01–C03；原型截图 MUST NOT 被嵌入页面或裁作生产资源。

#### Scenario: 验收单一首页场景
- **WHEN** 验收首页桌面视口
- **THEN** 检查满屏完整静态黄昏露台图内向远处延伸的台阶、前中后景、接触关系和群组留白；原有15件 Artwork 身份及批准范围不变，白色原创机器人和白兔等仅作为新的 pending 本地预览候选；类别只是场景 overlay，无 Featured 区；场景与页面仍待用户艺术批准，不出现第二主题、叠加角色群组或拼版裁片

#### Scenario: 验收手机同一露台的竖幅构图
- **WHEN** 验收 390×844 手机首页
- **THEN** 单行导航下展示自适应手机静态露台构图；不增加身份宣传条或 Featured 作品区。热区只映射该视口实际可见的已批准 Artwork 或已登记 pending 候选，不强塞桌面全部角色或任意裁切桌面图

#### Scenario: 验收平板第三种取景
- **WHEN** 验收 768px CSS 宽度的平板首页
- **THEN** 核对满屏露台按该比例合理取景，角色轮廓不被截断，热区和轮廓路径仍与实际可见角色对齐；不启用不可见角色热点

#### Scenario: 对照角色身份与页面层级
- **WHEN** 验收角色呈现及画廊、详情或移动页面
- **THEN** 核对 Dots 的细密短绒和无肢体基准、Grok Bot 的软几何与成对胶囊眼、Muse 的奶油包覆体与内嵌脸面、柴犬的立耳橙白口鼻和四足卷尾，并保持人物发丝、皮肤和衣料质地区分；页面层级与控件按 P01 对照

### Requirement: 缺少生产资源时必须记录缺口并保持待验收
桌面、平板与手机首页 MUST 有来源、用途、版本及 hash 可追溯的对应完整静态场景构图，并有逐项对应真实可见 Artwork ID / 版本的热点表。场景图、候选身份和页面呈现未获用户批准时 MUST 各自保持 pending；不得用独立透明角色叠层、重复角色或 P01/P02 截图裁片补齐，也不得把工程检查写成美术通过。

#### Scenario: 某个视口场景图或角色映射缺失
- **WHEN** 任一视口整景图、实际角色映射、候选身份批准或对应页面确认尚未完成
- **THEN** 明确记录缺失资源或 pending 范围，不创建不可见角色热点、不叠加临时角色图层，也不把另一视口场景误作已完成

#### Scenario: 已有 15 张原图批准但新场景待确认
- **WHEN** 新整景图引用已有15个 Artwork 身份，且可能包含额外的 pending 预览角色，而场景尚无用户确认
- **THEN** 每张原图既有批准仍只覆盖原文件和已确认范围；桌面 / 平板 / 手机整景、热点、新角色和页面呈现分别保持 pending，不扩大原图批准分母

#### Scenario: hover 或键盘聚焦首页角色
- **WHEN** 用户 hover 或 Tab 聚焦场景中可见角色
- **THEN** 沿该角色真实轮廓显示短暂 UI 描边反馈；reduced-motion 时为静态描边，角色图像本身不移动、变形或复制

## REMOVED Requirements

### Requirement: 特征卡视觉材料必须可追溯且达到展示质量
**Reason**: 当前产品范围已移除随机揭晓卡和结果摘要。
**Migration**: 保留历史线索资产、来源与批准证据；当前页面验收按完整 Artwork、场景资源和新视觉要求执行。

### Requirement: 候选线索只能进入明确的审阅预览
**Reason**: 当前产品移除的是随机揭晓线索候选，不再把线索素材当作角色预览。
**Migration**: 保留旧线索的历史状态及文件；白色原创机器人、白兔等新 Artwork 若有明确身份、资源、事实和 Prompt，则通过独立 `PREVIEW_*` 候选和同一详情结构供本地审阅，仍须单独取得用户艺术批准。
