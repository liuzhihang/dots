# character-contact-and-motion Specification

## Purpose

规范完整角色 Artwork 与透明资源的真实外观和接触关系，区分静态图片、完整变体及真实动画，不把旧组件适配或诊断当作发布能力。

## Requirements

### Requirement: 已发布完整作品必须符合身份和画面中的真实接触关系
每个可浏览或可随机发现的 Artwork SHALL 是独立完整作品。角色肢体数量、物种结构、配饰位置、手持物接触和遮挡 MUST 与该作品实际图像及对应身份一致。Feature 只能描述已看到的结果；不得在运行时添加、移动或适配部件。未制作的角度、动作和配件组合 MUST NOT 标作现有作品变体。

#### Scenario: 登记带有眼镜或头戴设备的成品
- **WHEN** 维护者将有来源和发布资格的完整角色图登记为 Artwork
- **THEN** 实际画面中的眼镜、耳机或帽子与角色接触自然且身份可辨；登记 Feature 不提供对其它角色的适配选项

#### Scenario: 登记人物或动物持物成品
- **WHEN** 完整作品显示人物手、动物爪或鸟翼持有道具
- **THEN** 画面保留正确物种肢体与真实承托关系；未制作的抓握组合不会成为可选输出

### Requirement: 角色 Artwork 和透明导出必须保持真实 alpha
标为透明角色的原图 SHALL 实际包含 alpha 通道并保持真实透明像素。角色下载 MUST NOT 新增页面底色、棋盘格、地面或独立脚底阴影；卡片、首页及弹窗的底色只属于 UI。验证 MUST 回读实际文件，未核验的图片不得显示为已验证的透明导出。

#### Scenario: 下载透明角色作品
- **WHEN** 用户下载标记为透明角色的 Artwork 或其登记的静态变体
- **THEN** 下载文件字节与该资源的发布版本一致，具有真实透明 alpha，且没有 UI 底色或额外地面影子

#### Scenario: UI 使用浅色卡片承载透明图
- **WHEN** 画廊或详情以浅色卡片背景显示角色
- **THEN** 背景仅出现在 UI 表面，实际 Artwork 资源和下载像素仍维持透明

### Requirement: 静态图片不得冒充角色动画或未制作动作
一个完整静态姿态、多个静态姿态和真正可播放的动画 SHALL 作为不同资源能力记录。用户选择某个静态变体时，系统只显示该已制作图像；没有动画文件时 MUST NOT 以 CSS 位移、滚动卡片或 Prompt 文案声称角色已动起来。

#### Scenario: 查看同一角色的静态姿态变体
- **WHEN** 用户选择已登记的挥手或眨眼作品变体
- **THEN** 展示对应完整静态图和绑定 Prompt，不把两张静态图宣称为可播放动画

#### Scenario: 作品没有已制作动画
- **WHEN** 用户查看未登记动画文件的作品
- **THEN** 页面标示静态或 Prompt 能力，动画播放与动画导出不可用
