# studio-creation-experience Specification

## Purpose

明确页面如何将现有角色创作和带走能力组织成无需账号的路径，使用户能编辑形象、使用真实可用的图片模式、复制或导出 Prompt，并在 ChatGPT 中自行附加个人参考图片。

## Requirements

### Requirement: 用户必须可从页面找到真实可用的角色创作路径
系统 SHALL 提供“内置形象”与“创作工作台”两条清楚路径。用户界面 MUST NOT 将 Artwork 与 Composer 呈现为并列的技术模式标签；整图、Canvas 组合及 Prompt 的能力边界仍须以易懂状态说明。工作台 SHALL 让用户从已组装角色开始调整，并允许查看和编辑同一份角色设定。可信完整姿态模板、登记变体及背景只有在实际 Canvas 支持时才能改变 PNG；当前参数超出已登记配方范围时，系统 MUST 保留 Prompt 与项目 JSON 能力、标明不会改变当前画面，且不得虚构渲染结果。整图 SHALL 按固定资产准确标记来源；底层模式、输出与兼容约束遵循 `rebuild-character-system` 既有合同。

#### Scenario: 在没有真实 Canvas 支持的参数上继续创作
- **WHEN** 用户在工作台选择一个未登记为当前角色变体的形状、表情、动作或配饰
- **THEN** 页面保留该设定的 Prompt 和项目 JSON，并说明它不会改变当前 Canvas；不伪装成实时角色预览，也不提供代表该配置的 PNG 导出

#### Scenario: 从内置形象进入工作台
- **WHEN** 用户从画廊选择“用这个形象定制”
- **THEN** 工作台载入该固定完整形象作为初始预览；实际 Canvas 能改变的选项只来自受信任资产清单，其他设定更新 Prompt 但不改变静态角色图

### Requirement: 用户必须能使用 Prompt、项目配置和 ChatGPT 带走创作
创作区 SHALL 提供页面可见的完整 Prompt 查看与复制、Prompt TXT 下载、项目 JSON 导入/导出，以及打开 ChatGPT 的入口。复制、TXT 与 ChatGPT 入口 MUST 使用同一份当前角色状态；ChatGPT 入口仅打开服务并提供 Prompt，不代替用户粘贴、附图或发送。

#### Scenario: 复制当前 Prompt
- **WHEN** 用户查看并复制当前角色的 Prompt
- **THEN** 复制结果与页面显示的完整 Prompt 对应当前冻结角色状态，并可通过页面或系统剪贴板回读核对

#### Scenario: 打开 ChatGPT 并使用自己的图片
- **WHEN** 用户选择在 ChatGPT 中继续创作
- **THEN** 页面打开 ChatGPT 并说明用户需要自行粘贴 Prompt、另附自己的图片并发送；页面不得声称本站已经上传、识别或将图片附加到会话

#### Scenario: 保存并恢复当前角色
- **WHEN** 用户导出再导入当前项目 JSON
- **THEN** 角色设定及创作模式按现有兼容合同恢复，且无需账号或云端用户空间

### Requirement: 创作入口必须区分固定作品、组合输出与 Prompt
系统 SHALL 在角色画面附近说明当前内容属于画廊固定作品、真实 Canvas 组合、Prompt 设定或结构诊断中的哪一种。用户界面不显示 Artwork/Composer 两个技术标签；只有实际成功渲染的当前角色 Canvas 才能作为当前角色 PNG 导出。静态作品原样下载只适用于明确登记的画廊图片。失败、缺资产、未支持设置和结构诊断均 MUST NOT 伪装为当前生成结果。

#### Scenario: 查看候选或历史图片
- **WHEN** 用户看到未验收候选或历史作品
- **THEN** 页面说明其状态、来源和固定属性，不称为当前配置已生成的角色或通过美术验收的基准

#### Scenario: 导出当前组合角色 PNG
- **WHEN** 当前家族有受信任组合包且所选设定完整落在包支持范围内，Canvas 已成功渲染
- **THEN** 页面仅从该当前 Canvas 提供 PNG 预览和导出，并保留准确的作品说明

### Requirement: 五组工作台的 Canvas 输出必须遵守已登记的完整形象和配方
五组工作台 SHALL 以受信任登记的完整姿态形象作为 Canvas 源，在实际 Canvas 中合成当前受支持的形象与背景。每一组的可选形状、耳机、其他配饰、姿态和颜色 MUST 限定为其实际存在的完整形象模板或显式受信任变体；工作台 MUST NOT 以单只静态位图、任意拉伸或通用参数 UI 冒充任意捏形功能。Dots 的裸形/耳机两种互斥配方 SHALL 保持原有范围并通过真实 Canvas 呈现；其他组仅可开放已登记模板确实支持的形象和背景。任何组选项超出真实 Canvas 支持范围时，Prompt 与项目 JSON 仍可用，但该选项 MUST NOT 被描述为当前 PNG 已呈现。所有候选都保持待网页美术验收与用户确认。

#### Scenario: 在 Dots 中切换已登记的裸形和耳机完整配方
- **WHEN** 用户在 Dots 工作台切换耳机开关
- **THEN** 页面通过互斥选择显示裸主体或耳机与主体正确接触的实际正面 Canvas，不能把耳机悬浮/穿入的另一张图叠在基准上充当组合

#### Scenario: 修改真实 Canvas 未登记支持的参数
- **WHEN** 用户在任一家族编辑未登记支持的形状、表情、姿态或配饰
- **THEN** Prompt 保留该设定，页面说明该控制只影响 Prompt，不改变 Canvas 当前输出

#### Scenario: 更换背景并导出当前 Canvas
- **WHEN** 用户从当前家族已登记的背景选项中选择背景
- **THEN** 页面在真实 Canvas 中将该背景与当前完整姿态形象合成；下载 PNG 与画布回读一致，并且背景与角色资产状态不会被标为美术已验收

### Requirement: 五组基准必须有真实的表情姿态变体
工作台 SHALL 为五组 canonical 基准各提供一套经登记的完整表情/姿态 PNG 变体，并通过既有角色字段原子选择。变体 MUST 以真实图片的眼形、表情、姿势和动作登记，Canvas、Prompt、项目 JSON 和 PNG 导出保持一致；不可将只更新 Prompt、CSS 位移或未加载素材称为已改变角色动作。所有变体保持候选待用户美术确认，既有 15 个图库身份不增加。

#### Scenario: 切换已登记的表情姿态
- **WHEN** 用户选择某基准的可用表情/姿态
- **THEN** 页面绘制该完整透明 PNG 与背景，更新同一角色配置与 Prompt，仅最新成功 Canvas 可以导出

#### Scenario: 重新导入含表情姿态的项目
- **WHEN** 用户保存再导入项目
- **THEN** schema 10 与文档 v1 保持，完整变体按可信字段恢复，未登记参数继续保留原值并明确不支持，不接收任意图片 URL
