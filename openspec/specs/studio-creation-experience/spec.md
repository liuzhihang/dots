# studio-creation-experience Specification

## Purpose

明确页面如何将现有角色创作和带走能力组织成无需账号的路径，使用户能编辑形象、使用真实可用的图片模式、复制或导出 Prompt，并在 ChatGPT 中自行附加个人参考图片。

## Requirements

### Requirement: 用户必须可从页面找到真实可用的角色创作路径
系统 SHALL 提供“内置形象”与“创作工作台”两条清楚路径。用户界面 MUST NOT 将 Artwork 与 Composer 呈现为并列的技术模式标签；整图、Canvas 组合及 Prompt 的能力边界仍须以易懂状态说明。工作台 SHALL 让用户从已组装角色开始调整，并允许查看和编辑同一份 VERSION 10 角色设定。当前 15 个已登记完整模板及明确登记的姿态/模块变体只有在实际 Canvas 支持时才能改变 PNG；角色背景不是可编辑能力，角色 Prompt、Canvas、渲染计划和 PNG MUST 忽略背景元数据并保持透明。当前参数超出已登记配方范围时，系统 MUST 保留 Prompt 和包装 v2 项目保存能力，将无真实 Canvas 输出的 `creation.composition` 设为 null，标明不改变当前画面且不得虚构渲染结果。新建角色 SHALL 默认使用透明背景。现行 v2 / VERSION 10 中合法的历史背景元数据 SHALL 严格读取并保留以维持项目引用完整性，但不能改变 Prompt 或图像。整图 SHALL 按固定资产准确标记来源；项目读写仅采用包装 v2 与角色 VERSION 10，旧格式提示 unsupported 且不自动迁移。

#### Scenario: 在没有真实 Canvas 支持的参数上继续创作
- **WHEN** 用户在工作台选择一个未登记为当前角色变体的形状、表情、动作或配饰
- **THEN** 页面保留该设定的 Prompt 和 v2 项目配置，并说明它不会改变当前 Canvas；不伪装成实时角色预览，也不提供代表该配置的 PNG 导出

#### Scenario: 从内置形象进入工作台
- **WHEN** 用户从画廊选择“用这个形象定制”
- **THEN** 工作台载入该固定完整形象作为初始预览；实际 Canvas 能改变的选项只来自受信任资产清单，其他设定更新 Prompt 但不改变静态角色图

### Requirement: 用户必须能使用 Prompt、项目配置和 ChatGPT 带走创作
创作区 SHALL 提供页面可见的完整 Prompt 查看与复制、Prompt TXT 下载、项目 JSON 导入/导出，以及打开 ChatGPT 的入口。复制、TXT 与 ChatGPT 入口 MUST 使用同一份当前角色状态；ChatGPT 入口仅打开服务并提供 Prompt，不代替用户粘贴、附图或发送。所有新项目 JSON 保存与导出 SHALL 使用包装 version 2 和角色 VERSION 10；旧包装、裸角色 JSON、旧 schema 与旧恢复别名明确提示 unsupported，不自动迁移或覆盖旧内容。当前会话草稿 MUST 可按 v2 导出并在重新导入 v2 后恢复。

#### Scenario: 复制当前 Prompt
- **WHEN** 用户查看并复制当前角色的 Prompt
- **THEN** 复制结果与页面显示的完整 Prompt 对应当前冻结角色状态，并可通过页面或系统剪贴板回读核对

#### Scenario: 打开 ChatGPT 并使用自己的图片
- **WHEN** 用户选择在 ChatGPT 中继续创作
- **THEN** 页面打开 ChatGPT 并说明用户需要自行粘贴 Prompt、另附自己的图片并发送；页面不得声称本站已经上传、识别或将图片附加到会话

#### Scenario: 保存并恢复当前角色
- **WHEN** 用户导出再导入当前项目 JSON
- **THEN** 角色设定及创作模式按包装 v2 恢复，且无需账号或云端用户空间；旧项目格式显示 unsupported，不自动迁移

### Requirement: 创作入口必须区分固定作品、组合输出与 Prompt
系统 SHALL 在角色画面附近说明当前内容属于画廊固定作品、真实 Canvas 组合、Prompt 设定或结构诊断中的哪一种。用户界面不显示 Artwork/Composer 两个技术标签；只有实际成功渲染的当前角色 Canvas 才能作为当前角色 PNG 导出。静态作品原样下载只适用于明确登记的画廊图片。失败、缺资产、未支持设置和结构诊断均 MUST NOT 伪装为当前生成结果。

#### Scenario: 查看候选或历史图片
- **WHEN** 用户看到未验收候选或历史作品
- **THEN** 页面说明其状态、来源和固定属性，不称为当前配置已生成的角色或通过美术验收的基准

#### Scenario: 导出当前组合角色 PNG
- **WHEN** 当前家族有受信任组合包且所选设定完整落在包支持范围内，Canvas 已成功渲染
- **THEN** 页面仅从该当前 Canvas 提供 PNG 预览和导出，并保留准确的作品说明

### Requirement: 五组工作台的 Canvas 输出必须遵守已登记的完整形象和配方
当前五组工作台 SHALL 继续以受信任登记的完整姿态形象作为 Canvas 源，并在透明 Canvas 中合成当前受支持的形象；背景字段不再是完整形象或组合包的渲染输入。该清单是现有内容，不构成未来内容分类或基底数量的上限。当前模板的可选形状、耳机、其他配饰、姿态和颜色 MUST 限定为其实际存在的完整形象模板或显式受信任变体；工作台 MUST NOT 以单张静态位图、任意拉伸或通用参数 UI 冒充任意捏形功能。Dots 的裸形/耳机两种互斥配方 SHALL 保持原有范围并通过真实 Canvas 呈现；其他现有模板仅可开放已登记模板确实支持的形象状态。所有新建当前输出 MUST 使用透明背景；旧 v2/VERSION 10 项目中的合法背景值按惰性元数据保留，不作为可编辑项，不改变 Prompt、Canvas 或解析出的 render plan。

新增模块工作 SHALL 只开放登记在本地可信素材目录、并由共享解算器证明可渲染的模块配方。组件是否可用 MUST 取决于明确声明的基底/布局、视角、姿态、槽位、依赖、遮挡、抓握和染色能力，不得由家族或浏览标签推断。任何当前模板或模块选项超出真实 Canvas 支持范围时，Prompt 与当前 v2 项目状态仍可用，但该选项 MUST NOT 被描述为当前 PNG 已呈现。旧格式输入提示 unsupported，不自动迁移或覆盖原数据。美术验收状态 SHALL 按具体素材、基底/姿态适配、页面版本和用户明确确认单独记录；尚未确认的适配保持待确认，已明确确认的当前版本不得在验收记录中继续列为未确认。冻结发布版本中的候选标签只描述发布时的状态，后续确认以关联该版本的记录为准，不要求为追记确认重新发布。

#### Scenario: 在 Dots 中切换已登记的裸形和耳机完整配方
- **WHEN** 用户在 Dots 工作台切换耳机开关
- **THEN** 页面通过互斥选择显示裸主体或耳机与主体正确接触的实际透明正面 Canvas，不能把耳机悬浮/穿入的另一张图叠在基准上充当组合

#### Scenario: 修改真实 Canvas 未登记支持的参数
- **WHEN** 用户在任一现有模板编辑未登记支持的形状、表情、姿态或配饰
- **THEN** Prompt 保留该设定，页面说明该控制只影响 Prompt，不改变 Canvas 当前输出

#### Scenario: 更换背景并导出当前 Canvas
- **WHEN** 用户在工作台查看当前模板并导出已登记完整形象或姿态的 Canvas PNG
- **THEN** 工作台不提供角色背景编辑项；PNG 使用实际 Canvas、保留角色真实 alpha，文件与回读的透明画布一致，背景不能通过配置值或导出选项重新填充

#### Scenario: 组合已登记的独立组件
- **WHEN** 用户在模块工作台选择一个基底支持且满足姿态、槽位、接触和遮挡规则的组件配方
- **THEN** 画面由共享解算生成的实际透明 Canvas 呈现完整组件组合，Prompt、项目引用与 PNG 输出对应相同的组件 ID、版本和配方

#### Scenario: 当前基底没有组件适配
- **WHEN** 用户尝试为一个没有明确声明该组件适配的基底选择该组件
- **THEN** 组件不可作为当前可渲染选项，角色结构不因配饰而新增不支持的肢体或部件，系统说明缺少适配

#### Scenario: 保持现有 Grok Bot 与 Meta Muse 模板
- **WHEN** 模块目录或工作台能力新增后，用户浏览或编辑现有 Grok Bot 或 Meta Muse 基准/完整模板
- **THEN** 原身份、素材与受支持状态仍可使用，不被模块占位图、另一组基底或 Prompt-only 图片替换，输出使用透明 Canvas

#### Scenario: 查看未批准的新模块适配
- **WHEN** 新组件的某个基底/姿态适配已工程可渲染但没有对应版本的用户美术批准
- **THEN** 该适配明确显示待确认，不进入精选或默认随机结果，且不把工程可用状态描述为用户美术通过

### Requirement: 五组基准必须有真实的表情姿态变体
工作台 SHALL 为当前五个 canonical 基准各提供一套经登记的完整表情/姿态 PNG 变体，并通过既有角色字段原子选择。变体 MUST 以真实图片的眼形、表情、姿势和动作登记，Canvas、Prompt、包装 v2 项目和 PNG 导出保持一致；不可将只更新 Prompt、CSS 位移或未加载素材称为已改变角色动作。尚未明确确认的变体 SHALL 保持候选待用户美术确认；已确认状态必须绑定实际呈现的素材、页面版本及确认范围，不能扩展到未制作或未呈现的状态。冻结发布版本中的旧候选标签不代替后续确认记录，当前 15 个图库身份不因此增加。所有姿态 Canvas 和 PNG 均 SHALL 保持透明，角色背景元数据不改变画面。

#### Scenario: 切换已登记的表情姿态
- **WHEN** 用户选择某基准的可用表情/姿态
- **THEN** 页面绘制该完整透明 PNG 并保持其真实 alpha，更新同一角色配置与 Prompt，仅最新成功 Canvas 可以导出

#### Scenario: 重新导入含表情姿态的项目
- **WHEN** 用户保存再导入含表情/姿态的项目
- **THEN** 包装 v2 与角色 VERSION 10 保持，完整变体按可信素材 ID/版本/哈希/配方恢复，未登记参数不伪装成已渲染状态，且不接收任意图片 URL
