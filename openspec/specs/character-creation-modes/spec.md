# character-creation-modes Specification

## Purpose

定义整图＋Prompt 与受本地分层资产包约束的组合模式如何共用角色设定，规定项目文档兼容、真实图片输出和结构诊断边界。

## Requirements

### Requirement: 整图与组合模式必须共用同一份角色设定
系统 SHALL 为每个角色提供 `artwork` 与 `composer` 两种创作模式，两种模式 SHALL 编辑同一份现有 VERSION 10 角色配置，并共用分组身份、颜色、表情、姿态、配饰、背景、来源和禁止项。整图参数变化 SHALL 更新当前设定的 Prompt；除非真实生成或合成了新图，静态整图 SHALL 保持原样并明确标记为示例，不能声称代表当前配置。

#### Scenario: 在整图模式中更改角色设定
- **WHEN** 用户在整图模式切换颜色、表情、姿态或配饰
- **THEN** 当前角色设定和 Prompt 更新，静态整图保持原文件并标明不随设定变化

#### Scenario: 两种模式使用同一角色设定
- **WHEN** 用户从整图切到组合，或从组合切回整图
- **THEN** 角色配置与 Prompt 语义保持一致；模式切换不重置角色、配饰意图、参考文字或输出设置

### Requirement: 项目 JSON 必须包装模式状态且保持现有角色 schema
新项目 SHALL 使用 `{format:"dot-studio-project", version:1, character, creation:{mode:"artwork"|"composer", artworkId:<trusted id|null>}}` 文档格式；其中 `character` SHALL 保留现有 VERSION 10 结构。创作模式包装层 MUST NOT 升级、改变或迁移现有角色 schema。系统 MUST 继续导入既有纯角色 JSON，并在项目保存、自动保存、撤销、重做和导入中保留模式与当前作品状态。项目图片输出 SHALL 仅由清单 ID 选择，不能由内嵌位图、任意本机路径或任意 URL 指定。角色文字及旧配置恢复副本可保留原始内容，但 MUST NOT 将其解释成可执行素材路径。

#### Scenario: 保存并重新导入项目
- **WHEN** 用户将任一模式下的角色导出为项目 JSON，之后重新导入
- **THEN** 原有角色字段、模式与受信任作品 ID 保持一致，VERSION 10 角色配置未被改写

#### Scenario: 撤销模式或作品选择
- **WHEN** 用户切换模式或受信任的整图作品后执行撤销和重做
- **THEN** 模式、作品 ID 与同一份角色设定按操作历史一起恢复

#### Scenario: 导入未知或不匹配的作品 ID
- **WHEN** 项目包含未知的 `artworkId` 或与角色组不匹配的 ID
- **THEN** 系统拒绝该导入并明确报错，保留此前有效项目；不回退到其他角色组的图片，也不解析 JSON 提供的 URL/路径

### Requirement: 整图模式只展示并原样下载本地登记的完整作品
整图模式 SHALL 只允许从站点本地登记的作品清单选择固定完整图；记录 SHALL 包含稳定 ID、所属角色组、作品名、素材来源说明和历史/原创/官方身份状态。整图导出 SHALL 下载所选文件的原始字节，不按当前参数重新裁切、重绘或合成。没有已登记作品的角色组 SHALL 如实显示无整图。历史样张 MUST NOT 被称为官方资产、当前参数生成结果、新基准角色或网页美术验收通过。

#### Scenario: 下载历史整图示例
- **WHEN** 用户选择一张登记为历史示例的整图并下载
- **THEN** 页面清楚标示所属组及历史示例状态，下载文件与本地来源文件字节一致，Prompt 则根据当前角色配置生成

#### Scenario: 切换到没有整图的角色组
- **WHEN** 用户为没有登记完整图的角色组选择整图模式
- **THEN** 页面显示该组没有可用整图，仍可编辑设定和复制 Prompt，不能显示别组作品作为替代

### Requirement: 组合模式必须由可信分层图真实合成当前输出
组合模式 SHALL 只读取应用随站点发布并在受信任清单登记的 `layered-2d` 资产包。每个包 MUST 绑定角色组、来源和版本，声明其固定视角、可支持配置值、图层次序、遮挡/接触关系与输出边界。影响主体、轮廓、表情结构或配饰结构的非颜色/背景字段 MUST 由完整配方声明：`pack.variants` 是 `{id, values, layerIds}` 数组；`values` MUST 绑定所有非颜色/背景可编辑字段，配方间不得有重复的 `values` 绑定，并且 MUST 恰有一个基准配方。合成时 MUST 只绘制当前匹配配方所列的 `layerIds`，不得自动附带基础图层或上一配方图层。颜色能力 MUST 通过当前匹配配方实际选中的每个图层的 `tintPath` 验证。若包没有 `variants`，只可对固定图层进行已声明的染色和背景更换，不能开放结构字段。所有非颜色/背景的图层集合或结构差异 MUST 由完整配方明确声明。当前实现 MUST 拒绝包含任一 `layer.when` 的资产包，不支持条件层显隐。`editablePaths` 声明 `camera`、`aspect`、`output`、`motionStyle` 或 `motionSpeed` 中任一项时，系统 MUST 拒绝注册该包。系统 MUST 对真实图层执行合成，并且只在完整 Canvas 已成功渲染且当前配置完全落在包声明能力内时，显示或导出当前角色 PNG。图层资产目前没有声明视角、参数、动作或接触能力时，界面 MUST NOT 暴露这些能力。MUST NOT 通过任意变形整图或使用诊断渲染器冒充该 Canvas。

#### Scenario: 使用当前配置成功合成
- **WHEN** 当前角色组有受信任分层包，且用户选取包明确支持的参数
- **THEN** 页面将声明的图层实际合成为当前 Canvas，并从该 Canvas 显示和导出当前 PNG

#### Scenario: 缺少组合包或参数不受支持
- **WHEN** 当前角色组没有受信任分层包，或当前配置超出其支持范围
- **THEN** 页面不显示或导出新的当前角色图，不把历史整图或三维诊断图当成合成结果；角色设定、Prompt、项目 JSON 仍可用，并说明缺少支持资产或参数

#### Scenario: 只支持固定正面视角
- **WHEN** 分层包声明仅支持 front 视角
- **THEN** 组合结果仅提供该视角，不显示侧面/四分之三自由旋转或未经制作的动作；共享 Prompt 设定仍可表达其他视角或动作，但须说明该设定不能合成并禁用组合 PNG

#### Scenario: 整体轮廓由配方替换而非叠加
- **WHEN** 某包尝试用 `layer.when` 在球形主体上追加一张心形图层来表示主体变成心形
- **THEN** 含 `layer.when` 的包被拒绝；要支持心形主体，包须由唯一匹配配方的 `values` 明确绑定心形结构，并且其 `layerIds` 仅绘制该心形主体及其配套部件、不遗留球形主体

#### Scenario: 无变体的固定图层只开放染色和背景
- **WHEN** 某包没有 `variants`，或当前颜色字段不在选中图层的 `tintPath` 中
- **THEN** 无变体包不得把结构选项标示为可合成能力；当前配方不能对不支持的颜色宣称可合成，仍可编辑共享 Prompt 设定，但不得生成超出包能力的当前 PNG

#### Scenario: 拒绝不支持的输出或运动路径
- **WHEN** 某包在 `editablePaths` 中声明 `camera`、`aspect`、`output`、`motionStyle` 或 `motionSpeed`
- **THEN** 系统拒绝该包的合成与导出，不把这些参数标示为组合支持能力；共享 Prompt 设定仍可编辑

### Requirement: 每个文本或图像导出动作必须绑定同一冻结状态
系统 SHALL 在复制 Prompt、下载 Prompt、打开 ChatGPT 或启动 PNG 导出时使用同一份冻结的角色配置与创作模式快照。异步导出过程中若角色组、模式、作品或配置发生变化，过期结果 MUST NOT 以当前角色名或“当前结果”下载；系统 SHALL 取消导出或清楚提示结果对应旧快照。剪贴板文本 SHALL 与页面展示的该次 Prompt 一致。

结构诊断的 PNG SHALL 捕获点击时已经绘制的动作和组装状态；未准备好、尚有配置更新未绘制或已关闭的预览 MUST NOT 开始导出。异步绘制或编码期间更新、关闭预览时，旧 PNG MUST 被取消，不能恢复已关闭预览。

#### Scenario: PNG 渲染期间切换模式
- **WHEN** Canvas 或其他允许的异步渲染仍在进行，用户切换模式、作品或角色
- **THEN** 旧异步结果不覆盖当前页面，也不会以新角色配置名义被导出

#### Scenario: CPU 预览仍有下一帧在处理
- **WHEN** 用户从已经准备好的 CPU 诊断预览导出，下一动作帧尚未绘制
- **THEN** PNG 使用点击时最后实际绘制的动作时间及组装状态，不使用继续增长的请求时间或默认静止帧

#### Scenario: 导出途中关闭或更新预览
- **WHEN** PNG 正在等待图层解码、诊断绘制或图片编码，角色配置更新或预览被关闭
- **THEN** 旧结果被拒绝，不分配后续过期绘制资源、不下载旧 PNG，也不以当前角色名导出；之后有效的新导出仍可执行

#### Scenario: 复制和下载同一 Prompt
- **WHEN** 用户从页面复制 Prompt、下载 TXT 或打开 ChatGPT
- **THEN** 三种操作均使用同一配置快照；剪贴板回读内容与该次页面 Prompt 完全一致

### Requirement: 结构诊断不得冒充整图或组合成品
现有程序化 3D/WebGL/CPU 渲染器 SHALL 保留在名称明确的“结构诊断”入口，延续本 change 原有三维路径的视角、动作和 CPU 诊断要求。诊断画面 SHALL 与整图示例和组合 Canvas 有明显不同的标记。结构诊断截图、实际 PNG、程序检查通过或 OpenSpec 任务完成 MUST NOT 被记录为角色艺术验收通过，也 MUST NOT 解锁该组扩展。若后续将真实 3D 角色作为产品成品交付，仍 MUST 满足本 change 原有 WebGL 与 CPU、多个视角、比例端点、动作、配饰接触及实际导出合同；不能以该诊断入口或本地 2D 固定视角能力豁免这些条件。无论成品是整图还是组合，角色身份、材质与配饰接触均 MUST 通过真实页面美术检查及该组用户确认。

#### Scenario: 查看三维结构诊断
- **WHEN** 用户显式打开结构诊断并检查旧实时渲染器
- **THEN** 页面说明其用途是几何/接触/动作诊断，且不把渲染结果归入整图下载或组合成品

#### Scenario: 记录某组艺术验收
- **WHEN** 一组仍只有历史整图、空组合包或结构诊断证据
- **THEN** 该组美术验收维持未通过，原有真实页面检查和用户逐组确认门槛不变

#### Scenario: 后续交付真实 3D 成品
- **WHEN** 某组把完整三维角色作为实际可编辑成品提交验收
- **THEN** 除真实身份、材质和接触关系外，还须通过原 WebGL/CPU、多视角、比例、动作和导出要求，并由用户明确确认该组

### Requirement: 创建能力不得要求账号、上传或自动代发
两种模式 SHALL 无需登录、注册或用户空间；图像与项目 JSON MUST 不作为图片上传或生成服务输入。打开 ChatGPT 时 SHALL 只提供用户当前 Prompt 并打开 ChatGPT，用户自行粘贴、另附图片并发送。系统 MUST NOT 自动上传图片、自动附图或替用户发送消息。

#### Scenario: 使用自己的图片生成
- **WHEN** 用户希望以自己的图片为参考
- **THEN** 页面说明用户应在 ChatGPT 中自行附加图片；本站的 Prompt 与项目 JSON 不携带该图片

### Requirement: 用户界面必须区分内置形象画廊和创作工作台
面向用户的主入口 SHALL 是两个目的明确的页面：“内置形象”用于浏览五组各三只的已组装固定作品；“创作工作台”用于基于所选形象调整实际受支持的参数。用户界面 MUST NOT 将 Artwork 与 Composer 呈现为并列的模式页签或要求用户先懂这两个内部概念。底层 `creation.mode`、可信 `artworkId`、Prompt 和导出规则 MUST 保持兼容，不升级 VERSION 10 角色 schema 或项目 JSON v1 包装层。画廊进入工作台时 SHALL 带入所选角色及对应作品 ID；工作台只能将真实 Canvas 支持的完整姿态模板、受信任变体及背景显示为可影响 PNG 的选项。未登记的姿态、肢体、五官、配饰或颜色设定 MAY 保留在 Prompt 和项目 JSON 中，但 MUST 明示不会改变当前 Canvas。

#### Scenario: 在内置形象和工作台间切换
- **WHEN** 用户从任一画廊形象选择“用这个形象定制”
- **THEN** 工作台载入相同家族、项目设定和可信 artworkId；页面展示的是同一已组装形象，不将技术模式切换误作另一只角色

#### Scenario: 找不到支持当前参数的真实 Canvas 配方
- **WHEN** 用户在工作台选择的配置不匹配任何完整姿态模板或受信任配方
- **THEN** 当前 PNG 不能宣称已包含该配置；Prompt/JSON 可继续使用，界面说明该项尚不改变画面
