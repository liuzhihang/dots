# character-visual-acceptance Specification

## Purpose

规范五组当前PNG模板在真实图库与工作台中的美术确认和工程证据记录，按实际支持的固定视角、姿态与合成参数判断能力，并保留历史失败、缺证和未来扩展的独立验收边界。

## Requirements

### Requirement: 模板能力检查与人工美术确认必须分开
画廊原图、工作台 Canvas、Prompt、组合覆盖图鉴与旧结构诊断 SHALL 分别记录能力和证据。模板与新增组合素材的美术 MUST 在真实页面检查身份、材质与配饰接触并由用户确认；逻辑测试、构建、图鉴、图像差异或诊断矩阵不能代替该确认。用户美术确认 MUST 绑定实际冻结版本及可核定的 look/状态/素材映射，MUST NOT 自动证明全量 PNG 字节、剪贴板、实体手机或旧三维成品工程通过。Site version 35/cache 83 的确认记录明确列出15个 look 和“PNG模板、背景合成、Prompt”范围；其 `supportedStateBoundary` 表述为当时工作台提供的登记状态，但没有逐姿态 PNG 的素材映射。该记录对具体姿态文件的覆盖 SHALL 标记为“确认范围待核定”，MUST NOT 自动断言已逐图批准或被用户否决。

#### Scenario: 模板美术获得用户确认
- **WHEN** 用户明确确认具体页面版本中的已登记形象和范围
- **THEN** 只将该版本、清单内身份及明确范围记为已确认，工程输出或设备未检查项保持其实际状态

#### Scenario: 缺少支持当前配置的素材
- **WHEN** 配置没有可信模板或完整配方
- **THEN** Prompt/JSON可用，但当前PNG不允许导出；诊断图不能补足素材缺失

#### Scenario: 用户确认记录未逐项映射到姿态文件
- **WHEN** 历史确认记录列出15个Gallery look，并以“当前工作台所提供的登记状态”描述状态范围，但没有姿态 PNG 的逐文件映射
- **THEN** 15个已列 look 保留记录范围内的确认，姿态文件的用户确认显示“确认范围待核定”，不得自动标成已批准或用户否决

### Requirement: 五组保留canonical基准且新增身份须独立验收
每组 SHALL 保留一只canonical基准；当前图库包含各组三项、共15个身份。该数量不是永久人数上限。新增身份 MUST 明确登记并按对应实际页面版本验收和确认；旧legacy配置、场景群像和历史素材不自动成为新图库身份，当前15项确认不授权批量新增。

#### Scenario: 浏览当前已登记形象
- **WHEN** 用户查看五组当前图库和工作台
- **THEN** 基准与同组登记变体保持明确身份，美术确认记录绑定实际版本和look清单；冻结页面中的旧候选标签可保留为该发布时状态，后续确认单独追加

#### Scenario: 增加新的图库身份
- **WHEN** 后续计划新增角色、物种、发型或轮廓
- **THEN** 另行明确设计范围、登记素材并提交真实页面确认，不能由当前五组确认推断新素材已通过

### Requirement: 美术验收必须检查真实页面和实际受支持合成
验收 MUST 在可访问的真实图库、工作台和首页中查看实际模板、已登记组合素材及 Canvas，并检查角色真实透明 alpha。背景字段不是受支持的合成能力；不得要求用户选择背景来证明输出，实际预览、模块组合和 PNG 只按透明结果检查。组合图鉴、独立生成图、缩略图、构建成功与任务勾选不得单独作为网页美术证据。独立组合素材 MUST 按其声明的基底、姿态和接触关系检查；未支持的自由视角、比例、配饰或材质 SHALL 只进入 Prompt，并明确不改变当前 PNG。首页现有搜索、`homeFamilies` 五组场景、布局、群像、卡片、导航和文案 MUST 保持现有设计；首页家族插画与页面底色不随角色输出透明化而改变。标签浏览控件只出现在图库和工作台，现有首页卡片可通过内部路由携带图库标签筛选条件而不改变首页呈现。项目菜单 MUST 移除旧角色 JSON 导出项 `save-character` 并保留统一 v2 项目导出、菜单容器和其他功能。浏览器回归 MUST 核对首页视觉及现有全局随机入口可用；移除背景功能入口和旧导出项记录为预期功能差异。

#### Scenario: 检查真实工作台
- **WHEN** 验收人员查看登记模板、组件配方或 PNG 导出
- **THEN** 当前 Canvas 和 PNG 使用真实透明 alpha，记录页面来源、版本、模板与配置；未支持高级设置不伪称已渲染，首页艺术底色保持实施前设计

#### Scenario: 只有生成图或构建记录
- **WHEN** 没有真实页面观察和明确用户确认
- **THEN** 对应美术确认保持未执行，不能因图像精细、构建或任务完成记为通过

#### Scenario: 检查新组合素材的真实接触关系
- **WHEN** 验收人员在真实工作台检查一个声明支持的模块化素材配方
- **THEN** 页面证据绑定素材、基底、姿态、视角和版本，记录实际遮挡/接触及未检查范围；内部图鉴状态仍与用户确认状态分开

### Requirement: 响应式与设备检查必须注明实际覆盖范围
页面检查 SHALL 记录桌面及320/390/768 CSS px视口的真实观察范围，关注身份、文案、操作和非预期裁切。模板图片完整或首页无溢出不能推断图库/工作台全量检查；浏览器视口模拟 MUST NOT 被称为实体手机验收。

#### Scenario: 检查不同页面与窄屏
- **WHEN** 验收者记录首页、图库或工作台的响应式结果
- **THEN** 说明实际页面、视口、版本和截图覆盖，未检查页面/设备明确为未执行，不拼接不同source成单一版本通过

### Requirement: 视角与动作验收必须遵循素材实际能力
当前模板 SHALL 仅按登记的固定视角与完整姿态检查，未制作的侧面、自由旋转或连续动作不列为已提供成品能力。旧三维多视角/关键帧证据 SHALL 保留为诊断历史，不能冒充当前模板通过。未来三维成品 MUST 通过独立变更恢复原多视角、比例、动作、材质、接触和双渲染门槛。

#### Scenario: 切换已登记姿态
- **WHEN** 用户切换模板支持的经典或问好状态
- **THEN** 画面使用对应完整图片，身份与接触按该图片检查；未制作状态不宣称可以合成

### Requirement: PNG下载与Prompt回读结论必须对应实际产物
声称某 PNG 或 Prompt 输出已验证时 MUST 回读真实结果：原始 PNG 记录实际文件、画面、尺寸、alpha 和哈希；Canvas PNG 另记录对应合成配置及实际画布尺寸、透明通道、画面和哈希；Prompt 记录实际剪贴板或文件文本。结构诊断 3D 与共享 2D 诊断 PNG 也 MUST 回读实际字节并检查 alpha。成功 toast、按钮可用、用户美术确认或单张抽样不能单独作为全量技术输出通过证据；有限目录声称全量通过时 MUST 明确覆盖全部适用 look、配方状态和透明输出。

#### Scenario: 检查一张实际下载PNG
- **WHEN** 验收者只核验一张当前模板 PNG
- **THEN** 记录该文件及配置和版本，不推断其他模板下载字节或全部透明边缘均通过

#### Scenario: 检查Prompt复制
- **WHEN** 页面复制 Prompt 后回读系统剪贴板
- **THEN** 只在内容与当次冻结 Prompt 一致时记录该次通过；没有回读时保持未验证

#### Scenario: 声称当前有限输出全量通过
- **WHEN** 验收者报告当前登记模板与模块配方输出全量通过
- **THEN** 证据逐项覆盖适用的 15 个 look、22 个模板状态及当前可信目录的全部模块配方，配方总数由实际目录派生；回读原始 PNG 与 Canvas PNG 字节/画面/尺寸/alpha/SHA-256 以及对应 Prompt；无法执行项说明原因并保持未通过或未验证

#### Scenario: 首页视觉保持且全局随机入口可用
- **WHEN** 验收人员在固定浏览器和视口检查首页，并从现有入口打开全局随机弹窗
- **THEN** 首页布局、群像、卡片、导航、文案与艺术底色保持冻结基线；现有随机入口可以打开并显示透明角色结果，未接入真实素材的随机结果仍如实标记为未验证

#### Scenario: 标签浏览不增加首页控件
- **WHEN** 用户从现有首页卡片进入图库并使用标签筛选，或在工作台打开标签浏览
- **THEN** 首页展示与文案保持不变，标签筛选只改变图库结果范围，标签控件位于图库或工作台且不会覆盖活动作品

#### Scenario: 项目菜单仅移除旧格式导出入口
- **WHEN** 验收人员在工作台打开项目菜单并执行 project v2 导出
- **THEN** 旧 `save-character` 角色 JSON 导出项不存在，v2 项目导出、菜单容器和其他菜单功能仍可用；该差异记录为旧格式停用的预期行为

### Requirement: 任务完成、范围取消和用户确认必须独立留档
验收记录 MUST 绑定页面版本、模板/配置、观察范围与实际用户答复，工程未执行或失败状态独立保存。因用户选择退出本阶段的要求 SHALL 记录为范围取消，保留原任务及原因，MUST NOT 将取消记为实现通过。归档 SHALL 依据保留任务完成和明确范围决定，不追改历史快照或失败矩阵。

#### Scenario: 按用户选择取消旧三维成品目标
- **WHEN** 用户明确选择模板合成和Prompt为本阶段交付、旧三维仅保留诊断
- **THEN** 保存原未完成任务与用户决定，取消项不计入当前完成数量，也不改成通过；未来三维成品另立变更

#### Scenario: 保存后续用户确认
- **WHEN** 已冻结或发布的页面随后得到用户明确美术确认
- **THEN** 新增绑定同一版本和素材清单的确认记录，原发布回执/快照中的历史false保持原值

### Requirement: 捕获调用不能覆盖角色透明输出
任何角色 Canvas、组合图鉴或结构诊断的捕获调用 MUST 保持真实透明 alpha，不得将预览界面底色或显式要求的不透明底色写入 PNG。

#### Scenario: 捕获调用要求不透明底色
- **WHEN** Canvas、组合图鉴或结构诊断捕获请求 `transparent: false`
- **THEN** 实际 PNG 仍有真实透明 alpha，调用方不能把预览界面底色写入角色画面
