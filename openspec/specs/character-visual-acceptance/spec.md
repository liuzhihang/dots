# character-visual-acceptance Specification

## Purpose

规定如何独立记录 Artwork/Asset 工程状态、用户艺术确认、目标平台验证和实际发布状态，并以真实页面/文件证据判断其具体范围。

## Requirements

### Requirement: 作品资源工程状态、美术批准、目标验证和发布状态必须分别记录
每个 Artwork/Asset MUST 分别记录文件存在与读取、版本/hash/尺寸/alpha、来源资格、用户美术批准范围、目标平台验证及发布状态。任一状态不得代替另一个状态。目录资格与资源有效性按具体版本检查；历史批准只覆盖其有证据的范围。

#### Scenario: 资源存在但没有人工批准
- **WHEN** 一张图通过格式和 alpha 检查，但没有绑定的用户美术批准
- **THEN** 工程状态可记为可读取，美术状态仍待确认，该图不得显示为已批准或因此进入精选/随机池

#### Scenario: 已批准作品缺失资源
- **WHEN** 用户批准记录存在但引用的 Artwork 文件缺失或 hash 不符
- **THEN** 资源状态显示缺失/不匹配，作品不可下载或抽取，批准记录原值及范围仍保留

### Requirement: 页面和资源验收必须绑定本次实际版本与观察范围
页面验收 MUST 记录实际站点/本地版本、源码/静态资源清单、浏览器视口、检查路径与结果。PNG 和 Prompt 的通过状态 MUST 基于实际下载字节/剪贴板或文件回读。屏幕模拟、脚本、概念图、截图 diff 或构建结果 MUST NOT 自动代表视觉批准或实体设备验证。冻结证据写入唯一新目录，不覆盖历史证据。

#### Scenario: 检查桌面及响应式页面
- **WHEN** 验收者检查桌面、320、390、768 CSS px 页面中的首页、图库、游戏、详情或参考图流程
- **THEN** 记录实际浏览器/版本和被观察路径；视口模拟明确标为模拟，不能宣称实体手机已通过

#### Scenario: 验证下载 PNG 与 Prompt
- **WHEN** 验收者检查 Artwork 下载和当次 Prompt
- **THEN** 回读下载文件尺寸、内容、alpha、hash，并回读该次剪贴板/TXT文本；未回读的输出保持未验证

### Requirement: 取消范围和历史缺证不得转换为验收通过
被明确取消或失败的历史工作 SHALL 保持原状态，缺失的证据不得补写为通过。当前产品的通过状态仅由当前范围对应的工程证据、素材登记、人工批准或平台验证分别产生。

#### Scenario: 已取消工作不作为当前通过项
- **WHEN** 当前范围不再包含一项历史工作，且其原记录标记为取消、失败或待确认
- **THEN** 保留对应历史状态；不得因当前重构或归档将其勾选为通过

#### Scenario: 新增变体没有确认记录
- **WHEN** 变体文件存在且工程校验通过但没有对应人工确认
- **THEN** 工程检查与用户美术状态分别显示，不能因测试通过标记艺术确认

### Requirement: 特征卡视觉材料必须可追溯且达到展示质量
随机卡与结果摘要 SHALL 使用独立登记、可追溯的展示素材，逐项记录 ID、来源、版本/hash、尺寸、表达的事实、适用作品、工程及独立美术状态。style MUST 为中性身份示意，其余实际有值维度须有准确线索；不以最终成品原图或裁片替代。已核实无值的可选类别不显示卡片、不要求空值图；有值缺图仍保持缺口。跨作品复用须逐个关联核对语义与展示质量，不自动适配或扩展批准。低清占位、原型/网页裁片、错误事实和重复完整成品 MUST NOT 冒充线索。候选预览保持 pending，原成品、新示意、页面与发布状态分别记录，工程通过不替代艺术确认。

#### Scenario: 从已批准高清图取一段特征
- **WHEN** 需要表达某件成品真实存在的帽子、耳机、材质或局部造型
- **THEN** 生产使用独立登记且语义准确的展示 Asset；源图裁片只能用于内部制作参考，不能作为生产默认或自动继承原图批准

#### Scenario: 原图无法提供清晰特征
- **WHEN** 高清源图仍无法清楚表达某项真实特征且没有独立线索
- **THEN** 记录素材缺口并保持 pending，不发布模糊占位或用工程任务替代艺术确认

#### Scenario: 使用独立登记视觉作为特征线索
- **WHEN** Artwork 引用帽子、耳机、材质或造型展示资源
- **THEN** 保留稳定 Asset 与来源，并核对表达事实及适用关联；它只作线索，不宣称可穿戴组件、独立成品或自动批准素材

#### Scenario: 独立揭晓视觉尚未制作
- **WHEN** 有值维度缺少独立素材
- **THEN** 保持缺口及待验收状态，不删该卡、裁成品补位或借不匹配通用素材关闭任务，也不更新用户批准状态

#### Scenario: 中性风格示意不剧透且保留身份
- **WHEN** 审查风格卡的新视觉
- **THEN** 核对它不呈现被抽中成品的专属配色、装备及姿态组合，同时保留 Dots 短绒、Grok Bot 软几何胶囊眼、Meta Muse 奶油包覆内嵌脸面等身份；不把最终图简单灰化当作中性素材

#### Scenario: 通用配饰跨作品复用
- **WHEN** 新作品关联已存在的通用配饰素材
- **THEN** 核对它在该卡表达的类型、外观和组合内容与作品一致；素材原批准仅保留其覆盖范围，新用途或新页面呈现若未获确认仍保持待确认，不宣称万能适配

#### Scenario: 原型方向与最终验收分开
- **WHEN** 将用户指向的同屏揭晓原型用于实现
- **THEN** 采用卡片在上、角色在下及抽完才揭晓的关系，并遵循后续去描述的文字纠正；原型重绘角色、四卡示例、多行说明或截图像素不自动成为生产素材、固定四卡要求或艺术批准

#### Scenario: 检查动态卡数的视觉节奏
- **WHEN** 验收 3、4、5、6 卡的桌面及 320/390/768 CSS px 抽取路径
- **THEN** 分别记录开场、滚动、逐卡停止、全停等待与完整角色阶段，核对无数量跳变、首卡剧透、空卡凑数和长说明；报告模拟视口及实际观察边界，不以静态原型证明滚动趣味性或实体手机通过

### Requirement: 候选线索只能进入明确的审阅预览
正式页面的默认抽卡池 SHALL 只消费已发布、具备对应版本及用途批准、事实与资源验证有效的线索，且作品的全部有效卡都满足该条件。`candidate-preview` 或美术 pending 素材 MUST 仅在维护者明确启用的审阅预览中出现，并清楚说明待确认状态；普通公开入口不得启用此例外。成品的既有批准 MUST NOT 提升线索状态。预览仍须满足真实事实、资源完整、不剧透和同结果绑定，不能因审阅模式接受缺图或错误素材。

#### Scenario: 已批准成品关联待确认线索
- **WHEN** 已批准 Artwork 的任一有效卡仍引用 candidate-preview/pending 线索
- **THEN** 该 Artwork 不进入正式默认随机池；成品原有画廊资格单独保留，不能通过隐藏该卡、借用其他素材或沿用原图替代来进入正式池

#### Scenario: 明确审阅新的线索
- **WHEN** 维护者为用户复核启用隔离的候选预览
- **THEN** 可展示资源完整且语义匹配的候选线索，评审说明标明待确认，普通公开入口不获得此能力；用户未确认前状态仍为 pending

#### Scenario: 发布检查不接受预览例外
- **WHEN** 验证准备发布的页面及默认抽取配置
- **THEN** 审阅例外保持关闭；只有批准记录覆盖具体资源版本和用途的 published 线索进入正式池，预览截图和测试通过不会自动更新这些字段
