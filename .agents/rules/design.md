# 设计实现与验收规则

本规则与根目录 [DESIGN.md](../../DESIGN.md) 配套。做视觉任务前先确认对应 OpenSpec 主规范/change 的当前范围，不以旧截图或历史任务表覆盖最新用户选择。

## 实现约束

1. 保留 Dots、Grok Bot、Meta Muse、人物、动物首批身份和预置标签；目录是可扩展的 typed tags，多标签引用同一 look，不全局把结构 family 改为 tag。画廊、家族场景和工作台单体资产分别管理；场景中新出现的成员不能自动登记为 `lookId`。
2. 当前 15 个登记 look 是现有产品事实，不是固定的未来展示人数。家族卡/hero 人数以明确选定的艺术稿和对应规范为准。
3. 顶部及 Dots/Grok Bot/Humans/Animals 卡忠实按 R01 构图、角色关系和文案层级实施，不自行另创布局；仅顶部右侧和 Muse 卡按 A02 微调 Muse 身份，只有 Muse 卡抱星并带 sage 植物。R01 页面图可用于 ImageGen 风格/布局参考；网站资产必须独立绘制或生成。禁止把 R01 截图像素直接嵌入、裁切、抠取、描摹成角色资产或将其 UI/文字烘焙进 PNG；独立场景插画可以按原型做有意的视口艺术裁切。
4. 人物与动物角色须原创，禁止复用动漫截图、贴图、裁片或完整可辨认的动漫身份。软件角色可在项目已批准的身份及来源范围内使用。
5. 不增加登录、账户或用户空间流程。工作台、画廊、静态下载、Prompt 与“结构诊断”的名称和语义不能互相混淆。
6. 导出状态必须对应真实产物：画廊原图注明原样字节；工作台 PNG 从当前 Canvas 合成；不支持的配置不得启用当前设置导出。Prompt-only 字段不等于 PNG 已实现相同视觉效果。
7. 当前产品包括已登记静态 PNG 模板、透明 Canvas 合成、Prompt 与明确适配的版本化 2D 组合。角色背景选择/染色已移除；新建角色默认透明，现行 v2/VERSION 10 的合法背景字段仅作为保留元数据，Prompt、render plan 与角色 PNG 忽略它。旧 Three.js/WebGL/CPU 模型仅用于“结构诊断”，诊断及共享 2D 捕获 PNG 同样必须保留 alpha；原 11 项 3D 工程/精细基准目标已按用户确认的范围决策取消，不得勾成 3D 通过。未来若另行批准真实 3D 成品，须建立新的范围与验收合同。

8. 首页布局、群像、卡片、主导航、文案和既有搜索/场景过滤保持不变；新标签/组件只扩展图库与工作台，删除旧兼容导出菜单项。
9. 所有创作入口共享组合 resolver；默认随机候选必须真实可渲染。先完整解算、核验资源再动画，锁定不静默替换。新素材按声明基底/姿态全量与组合覆盖检查，自动测试不等于人工美术批准，不自动接受新截图。
10. 本期仅维护者内置目录，不做用户上传、公共标签、投稿或审核系统。项目只读写 v2 + VERSION 10；移除旧格式迁移、恢复副本与旧角色导出。
11. 动态适配由可信几何 profile、组件锚点与 fitPolicy 解算位置、比例、朝向和层序；不以每个基底的固定 placement 冒充动态适配。仅支持明确登记的视角和姿态，超出结构/比例/接触约束时拒绝；实际组合按比例、接触、遮挡、材质光照、配色检查，不把工程通过写成美术确认。
12. 角色预览、老虎机角色结果、PNG 与 2D/3D 诊断捕获保持透明 alpha；Prompt 忽略背景元数据。恢复/编辑现行 v2/VERSION 10 项目时原样保留严格合法的背景元数据、`composition.inputs` 与有效指纹，不归一化或迁移。旧格式仍拒绝。删除工作台背景面板和首页唯一背景功能按钮，首页其余布局、艺术底色及历史冻结证据保持原样。

## 页面与视觉审查

- 先在实际应用页面查看新改动；按任务涉及范围检查桌面及 320、390、768 px 视口。记录具体冻结 source/cache 标识，发现空白图、裁边、溢出、遮挡或小尺寸不可辨识时按真实问题记录。
- 检查角色身份特征、大小/高低/前后层次、材质、道具/配饰接触、文案层级与颜色是否符合已选设计。不能仅用生成预览、组件测试或静态截图剪贴证明网页通过。
- PNG 验收检查实际下载字节、尺寸、alpha、SHA 和必要时目视结果；点击成功或 toast 出现不等于文件已核实。
- 用户艺术确认必须记录用户实际确认的页面版本/素材。Site 35/cache 83 下，首页与家族场景，以及五组当前 Gallery/工作台模板形象，已分别按对应记录获得用户确认；这不证明全量 PNG 导出字节或实体手机已验证。内审、构建、脚本、任务勾选和 Sites receipt 都不能代替用户确认；不同变更范围的确认不可推断互认。
- v83 冻结页上的候选标签与 `userArtApproved: false` 是捕获时的历史字段；后续确认通过独立记录追加。不得把历史标签当作当前用户否决，也不要改写冻结证据。
- 对实体设备或外网访问没有实测时，明确标为未验证。不要把桌面浏览器模拟称作实体手机验收。
- 发布后分别回读 Git 与 Sites 状态。保持既有 Site 身份、权限与发布配置；不要以修复为由更换私有 Site 或放宽访问范围。

审查记录应说明范围、绑定版本、实际观察和仍未验证的边界；不要用“通过”概括未检查的家族、导出路径或设备。
