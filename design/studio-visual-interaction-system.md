实现优先级为：本轮明确的文字合同和身份纠偏 → 已批准的原始角色素材与来源/批准记录 → `Photo 1.jpg` 对应页面结构 → 已实际取得且获准作为辅助的局部视觉材料。整张原型只能指导页面关系，不能嵌入网页或裁出角色像素；原型示例不是无条件的角色、文案或功能批准。

## 页面视觉关系

- **首页**保留 Dot Icon Studio 品牌、中央标题“小小角色，让大大的想象发生”、左右群像的大小与关系、轻盈明亮底色、现有两块 Hero 与五张专题卡。专题是可扩展内容入口，点击后进入对应图库查询；不变成固定“五大家族”渲染架构。原工作台宣传位改为精选作品、真实已制作变体或参考图文字辅助，不增加宣传长页。
- **画廊**以已发布作品图为主体，提供关键词、标签和更多筛选；浅色表面和筛选层级保持清楚。无内容标签不展示；无结果提供修改条件的直接入口。详情关闭后恢复原查询、滚动和焦点。
- **灵感游戏**是共享随机玩法的独立页面容器，本 change 使用默认有效池，不提供范围或硬锁控件；画廊随机入口仍冻结当前查询。游戏与首页/画廊入口使用同一抽取模型和 DrawResult。
- **随机揭晓**使用有明确层次的舞台和独立特征卡。页面展示从真实候选中选出一件作品的过程，不表示生成新像素或现场穿戴。卡片停完后让完整作品占据视觉中心。
- **作品详情**采用稳定的“作品详情”标题栏与正文作品名称，展示完整图片、精选事实、实际规格和直接操作。复制 Prompt、下载原图是主要操作，变体、完整 Prompt、目标说明和 ChatGPT 为按需查看的次级内容。
- **参考图辅助**只让用户选择风格、输入描述和保留项并生成文字模板；本站不选择、预览、识别或上传图像。用户在 ChatGPT 手动附图并自行发送。

## 身份与资源表现

- **Dots**沿用具体批准作品；新制作材料保留用户指出的柔软短绒触感，不得为统一组件示意而画成光滑塑料球。当前短绒图库作品与已批准的光滑紫色 Hero 具有不同的来源/批准范围；在用户裁决如何处理 Hero 前不修改原 PNG，也不宣称这些视觉材料已经统一。
- **Grok Bot**保留软几何主体、成对胶囊眼和克制表情；不得成为屏幕脸机器人。点列与液滴方向以已确认参考和真实素材为准。
- **Meta Muse**保留包覆式奶油形体与内嵌脸面；不替换成普通人物或随意玩偶。
- **人物**保留原创 Q 版比例、分层发丝/细发丝、皮肤和衣物质感；**动物**保留明确物种耳朵、口鼻、毛色、爪和尾部结构。
- Artwork 可分别登记 `revealVisuals.style`、`appearance`、`paletteMaterial`、`clothing`、`accessory`、`prop` 六类老虎机/特征说明资源。资源须记录来源、Asset ID、版本/hash、尺寸、语义用途及各自的工程和批准状态；它们不是可穿戴组件，也不参与最终作品合成。Style 可用真实 Artwork 识别图，其他非空维度使用独立且清晰准确的展示资源；`none`/`notApplicable` 使用统一、低强调且符合事实的空值卡。`sourceRect` 可留作内部制作辅助，不作为生产默认；缺少正式视觉资源时记录缺口并保持待验收，不以粗糙占位图关闭任务。供用户复核的 `candidate-preview` 可出现在候选预览中，但 `artApproval=pending`；既有15张完整 Artwork 的批准范围不变，候选图不授予新 Artwork 发布资格或“六类视觉通过”状态。新 visual 资源存在或工程检查通过均不自动构成用户美术批准。
- 角色原图默认透明且无烘焙地面/脚底阴影团。页面、舞台、卡片和弹窗可有底色；底色不能进入原图下载。场景插画与透明角色为不同资源类型。

## 八类事实与六张揭晓卡

结构化事实目录为八类：角色风格、外形、五官、配色材质、衣物、头部配饰、身体饰品、随身道具。动作/表情是同角色的独立完整变体或真实动画资源，不能混入本次揭晓槽；背景属于资源规格，不占卡槽。页面的六张固定卡按此顺序映射：

1. 角色风格
2. 外形五官
3. 配色材质
4. 衣物
5. 配饰（头部配饰与身体饰品）
6. 道具

桌面为一排六张 5:6 竖卡；手机使用可触控的横向轨道，突出当前卡并露出前后邻卡，不把六张压成不可读的一排。每卡候选可按顺序减速停止。滚动候选可以来自有效池里的不同 Artwork，每项绑定自己的来源 Artwork、Asset 版本/hash，只作为过程示意；六张最终停值、结果图、标签、Prompt 与下载绑定同一个 DrawResult。最终六项特征必须共同对应一张完整目录作品，不可拼出未登记的新图。

`none` 表示已核实没有该元素；`notApplicable` 表示该维度不适用，两者都可快速停止并准确呈现。`unknown` 不是“无”，不能进入需要该揭晓事实完整的默认池。未知数据不能由空白或近似视觉推断补齐；一张作品的实际配饰、衣物和道具不能从其它卡片拼进结果。

抽取弹窗、灵感游戏页面和共享揭晓视图在抽取前/动画中不显示范围、关键词、标签或硬锁控件。首页和游戏使用默认有效池，画廊入口冻结当前查询；本 change 不提供游戏范围控件。有效点击打开随机弹窗后，卡片动效立即开始。后台准备同一结果的完整图和揭晓视觉时，等待卡或候选卡可以继续滚动，但任何卡都不能提前停下或显示最终作品；同一 DrawResult 的所需资源就绪后才逐卡落定。若资源失败，当前抽取按普通用户能理解的方式结束并提供恢复操作，不偷偷换作品或放宽条件。页面不显示“已选定完整作品”“校验原图”“source”“冻结”等工程文案。结果锁定只在作品已经揭晓后按需展开。用户可将一个或多个真实 Feature 作为下一次抽取的必备条件，所有锁定值按 AND 求交；普通筛选维度内部的 OR 规则仍只适用于软筛选。锁定不重新抽单张特征卡、不改写当前结果、不将组件装到其它角色。空池在卡片开始滚动前明确报告；只有用户修改条件后才能再次抽取。

揭晓阶段文案围绕“遇见新的伙伴”。普通逐卡动画和主动跳过均先等同一结果资源可用，再停止六张卡；全部停止后进入约 900ms、结果仍隐藏的 `awaiting-reveal` 边界，再展示同一结果。若跳过发生在资源准备期间，只在资源就绪后立即静态落定，不重新抽取。Reduced Motion 不滚动、不翻牌、不做明显移动；同一结果资源就绪后，六张静态真实特征卡全部显示，结果保持隐藏，用户点“揭晓伙伴”才继续。结果顺序为六项摘要 → 完整角色图 → 名称与简短说明 → 复制 Prompt/下载图片 → 再来一款、详情和 ChatGPT 等次级操作。手机角色图居中，六卡摘要在角色上方以 110–120 px 级别短卡组成横向轨道，分类名、特征图和短名称完整可读，不使用省略截断。移动端重抽必须将实际滚动的 overlay/dialog/view 容器恢复到六卡舞台起点，不依赖 window.scrollTo 或把焦点滚到结果区。作品图始终保留登记像素的原色，不套滤色或色相变换。抽取前/抽取中不显示条件面板；关闭取消、快速重开、单候选、去重袋重置、加载失败仍维持同一结果绑定合同。

## 交互与视觉 token 语义

共享浅色页面使用当前已实现的 `--ink`、`--muted`、`--blue`、`--line`、`--panel`、`--soft`、`--radius` 等 `studio.css` 根变量；详情层通过这些共享颜色变量表达文字、分隔线和卡面。随机视图已经实现独立 token：`--fr-stage-ink: #f8f8ff`、`--fr-stage-muted: #d5d7e9`、`--fr-stage-deep: #1c2235`、`--fr-stage-light: #35344e`、`--fr-glass-edge: #e4e3ff4d`、`--fr-card-surface: #f5f3ff`、`--fr-card-ink: #35374f`、`--fr-step-accent: #bda5f8`。主要渐层按钮使用 `#8460d3` 至 `#6c49bc`，白字当前对比度约 4.57:1；继续调整时重新测量，不以旧值通过推断新候选通过。token 角色和实现色值都需实际截图复核，不能由变量名推断用户已批准视觉。

卡片需区分舞台、玻璃边缘、卡面、当前阶段与空值；低动态模式减少位移/模糊。空值卡仍保持槽位顺序，但不做长距离假滚动。打开详情或进入画廊／游戏时，初始焦点落在静态的 `#overlayTitle`、`#galleryTitle` 或 `#gameTitle`；这些标题不呈现输入框外观。按钮、链接、筛选等可交互控件必须保留清晰的 `focus-visible` 状态。Tab 顺序、Escape、触控关闭和窄屏按钮可达性必须保留。
