# 设计

## 背景

需求见 [proposal.md](proposal.md)，行为合同见 [studio-visual-experience spec delta](specs/studio-visual-experience/spec.md)。用户已选 [R01 首页设计](../2026-10-06-rebuild-character-system/references/r01-confirmed-direction.jpg) 为唯一首页与家族卡视觉目标。首页、两幅 hero 和五张卡都应忠实实现图中的角色比例/位置、配色、材质、道具关系与文字层级；四张已有非 Muse v2 家族卡的视觉偏离必须替换。用户强调只有 Meta Muse 需要身份微调，不得另创第二套卡片设计。

R01 可以提供给 ImageGen 作为构图、服装风格、材质和配色参考。页面最终使用新制作的单独角色场景图；不得直接嵌入整张网页截图，也不得从网页或动漫截图裁切、抠图或提取像素。独立新插画可以按 R01 在页面中做有意艺术裁切。人物与动物须原创，不可使用用户从动漫截取的像素、裁片/贴图或可辨认完整角色；R01 中人物/动物的服装和构图可用于视觉参考，但不能把该场景误称为动漫资产的复制授权。

页面用 `HERO_SCENES` 与 `FAMILY_SCENES` 加载纯展示图；图库身份由 `FAMILY_LOOK_IDS` 和 `getBuiltInLooks()` 管理。该 change 不修改既有五组 15 个可编辑图库 `lookId`、每组三只候选或其角色身份契约。首页插画和 hero 人物都只是对应身份的展示场景，不因画面精细就变成图库单体、可编辑图层、PNG 下载、Prompt 或已保存项目素材。

当前设计采用的展示成员数为：hero 左 5、hero 右 5；五卡分别为 Dots 4、Grok Bot 6、Meta Muse 1、人物 3、动物 5。这些是当前素材组合和位置关系的事实，不限制以后家族卡或图库增加人数。HTML/DOM 保留所有网页标题、说明、箭头、导航、候选状态与页脚文案；场景 PNG 不烘焙 UI 文字。

## 目标与非目标

**目标：**

- 忠实实现 R01 的顶部主视觉、五卡构图与页面层级。按图匹配角色相对大小、高低位置、颜色/材质、道具和群体前后关系。
- 用指定的本轮素材组织角色：左 hero 5、右 hero 5；Dots 卡 4、Grok Bot 卡 6、Meta Muse 卡 1、人物卡 3、动物卡 5。
- 对四张 v2 非 Muse 卡片作 R01 风格的展示素材替换，同时保留其原软件身份或原创设计身份；对 Muse 只做指定的 A02 单体身份微调。
- 保留五组 15 项图库、各组候选状态、中文人物/动物导航、画廊、工作台、显式 `startLookId`、问候交互及 PNG/Prompt 输出保护。
- 删除首页卡片中的“3 款候选”字样，保留画廊对各组三只图库形象的准确候选数。卡片标题、中文说明和两行英文短句按 R01 的位置/层级呈现。
- 使用实际最新 runtime 冻结来源重新捕获和检查真实首页，而不是将老版本截图当作当前结果。

**非目标：**

- 把 R01 之外的首页或卡片视觉方案加进来，或改变其原有群像主次/比例来迎合当前 v2 图。
- 改写五组 gallery 的原身份契约、已登记 15 个 `lookId`、每组三只候选，或将展示成员添加到 Gallery、工作台、随机池、单体下载、Prompt 和项目 JSON。
- 将 R01 的整页截图、抠图、裁片或像素作为站点素材；将生成画面文字烘焙成图片。
- 将用户提供的动漫截图内容直接用于人物或动物角色，或完整复制能辨认的动漫身份；换色或换装不构成原创重设计。
- 仅靠 CSS 改变图片裁切/尺寸来掩盖 v2 展示图与 R01 构图的偏差。
- 将 R01 布局选择、生成素材、构建、截图采集、无溢出或任务勾选当作网页美术验收/用户确认。

## 决策

### 1. 两幅顶部主视觉忠实重制 R01，右侧仅替换 Muse 身份

页眉、中央大标题、居中的主操作、左右主视觉和标题留白沿用 R01。不要复刻它的登录或“我的空间”功能。左右 hero 的人物成员、配色、材质、姿态与相对位置忠实跟随原型：

- **左侧五名成员：** 主位为光滑缎面紫色耳机 Dot，眼睛为 R01 的倾斜白胶囊形；栗色头发、白色衣着的小男孩挥手；小粉色三角、绿色云形和蓝色水滴围绕主角，保留原图的体量层次和互相靠近关系。
- **右侧五名成员：** 棕发丸子头、黄色衣着、眨眼并作 V 手势的女孩；橙色柴犬、橙色豆形伙伴和青绿色圆角方形，按 R01 的大小、前后与横向位置关系构图；唯一改动是将原型中的奶油色伙伴替换为 A02 身份的单只奶油包覆式 Meta Muse。Hero Muse 不持星、不带植物。

该 scene 使用 R01 展示版紫色缎面 Dot 和白色斜胶囊眼，不受现有 Gallery 内蓝色短绒 Dots 资产的外观限制；但不更改该 `lookId` 的可编辑角色资产，不声称 hero Dot 是 gallery PNG。当前 15 项图库、工作台和导出合同仍保持现状。

### 2. 五张家族卡按 R01 单一原型实施

卡片保持相同的层级：左上/上方为家族标题与简短中文描述，圆形箭头位于右上；主体群像占据主要画面区域；底部短句以两行英文呈现。首页卡删除“3 款候选”及其他图库数量提示；画廊仍显示准确的三只登记候选状态。人物/动物卡片标题使用英文 **Humans** 和 **Animals**，导航标签仍为中文“人物”和“动物”。

### 3. 仅对 Meta Muse 作单一身份微调

Meta Muse 家族卡只呈现一只奶油色包覆式 Muse，与 A02 指定身份一致：连续圆润的 hood 与躯干，脸面是暖色内嵌区域，hood 内缘和面部开口厚度清楚，配简洁表情、短圆手臂和双脚，表面为细腻布面/短纤维质感。Muse 双手/短臂怀抱星星，星星须与手臂有自然接触；sage 植物置于角色旁作为点缀，不遮脸、不穿过身体，不添加第二只粉色 Muse。星星与 sage 植物是家族卡专属道具，不进入 hero。

hero 右侧中的 Muse 使用相同的 A02 hood、脸面、奶油配色和比例，只按场景改变姿态，贴靠/坐在女孩旁；不持星，也不带植物。此处明确替换 R01 右侧的奶油色伙伴身份，其余棕发丸子头、黄色衣着的女孩、柴犬、豆形伙伴及青绿色方形均保持原型，不被重新设计。

### 4. 人物和动物原创与 R01 参考素材边界

允许 R01 文件作为 ImageGen 输入参考，使它遵循原型的构图、相对大小、高低/左右位置、服装配色、材质方向、卡片背景、主体与道具关系。ImageGen 输出必须是全新渲染的角色插画；不得用整页截图替换网页组件、裁切/抠图复用像素、描摹成可辨识角色，或将 UI/文字放进图片。

人物/动物原型能指导服装和群像风格，不改变动漫来源的禁用边界。三名人类角色和五只动物应重新设计面孔、毛发/毛色细节和身份标志，避免复刻用户从动漫截取的任何完整角色组合。软件内置 Dots、Grok 和 Meta Muse 的原版身份按来源标注处理；首页展示 Dot 的 R01 视觉可以与某些已登记 Gallery asset 不同，因为它不属于可编辑图库身份。

### 5. 场景展示不与可编辑图库绑定

Dots 4、Grok 6、Muse 1、人物 3、动物 5 是本轮场景绘制中的计数事实，不是数组上限、图库数或验收打分。现有图库仍每组 1 只 canonical 加 2 只待确认候选，共 15 个；候选数从 Gallery 数据读取。首页卡不展示该数量。

`displayMembers` / `displayCount` 只说明图中成员；`FAMILY_LOOK_IDS` / `getBuiltInLooks()` 继续管理 Gallery 和创作资产。每张家族卡的开始创作仍用显式有效的 `startLookId`，不可从展示图成员推导。任何展示角色不得自动进入图库、工作台、随机池、PNG 导出、Prompt 或项目 JSON。

### 6. 修改后使用真实当前 source 验收

较早 v72 native viewport 图只保留为历史基线，并且发生在本轮场景内容确定之前。当前实际 runtime 已继续迭代；实施前须从真实本机冻结清单读取源码/source，文档不得将 v72 误称为当前或推测 source ID。

新资产写入当前源后，在真实页面分别捕获桌面与 768/390/320 CSS px 视口。逐视口核对 hero 清单、五张卡的组别/人数、主体相对大小/位置、色板/材质/道具接触、中文描述、英文双行短句和窄屏完整性。首页 card 不出现“3 款候选”，Gallery 页面各组三只记录仍准确。根据源码版本/source ID 和实际截图留档。构建、图像文件、无溢出、视觉方向选择和程序测试只能证明其各自检查范围，不能替代真实美术评审或用户确认。

## 风险与权衡

- **把旧 v2 卡片微调后继续作为 R01 结果** → 按明确的角色组合和相对位置重做非 Muse 四张卡片图，而不是以 CSS 掩盖偏差。
- **展示 Dots 被错当为 Gallery Dot 编辑素材** → 保持 scene 与 15 项 `lookId` 数据严格独立，并在来源记录中标注 R01 展示版材质/白胶囊眼。
- **把 R01 展示 Dot 错当成 Gallery 资产** → 明确标注 scene-only 的光滑紫 Dot 与白色斜胶囊眼；Gallery 资产仍按其既有合同管理，两条资产路径互不改写。
- **Muse 变成两只或泛化毛绒动物** → 首页右侧与 Meta Muse 卡各呈现同一 A02 身份的单只奶油 hood Muse；只有卡片抱星并使用 sage 植物，hero 不带这些道具；不保留粉色第二只。
- **文案把图库计数暴露在不合适位置或被烘焙到图片** → 首页删除候选数量，Gallery 保留真实数量；所有标题、导航及中英文句均由 HTML 渲染。
- **R01/动漫参考被直接作为角色原图** → R01 可作 ImageGen 的风格输入，网页仅展示新绘资产；人物动物要原创身份，动漫截图像素/裁片/完整角色禁止使用。
- **页面/脚本结果被误报成美术通过** → task 3.2、3.3 与 task 4 只能依据各自的真实实现、独立评审及用户明确确认更新，保留版本与范围证据。

## 迁移计划

1. 实施前读取实际最新运行代码、`FAMILY_SCENES` / `HERO_SCENES` 与当前冻结清单；不要基于历史 v72 快照推定当前 source。
2. 保留 R01 总体页面结构；忠实重制 hero 左右场景，其中右侧只将奶油色原型伙伴替换为 A02 Meta Muse。
3. 按当前表格替换五张 family card 画面，非 Muse 四卡复原 R01 视觉；Muse 单体呈现；HTML 文案按 R01 层级改写，首页去掉候选数，导航维持中文人物/动物。
4. 验证 15 项现有图库身份与所有已保存项目不变，展示 scene 成员不进入可编辑图库或工作台；运行必要程序检查并采集新源码的实际页面证据。
5. 完成独立评审和用户明确确认后才更新相应任务。当前不得提前打勾。

## 未决问题

R01 页面和五张卡的视觉目标、当前人数及 Muse 唯一替换方向均已确定。当前 v83 的实现、source 绑定页面核验、独立评审与用户明确确认均已完成，见下文及人工确认记录；未来构图人数可调整，不受本轮当前素材数限制。旧 3D 模型的工程验收仍由 rebuild-character-system 独立跟踪。
