# Spec Delta

## Purpose

为维护者制作的静态 2D 素材建立版本化目录、显式适配约束和共享解算，使每项推荐结果都能由受信任的实际 PNG 配方复现、保存、恢复和验收。

## ADDED Requirements

### Requirement: 模块素材必须登记完整且可校验的素材契约
每个可参与模块组合的资产 MUST 使用稳定 ID、素材版本和 SHA-256，并登记素材类别、占用槽位、支持的基底/身体布局、视觉风格适配、视角、姿态、锚点与对齐规则、图层次序、前后遮挡、依赖/互斥、抓握或接触要求、染色区域（若有）、来源和使用范围、工程渲染状态、发布资格及美术确认引用。一个素材声明的能力 MUST 对应实际存在并已核验的文件及完整渲染配方。标签、系列或 family 映射 MUST NOT 单独授予兼容或渲染能力。

#### Scenario: 登记具有明确适配范围的组件
- **WHEN** 维护者登记一件带版本与哈希、槽位、基底/姿态支持、遮挡/接触、来源及验收状态的本地组件
- **THEN** 系统仅将契约中明确声明且文件哈希匹配的基底与姿态关系提供给解算器

#### Scenario: 素材缺少必要契约或文件校验失败
- **WHEN** 组件缺少稳定身份、支持范围、来源、适配关系或本地文件的哈希与尺寸不匹配
- **THEN** 系统拒绝将其注册为可渲染资产，并且不得将它加入精选或默认随机候选

#### Scenario: 仅新增浏览标签
- **WHEN** 一个现有形象只增加作品系列、主题或风格标签
- **THEN** 标签仅影响内容检索范围，不改变当前活动作品、基底能力、配方或素材兼容性

### Requirement: 组合解算必须先满足硬约束再应用美术推荐规则
系统 SHALL 将“能否组合”的硬约束与“是否优先推荐”的美术规则分开计算。硬约束 MUST 覆盖所选基底/布局、槽位占用、视角与姿态支持、素材依赖与互斥、锚点、遮挡顺序、抓握/接触及本地已核验的渲染能力。任一硬约束不满足时，系统 MUST 拒绝该组合并说明具体冲突，不得自动增加身体结构或替换锁定素材。美术规则只 SHALL 调整可行组合的推荐顺序；高级编辑可显式放宽推荐规则，但 MUST NOT 绕过硬约束。

#### Scenario: 请求不兼容的身体配饰
- **WHEN** 用户为无手臂基底选择要求双手承托的杯子，且目录没有该基底的已验证抓握适配
- **THEN** 解算器拒绝该组合并说明缺少抓握适配，不为角色增加手臂，也不显示为可导出的当前结果

#### Scenario: 可行组合违反默认风格建议
- **WHEN** 用户显式打开高级编辑并选择多个结构兼容但超过默认搭配数量的配饰
- **THEN** 系统可保留这些显式选择，但仍执行全部硬兼容、依赖、遮挡和渲染检查

#### Scenario: 所有可行组合均与锁定项冲突
- **WHEN** 用户锁定的素材与当前基底或姿态不存在共同可行配方
- **THEN** 系统保留锁定项并报告冲突，不以另一个素材静默替换它

### Requirement: 所有工作台入口必须生成同一种真实可渲染组合
手动编辑、精选搭配、随机候选、项目恢复、预览与导出 SHALL 共用同一组合解算结果格式 `ResolvedComposition`。该结果 MUST 包含已解析素材的稳定 ID、版本、哈希、确定性图层顺序及锚点/遮挡规则、姿态/抓握配方、标准化输入、输入指纹和解析结果指纹。系统 MUST 先确定完整可行的 `ResolvedComposition`，再开始滚轮揭晓或预览；未解析的 Prompt-only 配置 MUST NOT 进入默认成品结果。模板适配器 MUST 让现有 `fixed-image-2d` 和 `layered-2d` 继续走现有完整配方与安全校验，同时在同一结果接口中保留其当前图层选择行为。

#### Scenario: 通过不同入口选择相同组件配方
- **WHEN** 用户手动选择、应用精选方案、重抽随机或恢复相同项目输入
- **THEN** 各入口由同一解算规则生成相同的标准化素材引用、图层次序和解析指纹

#### Scenario: 当前输入没有完整渲染配方
- **WHEN** 输入包含未登记的素材、姿态、染色区域或接触组合
- **THEN** 解算器返回不可渲染原因，Canvas 不显示为当前组合，PNG 导出保持禁用，Prompt 设定仍可保留

#### Scenario: 继续使用旧完整模板或分层配方
- **WHEN** 用户使用任一既有完整模板或 `layered-2d` 配方
- **THEN** 模板适配器继续使用该配方原有的精确图层选择、完整结构绑定、本地路径校验和真实 Canvas 导出边界

### Requirement: 默认随机必须从真实可行且已批准的组合中选取
默认随机候选 SHALL 只来自文件和哈希已核验、硬约束可解、已有完整 Canvas 配方且该基底×素材×姿态适配具有当前版本美术批准的组合。随机过程 MUST 在动画揭晓之前生成完整候选，不能逐列独立选择后再临时替换冲突项。默认搭配 SHALL 至多推荐一件主配饰、一件辅助配饰和一件主要道具；基底固有穿搭不计入该数量。该数量限制属于默认候选风格策略，高级编辑可放宽，但不能绕过硬兼容。没有可行候选时系统 MUST 说明锁定项、筛选条件或适配范围造成的冲突。

#### Scenario: 随机生成一个可绘制完整结果
- **WHEN** 用户从当前筛选范围请求默认随机
- **THEN** 系统先返回一个包含真实已批准素材 ID、版本与完整配方的可行 `ResolvedComposition`，其各展示阶段均来自该候选，最终 Canvas 可以按同一结果渲染

#### Scenario: 候选池中只有 Prompt-only 设置
- **WHEN** 某随机选项只存在于角色配置或 Prompt，未绑定受信任的实际 PNG 配方
- **THEN** 该选项不进入默认随机成品池，也不会在滚轮或最终组合图中伪装为真实素材

#### Scenario: 随机没有满足锁定与筛选的结果
- **WHEN** 当前候选范围内不存在符合锁定项及硬约束的已批准配方
- **THEN** 随机流程说明不可行条件，不生成或静默替换一个不兼容结果

### Requirement: 所有新项目必须用 v2 区分真实组合与 Prompt-only 配置
所有新保存、导出和随机应用结果 MUST 使用 `{format:"dot-studio-project", version:2}`，且只包含角色 VERSION 10。`creation.composition` MUST 为 null 或实际解算对象；非 null 对象的 `kind` MUST 明确为 `template` 或 `modular`，并保存共享 resolver 实际生成的可复现引用，包括目录版本、实际素材稳定 ID/版本/哈希、配方 ID/版本、标准化姿态与输入、输入指纹及解析结果指纹；模板 kind 保存模板/状态 PNG，模块 kind 保存基底与按槽位排序的输入素材。没有可绘制结果时 `creation.composition` MUST 为 null；Prompt-only 角色 VERSION 10 字段仍可保存，解算原因在加载/恢复时重新计算，不得伪造素材引用、图层或解析指纹，也不得阻止保存角色配置。项目 JSON MUST NOT 将内嵌图片、任意路径、任意 URL 或直接提供的图层清单/`ResolvedComposition` 作为可信素材来源。导入只接受包装 v2 内角色 VERSION 10；非 null 组合按可信登记引用重新解算，null 组合仅恢复 Prompt-only 配置且不能显示为已绘制组合。完整模板仍使用现有 PNG 和精确配方，不得退回旧包装格式。

旧包装、裸角色 JSON（包括裸 VERSION 10）、VERSION 10 之前的角色 schema、旧字段别名和恢复副本均 MUST 返回明确的当前格式不支持提示；系统 MUST NOT 自动迁移、映射旧 alias、从 `legacy.originalConfig` 或 Muse/Pets alias 恢复角色，也 MUST NOT 将这些旧字段保存在 VERSION 10 新项目中。拒绝输入时原始导入文本或旧存储草稿 MUST 保持未覆盖，提示 MUST NOT 声称数据已删除。新 v2 包装的字段 MUST 经过严格白名单校验；角色 VERSION 10 中当前 canonical `family` 字段仍按当前角色合同处理，不全局改名为 tag。

#### Scenario: 保存并重新导入模块项目
- **WHEN** 用户导出 `kind: modular` 的模块组合项目，再从 JSON 导入
- **THEN** 系统根据本地可信目录中的 ID、版本与哈希重新解算，并恢复相同的受支持槽位输入和解析指纹，非 null `creation.composition.kind` 为 modular，角色 VERSION 10 不变

#### Scenario: 保存并重新导入真实模板随机结果
- **WHEN** 用户将随机得到的完整模板组合保存为 `kind: template` 项目，再从 JSON 导入
- **THEN** 项目保存实际模板/状态 PNG 的素材 ID、版本、哈希和配方引用；系统从可信目录重新解算并恢复同一真实画面，不只保存 `artworkId` 或随机 seed

#### Scenario: 保存并重新导入未随机的完整模板项目
- **WHEN** 用户保存一个直接选择的现有完整模板项目
- **THEN** 项目使用包装 version 2，`creation.composition` 为非 null 且 `kind: template`，保存实际完整 PNG 素材 ID、版本、哈希和配方引用，并恢复同一登记模板

#### Scenario: 保存不能绘制的 Prompt-only 配置
- **WHEN** 用户保存包含超出已登记渲染能力的姿态、颜色或组件配置
- **THEN** 项目使用包装 version 2 和角色 VERSION 10，`creation.composition` 为 null；Prompt-only 角色配置可保存/恢复，不伪造 Canvas/PNG 组合，且 resolver 在恢复后重新计算能力原因

#### Scenario: 导入未知、过期或哈希不匹配的组件引用
- **WHEN** 项目中的基底、素材、配方版本不存在或哈希与当前可信目录不匹配
- **THEN** 系统拒绝将该组合渲染或导出为当前结果，显示具体缺失/不匹配项并保留其余有效角色文本与项目数据，不选择替代素材

#### Scenario: 导入旧包装、裸角色或旧恢复别名
- **WHEN** 用户导入项目包装 v1、裸角色 JSON（包括 VERSION 10）、VERSION 10 之前的 schema，或包含 `legacy.originalConfig`、Muse/Pets alias 的数据
- **THEN** 系统显示当前格式不支持，不自动迁移、映射 alias 或恢复旧配置；源文本与旧存储草稿不被覆盖，也不宣称已删除

### Requirement: 染色能力必须与实际解析颜色和像素输出一致
素材只有在其染色区域、目标颜色字段和选中配方均登记且完整可绘制时，MUST 才声明该字段可改变 Canvas。解析结果 MUST 保留用户选定的染色输入；Canvas、导出 PNG 与解析指纹 MUST 对应同一颜色值。若缺少遮罩、染色映射或可读像素证明，系统 MUST 保留该值用于 Prompt，但不得开放颜色渲染或当前 PNG 导出。

#### Scenario: 应用登记染色区域
- **WHEN** 用户为具有已登记染色区域的素材选择一种受支持颜色
- **THEN** 解算结果包含该颜色，Canvas 与导出的 PNG 实际显示对应像素变化，解析指纹随颜色输入变化

#### Scenario: 染色字段丢失或遮罩缺失
- **WHEN** 候选配置改变了颜色，但解析后的素材仍使用基底默认颜色，或所选配方缺少对应染色区域
- **THEN** 系统不得报告该颜色配置可渲染或启用当前 PNG 导出，并指出缺少的颜色映射或像素证据

### Requirement: 每项新适配必须独立记录人工美术批准
工程可用状态 MUST 与适配协调性检查及用户美术批准分开记录。每个准备进入精选或默认随机池的基底×素材×姿态/视角适配 MUST 有独立批准记录，精确绑定基底资源引用（ID、版本、SHA-256）、素材 ID/版本/SHA-256、配方 ID/版本、姿态与视角，以及规范化配方指纹。多组件 recipe 中每项素材的批准记录都 MUST 绑定同一完整组合 recipe 及其真实组装页面；单件适配证据或另一组件批准不能补足缺失批准。配方指纹 MUST 覆盖布局、风格、放置锚点/尺寸、图层顺序和高风险适配声明；任何绘制相关内容变化，即使版本未递增，也 MUST 使旧批准失效。批准证据 MUST 指向具体冻结来源和页面：记录来源清单路径、来源 SHA-256、每张页面图像的路径与 SHA-256，以及对应视口尺寸。每条适配记录 MUST 另含 `coordinationChecklist`，且仅含 `proportion`、`contact`、`occlusion`、`materialLighting`、`palette` 五项；五项都 MUST 由人工基于记录页面明确标记为 `pass`，缺项、`issue` 或 `unreviewed` 均不得视作有效批准，也不得进入精选或默认随机池。该清单是对实际画面的人工判断，不是自动测量结果；工程上可绘制或清单全通过均不能替代独立的用户美术批准。其他基底、姿态、标签、模板或后续版本 MUST NOT 因相似性或同一组件而自动继承批准。冻结记录中的历史状态 MUST 保持原样，后续批准 SHALL 通过关联具体冻结版本的新记录追加。

#### Scenario: 组件在一个基底上获批后用于另一个基底
- **WHEN** 某配饰适配已在 Dots 基底获得美术批准，维护者声明它还支持人形基底
- **THEN** 人形组合保持待批准，不进入精选或默认随机池，直至该具体适配经过独立真实页面检查与用户确认

#### Scenario: 历史模板已有确认而新增组合尚未确认
- **WHEN** v83 已批准模板作为一个组件组合的外观参考，但新增的组合图尚无批准记录
- **THEN** 系统仅保留 v83 原模板批准范围，不把模板确认扩展到新组合

#### Scenario: 可绘制的适配仍有未通过的协调性检查
- **WHEN** 某模块配方工程可用，但五项协调性检查中缺项、标记为 `issue` 或仍为 `unreviewed`
- **THEN** 该组合可以作为明确待审状态预览，但其适配批准保持待处理，不进入精选或默认随机；即使五项均通过，仍须另行取得该适配的用户美术确认

#### Scenario: 多组件 recipe 逐项满足适配批准
- **WHEN** 一个 recipe 同时包含耳机和眼镜等多个动态组件，但其中一个组件缺少与该基底、素材哈希、recipe 指纹及页面证据精确匹配的人工记录
- **THEN** 组合仍可在硬约束通过时作为待审预览，但整体 recipe 保持待批准并排除在精选和默认随机之外，不能用另一组件的批准补足

#### Scenario: 用户拒绝一个精确绑定的人形耳机适配
- **WHEN** 用户拒绝绑定到特定 cache/source、完整人形素材、耳机/眼镜组件版本与哈希、geometry profile 指纹和 recipe 版本的组装结果
- **THEN** 系统将该精确适配/recipe 记录为 rejected 并排除出精选和默认随机；不得把拒绝扩展到未审阅的其他配方或页面。修订后的图像、几何、遮挡或材质必须使用新的有效版本/指纹和真实捕获重新审核，不能从被拒绝结果继承批准

### Requirement: 内置素材目录不得引入用户上传或不明来源图像
本阶段的模块素材 SHALL 由维护者登记为站点随附的本地资产，并记录来源和允许使用范围。系统 MUST NOT 接收用户上传图像、公共投稿、任意外部 URL 或参考截图裁切图作为可组合资产。人物与动物素材 MUST 保持原创身份；作品系列标签 MUST NOT 视作图像素材许可。

#### Scenario: 添加来源范围清楚的原创部件
- **WHEN** 维护者添加有明确来源和使用范围的原创本地部件
- **THEN** 该部件可按普通工程、适配和美术门槛进入待审目录

#### Scenario: 试图以参考截图像素登记组件
- **WHEN** 素材来源是动漫截图裁片、网页截图或没有允许分发范围的参考图像
- **THEN** 系统拒绝将该文件登记为可分发模块素材，并保留来源审查失败原因

## MODIFIED Requirements

### Requirement: 动态组件必须根据受信任基底几何逐件解算
需要动态挂载的组件 MUST 登记有版本的 `fitPolicy` 和 `sourceParts`。头戴 kit 可以使用多部件弧线解算；眼镜、围巾等组件可以使用有明确语义的双锚刚性适配，按实际基底眼点、颈部接触点等维护者标注的锚点计算平移、朝向和等比尺寸，不得用每个 look 手填固定 placement 冒充动态能力。每个 `sourceParts` 项 MUST 指向受信任本地素材哈希内的独立源矩形、局部锚点和图层/遮挡规则；源矩形 MUST 在实际素材像素边界内，不得通过拆切完整角色模板制造部件。每个 `baseGeometryProfile` MUST 由维护者针对实际登记的完整基底和姿态标注，并绑定精确 `baseId`、完整基底素材 ID/版本/SHA-256、`bodyId`、视角、姿态、布局、风格和画布尺寸；特征点与面部禁入区用该画布上的归一化坐标登记。标签或 family MUST NOT 推导身体几何或赋予适配能力。用于头戴式耳机的人形 profile MUST 同时提供头部边界、左右耳挂/耳部可用范围、头顶弧线与需要的发丝/耳朵遮挡信息，或同等可信的几何与遮挡数据；耳罩尺寸 MUST 根据耳部与头部比例共同解算，头梁 MUST 贴合头顶弧线，不能仅以固定头宽比例放大或缩小。

共享 resolver MUST 用确切匹配的 `baseGeometryProfile`、每个组件自己的 `fitPolicy` 和 `sourceParts` 分别解算该组件全部部件的挂载位置、尺寸、朝向、层序与遮挡。同一配方可在一个共享 profile 上包含多个动态组件；每个 render module MUST 保留自己的 `fitVersion`、`fitFingerprint`、`fitProfileRef` 和部件变换，项目输入 MUST 以稳定 asset ID 排序保存逐组件 `fitRefs`，并包含共享 solver 版本与整组 fit 的聚合指纹。完整结果指纹 MUST 纳入 profile、各 policy、源部件清单和每个动态组件的解算图层。不同模块按 `(module.z, part.z)` 确定绘制顺序；同一配方必须显式登记，不能由目录笛卡尔积自动推断组合。

像素级素材 ID/版本/hash 仍引用完整本地组件素材；导入和恢复 MUST 从可信目录重新计算每个 fit，不信任项目 JSON 提供的源矩形或已算布局。完整角色基底 MUST 保持原始整图，不裁切或形变。头戴式组件 MUST 检查左右接触点、部件间连接、允许尺寸范围、层序/遮挡和面部 keepout；双锚组件 MUST 检查两锚点、允许几何范围、朝向、比例及已登记遮挡。任一组件的 fit 或组合硬约束失败、profile 不存在或姿态/视角不受支持时 MUST 拒绝整个 recipe，不得返回部分结果、回退固定坐标或静默换掉选择。动态 fit 的工程可用、组件间协调性检查和用户美术批准继续独立记录；不宣称任意形状/角度都支持。

头戴式组件用于有发型/耳朵细节的基底时，profile MUST 提供验证过的遮挡层或遮罩，使连续头梁和耳罩与发丝、耳部的前后关系符合对应视角；如果扁平基底没有足够的遮挡信息，适配 MUST 保持 unsupported。耳罩尺寸、头梁弧线、耳部接触和发丝穿插/覆盖还 MUST 通过真实组装图的人工协调性审查，几何 solver 通过不能代替比例、接触、遮挡、材质光照和配色的美术检查。

#### Scenario: 同一耳机素材适配两个已标注基底
- **WHEN** 同一耳机 kit 被显式登记到两个具有不同真实头部几何的基底/姿态 profile
- **THEN** resolver 从每个 profile 推导相应耳罩与头梁部件布局，得到不同的 fit 指纹；固定同一背景后实际 Canvas/PNG 反映几何适配差异，且不改变完整基底像素

#### Scenario: 同一耳机 kit 分别适配四个人形登记状态
- **WHEN** 维护者将同一个稳定 ID 的耳机 kit 声明适配栗发人物 classic、栗发人物 wave、黄色卫衣丸子头人物和金发眼镜人物四个精确登记状态，并为每个状态绑定各自完整基底素材引用/hash、姿态、几何与遮挡 profile
- **THEN** resolver 对四个状态分别依据实际耳部范围、头部边界、头顶弧线及发丝/耳部遮挡求解；每个可支持状态都生成独立 fit/recipe 指纹和真实 Canvas/透明 PNG，耳罩比例、头梁接触和前后遮挡按对应人形呈现，不继承 classic 的坐标、批准或验收结论。实现和验收还检查 wave 抬手与耳机部件的邻接关系，以及金发眼镜人物基底内原有镜腿与耳罩的空间/遮挡冲突，不以重复添加眼镜组件遮盖问题。缺少可靠 profile 或渲染证据的单个状态保持 unsupported，不计为可用适配，也不静默回退到固定坐标

#### Scenario: 眼镜和围巾按语义锚点动态适配
- **WHEN** 维护者为眼镜登记人形瞳孔双锚，为围巾登记柴犬颈部接触双锚，并分别绑定精确基底素材引用、姿态与组件哈希
- **THEN** resolver 使用同一双锚算法按对应几何 profile 计算组件变换；改动锚点/基底几何会改变变换与 fit 指纹，不通过复制固定坐标来宣称动态支持

#### Scenario: 同一几何 profile 下组合头戴耳机与眼镜
- **WHEN** 用户选择目录中显式登记的人形 classic 耳机加圆框眼镜 recipe
- **THEN** resolver 对两个动态组件分别解算并返回按 asset ID 排序的 fitRefs、逐模块 fit 指纹和一个聚合指纹，再按模块与部件图层顺序输出完整可绘制结果；任一模块冲突时拒绝整个 recipe，不静默移除或替换组件

#### Scenario: 头梁连接或面部禁入检查失败
- **WHEN** 耳罩接触点、耳罩到头梁的连接、允许尺寸范围、层序/遮挡或面部 keepout 任一硬检查失败
- **THEN** resolver 返回明确不可用原因，组件不显示为当前可绘制结果、不可导出且不进入默认随机池，不以刚性覆盖图或备用配方掩盖失败

#### Scenario: 未登记的身体结构或姿态请求动态适配
- **WHEN** 用户为组件选择未绑定精确基底素材引用的 profile、未声明姿态/视角或不存在的身体结构
- **THEN** resolver 拒绝该适配；图库标签和 family 名称不能补足缺失 profile，也不能把任意形状或角度称为支持能力

#### Scenario: 多个动态组件中有一个 fit 失败
- **WHEN** 多组件 recipe 中任一组件不支持共享 profile，或其锚点、尺寸、面部安全区、依赖、槽位、遮挡及图层合同不能解算
- **THEN** 整个 recipe 标为不可用并保留具体失败原因；系统不应用其它组件的部分结果，也不换成另一件未锁定素材
