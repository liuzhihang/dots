# Spec Delta

## Purpose

为当前模板和后续模块化 2D 素材生成可追溯的组合覆盖、真实导出证据与增量检查范围，使新增素材可以持续验证而不把抽样报告说成穷尽结果。

## ADDED Requirements

### Requirement: 当前有限模板与输出路径必须全量列入覆盖
覆盖目录 MUST 从当前可信 look、已登记配方和受支持背景能力生成有限基线清单，并包含全部 15 个登记 look、12 个基准配方状态、10 个固定完整模板状态（共 22 个配方状态）以及全部 3 种已登记背景模式下适用的输出。目录 MUST 分开报告 look 身份、配方状态、唯一 PNG 文件、声明应检验分母、明确规则排除数、可解算数和已执行的 pass/fail/blocked 数；Dots 的两个耳机状态即使读取同一张 PNG，也必须作为两个配置状态覆盖。每个适用的原始 PNG 与 Canvas 输出 MUST 回读实际字节、尺寸、alpha、SHA-256 和画面；Prompt 输出 MUST 回读实际剪贴板或 TXT 内容。

#### Scenario: 生成当前有限基线覆盖报告
- **WHEN** 验收人员为当前登记目录生成覆盖报告
- **THEN** 报告包含 15 个 look、12 个基准状态、10 个固定模板状态、3 种已登记背景的全部适用组合和实际导出结果，并将相同 PNG 文件与不同 Dots 状态分别计数

#### Scenario: 回读当前 PNG 与 Prompt 产物
- **WHEN** 验收人员运行某个已登记状态的 Gallery 原图或工作台 Canvas 导出用例
- **THEN** 报告绑定实际输出字节、画布尺寸、透明通道、SHA-256、画面检查和对应 Prompt 回读；没有回读的项目保持未验证

### Requirement: 模块化素材覆盖必须遵循声明能力并分层生成
新增模块素材 MUST 对每个声明支持的基底和姿态执行全量单素材检查。对实际可渲染的兼容关系，覆盖 MUST 包含有效两因素组合；头型×发型×帽子×耳机、袖口×手表×手势、道具×抓握×视线等高风险关系 MUST 覆盖声明的三因素或四因素组合；已批准的精选配方 MUST 全量回归。较大组合空间 MUST 使用固定 seed 的抽样与性质检查；连续参数 MUST 检查代表值、边界值和极端姿态，不得宣称连续空间已穷尽。

覆盖报告 MUST 分开统计唯一基础设计/素材 ID、组件×基底/姿态的适配、可解算配方以及背景输出数。一个配方可以包含多个动态适配组件，但只有可信目录显式声明共存且共享 resolver 成功解算时才能作为有效组合。每个动态组件 MUST 单独记录资源 ID/版本/hash、fitPolicy、sourceParts、profile 引用、fit 版本/指纹和实际绘制子层；捕获 MUST 原样保留 resolver 提供的按 assetId 排序的 `composition.inputs.fitRefs`，并逐项核对每个组件的版本、指纹和 profile 引用。resolver 的配方级聚合 fit 版本/指纹 MUST 与组件级结果分开保存；只有 resolver 明确提供的聚合值可记录为聚合值，且聚合指纹 MUST 与完整排序 fitRefs 一致。统计 MUST 按目录实际内容推导，不得把配方数、子图层数或背景输出数当作基础设计数或唯一适配数，也不得固定预期 recipe 总数。

#### Scenario: 新素材登记后生成单素材全量适配用例
- **WHEN** 维护者登记一件具有基底、槽位和姿态兼容声明的新素材
- **THEN** 覆盖范围包含该素材与每个声明支持的基底及姿态，并包含其已声明的邻接兼容关系

#### Scenario: 检查高风险组合和较大组合空间
- **WHEN** 素材目录声明高风险三/四因素关系或组合空间超过有限全量检查范围
- **THEN** 高风险关系和精选配方全部列入回归，其他有效关系按固定 seed 与性质检查覆盖，报告标明实际分母、用例数和参数边界

#### Scenario: 验证多组件动态配方及分开计数
- **WHEN** 可信目录声明两个或更多动态组件可在同一基底、姿态和视角共存，例如人形基底上的耳机与眼镜
- **THEN** resolver 为每个组件保留精确素材引用、profile、fitPolicy/sourceParts 和独立 fit 版本/指纹/绘制子层；覆盖报告分别统计唯一基础设计、单组件适配、配方及每种背景输出，recipe 总数由当前目录派生；未声明或无法解算的共存组合保留为相应硬约束排除或失败，不伪装成有效配方

### Requirement: 覆盖分母必须保留声明支持但执行失败的用例
覆盖报告 MUST 分开表示声明应检验分母、由明确硬约束排除的组合、实际可解算数和已执行的 pass/fail/blocked 数。只有素材合同明确声明不支持的基底/姿态或明确互斥、槽位冲突等硬约束，才可作为排除项；排除项 MUST 记录稳定用例标识、对应约束和原因。合同声明支持但素材缺失、来源/版本/hash 不符、尺寸不符或渲染失败的用例 MUST 留在声明应检验分母并标记为 fail 或 blocked，MUST NOT 被移出分母或计作 pass。不得静默替换锁定素材或临时补图；存在活动声明时，空分母 MUST NOT 被报告为通过。

#### Scenario: 明确不兼容的组合依规则排除
- **WHEN** 生成器遇到素材合同明确声明不支持的基底/姿态，或明确声明互斥的两个槽位/素材
- **THEN** 该组合记为硬约束排除项，报告保留稳定标识、命中的声明约束和排除原因，不混入声明应检验分母或成功数

#### Scenario: 声明支持的素材文件缺失或校验失败
- **WHEN** 组合声明支持某基底与姿态，但对应素材文件缺失、来源或版本/hash 不符、注册尺寸不符或实际渲染失败
- **THEN** 该用例继续留在声明应检验分母，并标记 fail 或 blocked；报告不得通过排除它来提高覆盖率

#### Scenario: 所有已声明素材均无法渲染
- **WHEN** 活动素材合同声明了至少一个应检查组合，但其中全部素材都因缺失或渲染错误而失败
- **THEN** 报告保留这些必检用例并返回 fail/blocked，不得显示空分母或 100% 通过

### Requirement: 内部组合图鉴必须支持分页与完整配置回查
维护者 MUST 能按基底、素材、姿态和视角分页查看已生成用例。每个组合图鉴格 MUST 能打开其完整配置与资源版本，并能记录穿插、悬空、遮脸、比例、风格、画布或导出问题。图鉴 MUST 按需生成页面，不得为了视觉索引预渲染整个笛卡尔积。图鉴状态、自动比较结果和人工美术批准 MUST 分开记录；用户批准记录若只有宽泛状态范围、缺少可核定的状态到素材映射，系统 MUST 显示“确认范围待核定”，不得推断通过或否决。

#### Scenario: 从图鉴格打开完整用例
- **WHEN** 维护者选择一个分页图鉴格并打开详情
- **THEN** 系统展示该格的完整组合配置、基底/姿态/视角、素材 ID 与版本，并允许按指定问题类型记录发现

#### Scenario: 分页检查不隐含人工批准
- **WHEN** 内部图鉴生成或自动图像比较完成
- **THEN** 系统只记录内部覆盖与检查状态，不把它们标成用户美术批准或替代明确的人工确认

#### Scenario: 历史批准范围无法映射到具体状态
- **WHEN** 用户批准记录声明了工作台登记状态范围，但没有列出对应姿态文件或其冻结素材映射
- **THEN** 图鉴将该状态的批准标为“确认范围待核定”，不自动视为用户批准或用户否决

### Requirement: 模块适配协调性复核必须绑定精确版本并与批准分开
每个模块适配的内部协调性复核 MUST 绑定基底 ID 与资源版本/hash、组件 ID 与资源版本/hash、配方 ID/版本/指纹、姿态和视角；声明几何适配时还 MUST 绑定 geometry fitPolicy、geometry profile/fit profile 引用及来源部件。sourceParts 是同一稳定组件/素材包的内部图层切片，MUST NOT 作为额外独立基础设计或素材重复计数；唯一源 PNG、稳定组件 ID 与实际绘制子层应分别报告。新适配的比例、贴合/接触、遮挡/层序、材质/光照、配色五项 MUST 初始为 `unreviewed`，整体初始为 `pending`；只有五项均显式 `pass` 才能进入 `ready-for-explicit-confirmation`，人工发现有阻碍时可记为 `rejected` 并附原因。协调性复核 MUST 与工程执行状态、用户美术批准和发布资格分别统计，MUST NOT 自动改变任何美术批准、默认候选资格或必检分母。复核及单格 localStorage 问题标注 MUST 一起导出并保存在冻结证据中。模块 Canvas 捕获 MUST 记录实际解析出的几何 fit 版本/profile、变换/图层顺序/遮挡及 fit 指纹（适配声明提供这些字段时），不得将有限声明配方扩大表述为任意旋转或任意姿态支持。版本、哈希、几何策略/profile、姿态、视角或配方指纹改变后，旧复核 MUST NOT 继承到新适配。

当一个配方包含多个动态组件时，复核 subject MUST 为每个组件分别绑定 fitPolicy、sourceParts、其适用的 profile 引用和资源版本/hash；捕获 MUST 保存每个组件独立的 fit 版本/指纹与已解算子层。若 resolver 提供配方级聚合指纹，可同时记录；不得将某一个组件的指纹当作整个配方的聚合结果。多个配方的协调状态与多个基础设计/适配数量 MUST 分开统计。

#### Scenario: 新模块适配开始协调性复核
- **WHEN** 维护者打开一个此前没有精确复核记录的模块适配
- **THEN** 系统按精确基底/组件资源、配方版本/指纹、姿态和视角创建五项均为 `unreviewed`、整体为 `pending` 的复核，且不修改工程状态或美术批准

#### Scenario: 导出并冻结单格协调性和问题标注
- **WHEN** 维护者编辑模块图鉴某格的协调性清单或问题备注并导出捕获证据
- **THEN** capture manifest 与冻结报告保留同一精确适配 subject、五项状态、整体结论及 localStorage 问题标注；工程 pass/fail/blocked 分母、协调性结论和美术批准分别记录

#### Scenario: 旧版本复核不适用于新适配
- **WHEN** 组件或基底资源 hash、配方版本/指纹、姿态或视角发生变化
- **THEN** 先前复核不匹配新适配；新复核回到五项 `unreviewed` 和整体 `pending`，旧记录不能产生批准或候选资格

#### Scenario: 捕获声明几何适配的实际绘制参数
- **WHEN** 验收人员捕获包含几何 fit 的登记模块组合
- **THEN** 每条 Canvas 输出同时记录真实 PNG 字节证据和实际解算的 profile/fit 版本、绘制变换、图层顺序、遮挡规则及指纹；这些工程参数不自动构成协调性通过或用户美术批准

#### Scenario: 冻结同一配方中的多个动态适配结果
- **WHEN** 冻结一个包含多个动态组件的可解算配方
- **THEN** 冻结报告逐组件验证来源素材/子图层及各自 fingerprint，并保留共享或组件级 profile 绑定；组件数量、单组件适配数、配方数与背景输出数互不替代，待复核或拒绝状态不删除任何声明应检输出

### Requirement: 素材与规则变更必须生成对应的增量影响范围
增量范围 MUST 根据基底、占用槽位、支持姿态和邻接素材依赖生成。新增素材 MUST 检查其全部声明基底/姿态及邻接关系；公共布局、Canvas 合成器、染色逻辑或基底变化 MUST 扩大到所有受影响用例；标签浏览变更 MUST 检查筛选与随机候选池，但通常不触发几何全量回归；新增主题组合美术规则 MUST 覆盖相应组合与风险交互。

#### Scenario: 修改公共合成或染色逻辑
- **WHEN** 维护者修改公共布局、图层解算、Canvas 合成、染色或基底素材
- **THEN** 增量报告扩大到所有引用该公共能力或素材的既有与新增用例

#### Scenario: 只修改标签浏览或筛选规则
- **WHEN** 变更仅影响标签目录、筛选或随机范围
- **THEN** 报告检查标签筛选结果和默认随机候选池，不要求无关的几何组合全量回归

#### Scenario: 修改主题组合规则
- **WHEN** 新增或调整主题相关的组合、美术或兼容规则
- **THEN** 报告包含受该规则影响的组合及其声明的高风险邻接用例

### Requirement: 冻结覆盖证据必须可复现且不得自动接受新基准
每份冻结报告 MUST 固定源码提交、cache/module 版本、source ID 和源码清单/hash、浏览器与视口、画布尺寸、素材 ID/版本/hash、状态配置、seed 和静态帧参数，并绑定实际证据及覆盖分母。若源码工作树未提交或 source ID 未覆盖该工作树，报告 MUST 同时固定 dirty-source snapshot hash 与其变更路径/文件 hash 清单；仅记录 commit 和 cache 版本不足以绑定源码。新证据 MUST 写入 `design/acceptance/current-<本机日期>-v<cache版本>/` 下未存在的新目录；归档记录和既有冻结目录 MUST 保持原样。视觉差异、脚本通过或内部评审 MUST NOT 自动接受新的截图基准。

#### Scenario: 固定环境并冻结本次结果
- **WHEN** 维护者完成一次可复现的覆盖检查并冻结其结果
- **THEN** 新目录记录固定环境、源码 source ID/manifest 或 dirty-source snapshot hash 与文件清单、用例分母、实际执行数、跳过/排除原因、资源版本和证据链接，且不改写任何旧归档

#### Scenario: 冻结源码包含未提交文件
- **WHEN** 捕获页面的工作树包含未提交或未被 source ID 覆盖的文件
- **THEN** 报告绑定这些文件的路径与 hash 和对应 dirty-source snapshot hash，不能仅凭 HEAD commit 与 cache 版本标记为可复现

#### Scenario: 目标冻结目录已存在
- **WHEN** 本次日期和 cache 版本对应的冻结目录已经存在
- **THEN** 冻结流程拒绝覆盖该目录，并要求选择新的唯一版本目录

#### Scenario: 图像差异产生候选截图
- **WHEN** 自动像素比较报告图像差异或新基准图像生成
- **THEN** 图像保持为待人工审查状态，不能自动写成已批准基准

### Requirement: 新版项目往返与旧输入拒绝必须分别验证
覆盖 MUST 验证所有当前有效项目统一使用 project v2 包装与角色 VERSION 10，覆盖保存、导出、自动保存、导入恢复、撤销和重做。`creation.composition` MUST 明确为 `null` 或完整的已解算引用：Prompt-only/未解算编辑态可保存 `null`，同时保留角色配置并在导入、撤销和重做后恢复；真实模板或模块渲染作品 MUST 保存非 null 的组合引用。已解算引用 MUST 以 `kind: template|modular` 表示类型，并保存实际素材稳定 ID、版本/hash、配方引用、完整解算配置和解析指纹，使恢复结果可复现而不依赖 seed。默认随机成品 MUST 来自非 null 的真实可渲染候选，null/Prompt-only 配置 MUST NOT 进入默认随机池。project v1、纯角色 JSON、角色 schema 6–9 与旧角色别名 MUST 被拒绝；拒绝 MUST 说明格式错误并保留当前有效作品。不得提供迁移、兼容回退或正向旧格式验收。项目 JSON MUST NOT 将内嵌图片、任意路径、任意 URL 或直接提供的图层清单/`ResolvedComposition` 作为可信素材来源。

#### Scenario: 恢复现有项目并撤销
- **WHEN** 用户导入角色 VERSION 10 的 project v2 项目，或对该项目执行恢复、撤销与重做
- **THEN** 角色配置及其 null 或已解算组合状态保持一致；有已解算引用时，稳定素材引用和解析结果恢复一致，标签浏览或覆盖检查不会覆盖正在编辑的作品

#### Scenario: 新版项目保存模板或模块化组合
- **WHEN** 用户导出 `composition.kind` 为 `template` 或 `modular` 的 project v2，再从 JSON 导入
- **THEN** 系统根据本地可信目录中的稳定 ID、版本/hash 与完整配置恢复同一实际组合，不依赖随机 seed 重抽，角色 VERSION 10 不变

#### Scenario: 保存和恢复 Prompt-only 编辑态
- **WHEN** 用户保存或导出尚无真实渲染配方的 Prompt-only 编辑态
- **THEN** 项目仍使用 v2 与 VERSION 10，`creation.composition` 为 `null`，角色设定和 Prompt 配置在导入、撤销与重做后保持一致，且当前 PNG 不伪称包含未渲染设置

#### Scenario: Prompt-only 编辑态不进入默认随机成品池
- **WHEN** 默认随机候选池包含配置状态为 `composition: null` 或仅支持 Prompt 的选项
- **THEN** 该选项不进入默认成品池或滚轮揭晓；只有具备真实可渲染非 null 引用的候选可生成默认随机成品

#### Scenario: 拒绝旧版项目和角色格式
- **WHEN** 用户导入 project v1、纯角色 JSON、角色 schema 6–9 或包含旧角色别名的项目
- **THEN** 系统说明格式已停用并拒绝导入，当前有效角色和作品保持不变，不执行迁移或兼容回退
