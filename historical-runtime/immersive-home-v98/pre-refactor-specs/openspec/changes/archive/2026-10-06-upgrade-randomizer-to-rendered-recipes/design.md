# Design

## Context

以只读审查的 `main@4d952b907ef4823db7b5e9792726c80a4226eeb8` 为基线：现有全屏随机器已经提供临时候选、四类锁定、显式应用、Escape 关闭、焦点恢复、减少动态和旧回调失效控制。候选仍由配置数组生成，结果图则由调用端按 family 读取固定基准 PNG；真实组合渲染器没有参与候选筛选。该快照中项目 JSON 外层仍为 v1、图库仍按五个 family 筛选；这些是审查时的源码事实，不是本方案的目标合同。依赖的目录 change 将为图库和工作台提供标签范围。

## Goals / Non-Goals

**Goals:**

- 将首页现有随机入口、图库入口和工作台入口接到同一个全局弹窗。首页保留当前 `familySearch/homeFamilies` 搜索与五组场景过滤的呈现和范围，不新增 typed-tag 控件；图库和工作台管理可扩展标签范围并把当前查询传给弹窗。
- 冻结首页现有布局、群像、卡片、导航和文案；不制作首页新插画。
- 在播放任何揭晓动画前，基于标签范围、锁定项、可用素材和共享组合解算器固定一个可行的真实候选；继承了标签范围时，允许在 dialog 中简洁地切回全部，不显示标签搜索列表。
- 保留当前已登记的 15 个模板、PNG 配方、撤销/重做和当前草稿语义；先用共享解算接口适配这些完整模板和已登记静态状态，只呈现真实支持的阶段。素材批准记录不扩大为未经检查的 PNG 字节或设备验收结论。无需等待首批全部模块素材完成，之后可逐步开放已验收模块。
- 用一个活动 Canvas 呈现候选实图，并以同一 resolved composition 驱动预览、应用和 PNG 导出。
- 所有新建、当前保存、项目 JSON 导入/导出及已应用随机作品统一使用 dot-studio-project v2 + 角色 VERSION 10，并由 add-modular-2d-composition 实现唯一序列化、解析与验证入口；本 change 只消费其公开合同。
- 将旧 project v1、单独角色 JSON 和角色 schema 6–9 的输入明确标记为不支持，不自动转换，不提供降级导出或第二套兼容解析器。

**Non-Goals:**

- 本变更不实现标签目录本身；它依赖 evolve-catalog-tags 在图库和工作台提供 typed TagQuery 与查找结果。首页保留现有搜索/五组场景过滤，不增加 typed-tag UI；已有家族导航进入图库时按目录合同映射范围。
- 本变更不实现完整 24 件模块素材或一整套组合引擎；它依赖 add-modular-2d-composition 先交付共享 resolver 合同和可工作的完整模板适配器。
- 不以生成器、占位缩略图或结构诊断图补齐缺失素材；不将 Prompt-only 字段并入默认随机成品。
- 不实现连续角色动画、任意视角、3D、用户上传、社区、账户和审核系统。
- 不改首页 hero/卡片/主导航/版式/群像/文案，不添加首页插画或 typed-tag 控件；首页已有搜索与五组场景过滤按现状保留。
- 不部署站点或改变仓库、Sites 的身份和访问范围。

## Decisions

### 1. 由目录查询提供候选范围，family 继续表达运行时能力

弹窗入口接收目录层的 TagQuery 和清晰的来源范围。图库和工作台的 typed-tag 搜索/多选 UI 由目录层提供，入口把当前查询原样传入弹窗；首页沿用现有搜索和五组场景过滤的呈现与语义，不添加新标签控件，现有筛选范围可映射到对应目录查询。随机 dialog 不提供标签搜索列表，只提供简洁的“切回全部”动作；在已有结果或空候选错误状态均可调用，该动作清除当前标签查询以供后续抽取，不改变锁定项、活动作品或项目。首页视觉保持冻结。

角色 family、artworkId 和 presetId 继续保留其身份、结构适配和当前角色配置语义。实现不得将 family 全局替换为 tag，也不得为了容纳作品系列而扩展 FAMILIES。标签查询算法只在目录层实现一次，随机器消费其结果，不复制 OR/AND 和搜索逻辑。

**考虑过的替代方案：**把每个作品系列加入 FAMILIES。拒绝，因为现有 family 同时控制默认值、模型允许形状/材质、组合 pack 匹配和当前草稿恢复；专题标签不能决定渲染能力。

### 2. 候选以 ResolvedComposition 为唯一输入

共享组合解算器提供一个稳定的解析结果，随机器和渲染器消费同一个对象。随机器在抽取前为候选构造通过 stage2 唯一 API 校验的 v2 + VERSION 10 暂存项目；该 pending payload 隔离于当前作品，只有显式应用时才提交。ResolvedComposition 至少包括：

- resolver 版本，配方 ID 和配方版本；
- 基底 look/artwork ID；每个当前适用阶段的稳定值或槽位绑定；
- 实际素材 ID、素材版本或登记哈希；
- 经校验的角色配置、视角、尺寸和背景参数；
- 可预览、可导出状态及不支持的字段原因。

本地素材路径只能由已登记 ID 在可信目录中解析，禁止将路径或 URL 当成项目数据。解算器必须验证槽位、基底、姿态、遮挡/接触条件、资源登记状态和当前 Canvas 能力。随机器不允许只调用角色 config 随机后再询问当前 pack 是否碰巧能画。

**考虑过的替代方案：**继续让 randomRecipe 生成配置，然后在动画停止后检查 pack。拒绝，因为它会先向用户揭晓无法渲染的结果，且无法保证锁定项不被后置修补。

### 3. 先消费已交付的模板 resolver，再扩展候选接口与模块

add-modular-2d-composition foundation 1.1–1.6 已负责共享 resolver、当前完整模板/静态状态 adapter、唯一 v2 合同、旧路径移除、`save-character` 菜单项删除和当前跨入口 PNG 一致性。随机 change 消费这套已交付接口，不再把 v2 与模板 adapter 拆成先后依赖，也不等待整个 stage2 change 完成。stage2 任务2.4提供的当前模板候选接口是单独的集成依赖；随机器只等待该接口可用，不等待新模块 PNG 或其余素材任务。

首批真实随机只使用共享 resolver 可确认可绘制、资源已登记且符合当前有效开放资格的 15 个模板和各自实际支持的 PNG 状态。完整 look 至少显示一个“完整形象”阶段；只有登记状态确实对应独立可选素材时才增加阶段，绝不把烘焙在完整 PNG 中的配色、服装或配饰拆称为组件。后续模块候选仅在对应素材真实存在、解析通过、PNG/Canvas 输出验证且所需适配获得人工批准后加入同一候选接口。

非背景染色字段修复仍由 stage2 负责，但不作为无 `tintPath` 当前模板候选的前置条件。只有未来某个已登记模块声明并实际使用非背景染色时，才要求该分支通过染色值保留和 Canvas 像素回归后进入候选池。

代码里的候选/未审文案与外部确认记录若不同，实施前必须回读当前权威确认记录并将资格映射到版本化素材登记；不得直接修改历史冻结记录或从旧预览图推定批准。

### 4. 动画只揭晓冻结候选，不参与抽取

弹窗会先从入口传入的查询范围、锁定绑定和 resolver 返回值求出有效候选，再挑出唯一 ResolvedComposition，将其置于角色 VERSION 10 的 v2 暂存项目合同中，并预载所有必要资源。阶段缩略图的滚动列表只能引用同一可行结果集合中的登记素材，最终停在该候选绑定的 ID 上。锁定项直接固定 ID 和版本。

动画完成后，单一活动 Canvas 显示此 ResolvedComposition。用户可跳过动画，系统或应用减少动态时立即揭晓静态结果；两条路径的资产 ID、版本、配置和 Canvas 结果必须一致。候选渲染错误不允许回退到 family 基准图，也不能在动画后换选另一个 candidate。

**考虑过的替代方案：**每个滚轮独立随机，然后在最终拼装时修复不兼容字段。拒绝，因为这会让动画承诺一个实际不存在的候选，并可能静默替换用户锁定项。

### 5. 以单独状态机和代次令牌隔离异步任务

弹窗状态按下列顺序演进：

```text
closed -> intro -> resolving -> preloading -> revealing -> assembling -> result
                    |              |             |            |
                    +--------------+-------------+-------------> failed
```

首次打开只显示 CTA 和关闭操作。抽取后有一个 pending candidate；只有预载、Canvas 组合（以及结果编码校验如本机适配需要）全部满足当前就绪条件，才替换已显示 candidate。局部重抽以当前已显示 candidate 和锁定项为输入。无解或加载失败保留上一个可用 candidate；首轮失败则显示错误和重试入口。

每次 open 建立 session token，每次随机/局部重抽增加 turn token；候选自带 resolver revision。close、dispose 和 re-open 使旧 token 失效。图片读取/解码、Canvas 更新、PNG 编码和错误回调在每个异步边界检查 session、turn 与候选 revision；旧操作可被取消时主动取消，同时始终依赖 token 防止无法中止的回调落入新状态。跳过仅结束当前揭晓计时，不重新求候选。

### 6. 统一 v2 项目合同与提交原子化

所有新建、保存、导入和项目 JSON 导出统一使用 dot-studio-project version 2，并在角色 payload 中使用当前 VERSION 10。v2 必须显式包含 `creation.composition`：可为 `null`，也可为包含 `kind=template|modular` 的已解析组合引用。默认成品随机候选和已应用随机结果 MUST 为非 null；Prompt-only 或当前不可渲染的编辑状态可按 stage2 合同保存为 null，不得伪造素材引用。非 null 组合只记录登记 recipe/assets 的 ID、revision/hash、resolver 版本与恢复解析结果所需配置，不携带任意路径、图片字节或外部 URL。randomSeed 只能作为辅助复现字段，不能成为恢复依据。

唯一 v2 序列化、解析和验证入口由 add-modular-2d-composition 提供，本 change 只调用该接口，不新增旧格式转换、兼容 reader、独立角色 JSON 导出或降级导出。stage2 同时移除旧 `save-character` 兼容导出菜单项，不在本 change 中重建。项目导入只接受严格有效的 project v2 + 角色 VERSION 10；v1 包装、独立角色 JSON、角色 schema 6–9 等旧输入统一返回清楚的“不支持格式”结果，不自动转换且不得修改当前项目、草稿或历史。

应用候选时一次生成完整的 v2 项目，在既有 commit/history 边界形成一条撤销记录；提交后工作台继续使用同一 ResolvedComposition。关闭或取消不调用 commit，保留打开 dialog 前的当前草稿与撤销/重做状态。

**考虑过的替代方案：**保留 v1/raw-role 兼容与降级导出。拒绝，因为用户已决定旧格式无需继续支持；维护多套解析/恢复路径会使项目合同和随机结果产生分歧。旧输入明确报告 unsupported，由用户从当前登记内容重新开始，不自动导入或转换。

## Risks / Trade-offs

- [锁定组合没有可行解] -> 不放宽锁、不找近似素材；保留原候选，列出冲突阶段，允许用户手动解锁或返回。
- [预载多个缩略图增大初次延迟] -> 只对当前标签范围和当前支持阶段构造有限预览集合；先冻结唯一候选并预载其必需资产，滚动样例也只能来自已登记和可用素材。若缩略图未齐，不开始承诺滚动的动画。
- [完整模板和模块阶段混用造成 UI 误导] -> resolver 声明本次真实支持的阶段；模板阶段显示完整形象，模块阶段仅显示实际独立资产，不补空占位阶段。
- [当前源码的候选状态与历史审批记录看似冲突] -> 以当前有效人工确认和绑定素材版本形成随机资格，保留原冻结文件；未能核实的素材不进入默认随机池。
- [旧文件无法继续导入] -> v2 importer 对非 v2 或非 VERSION 10 输入返回明确 unsupported 错误，不改当前项目/草稿/撤销历史；不尝试自动迁移、raw-role fallback 或降级导出。
- [关闭后仍有浏览器解码/编码回调] -> 每个异步步骤绑定 session/turn/revision token；关闭、重开、重抽、失败及销毁路径都由实际 DOM/浏览器测试覆盖。

## Migration Plan

1. 方案确认及素材批准核对后完成第一个基础闭环：evolve-catalog-tags 交付图库/工作台 TagQuery 与页面切片；add-modular-2d-composition 完成 foundation 1.1–1.6，包括当前模板共享 resolver/adapter、v2 + VERSION 10、旧路径移除和跨入口 PNG 一致；add-composition-visual-regression 交付 group 1 的当前模板/PNG 基础报告。此报告的随机池集成项明确标记 deferred/blocked，不计通过且不作为本步基础报告门槛，避免与随机器接线形成循环。
2. 第二个闭环只等待 stage2 任务2.4的当前模板候选接口，不等待 stage2/视觉回归整个 change 或首批模块素材完成。基于已交付模板 resolver 先完成真实候选求解、资源预载、缩略图揭晓/静态揭晓、活动 Canvas、v2 暂存与应用提交；首批范围限于已登记 15 个模板和当前确实支持的 PNG 配方。
3. 加入真实 DOM、桌面与 320/390/768 px 视口、PNG 字节/像素检查和一次撤销检查；复用首闭环报告，只补查随机资格池中尚无实际输出证据的候选。stage4 随机池专属回归在实际候选接线后补做；不重复建设全库 capture 流水线。所有新视觉基准采用新的 QA 目录，不覆盖冻结证据。
4. 后续仅在 stage2 登记的模块候选接口、真实素材及相应人工批准就绪后扩展随机阶段。非背景染色修复只约束实际使用该能力的模块分支，不阻塞当前模板随机。
5. 由用户检查当前候选版本与人工美术结果并确认后，才进入实施的下一增量。此 change 的任务不授权站点发布；发布必须是后续单独确认的工作阶段。

## Open Questions

无。初始模板随机池的确切成员是实施前的核验门槛：须从当前有效批准记录与真实资源版本得出，不在此设计中凭历史截图或状态标签猜定。
